Von Offline-Vorschlägen zum KI-gestützten Programmieren

Beginnen Sie mit schnellen tabellenbasierten Vorschlägen, die pro Anfrage nichts kosten. Richten Sie dann den Assistenten ein, fordern Sie Online-Alternativen an, probieren Sie ein On-Device-Modell aus und schließen Sie mit fokussierten KI-Prompt-Zellen ab, die Ihren Code erklären.

  • Nur Pro
  • Pro 1.4.0 + bevorstehende Ausführungssteuerungen
  • Lokales Modell: Android

Die meisten Screenshots zeigen die Android-App; einige sind Browser-Aufnahmen. Layouts können je nach App-Version variieren.

Überprüfen Sie Ihre Version. Die Ausführungsänderungen im Anhang sind für die vorgeschlagene Version Pro 1.5.0 geplant, die noch unveröffentlicht ist; die endgültige Versionsnummer kann sich ändern.

„Free“ bedeutet hier ohne API-Gebühren. Tabellenvorschläge und das On-Device-Modell rechnen nicht über einen Anbieter ab. Das macht sie nicht zu Funktionen der Free-Edition: Diese Anleitung ist für SciREPL Pro. Online-Anfragen nutzen Ihr eigenes Anbieterkonto und können Geld kosten.

  1. Mit Offline-Tabellenvorschlägen beginnen

Schritt 1 · Kein API-Schlüssel erforderlich

Mit Offline-Tabellenvorschlägen beginnen

Suchen Sie ☰ Menü in der Kopfzeile der App: Es ist die Schaltfläche mit drei horizontalen Linien. Öffnen Sie Vervollständigung. Die Auswahl für Abschnitt unterteilt Allgemein, KI-Vorschläge (online) und Lokales Modell (auf dem Gerät). Beginnen Sie mit Allgemein.

  1. Setzen Sie Lokale Codevervollständigung → An. Die Standardeinstellung Automatisch (Desktop an, Touch aus) würde dies auf einem Telefon sonst deaktiviert lassen.
  2. Setzen Sie Vorschlags-Chips → An und behalten Sie Vorschläge → An der Cursorposition bei. Um die Tabellen zu isolieren, setzen Sie im Online-Bereich KI-Vorschläge → Aus und im lokalen Bereich Lokales Modell verwenden → Aus, falls eines davon zuvor aktiviert war. Kehren Sie zu Allgemein zurück.
  1. Schließen Sie die Vervollständigung. Wählen Sie in einer neuen Übungs-Arbeitsmappe eine Code-Zelle und die Sprache JavaScript. Tippen Sie cons ein, mit der Schreibmarke am Ende und ohne Auswahl. Diese ersten Buchstaben von const werden als Präfix bezeichnet. Achten Sie auf const.
  2. Im Screenshot unten folgt auf cons ein schwaches t – Inline-Ghost-Text. Tippen Sie auf Übernehmen oder drücken Sie Tab, um den Vorschlag einzufügen, was const ergibt. Wenn stattdessen ein const-Chip erscheint, ist das Antippen eine weitere Möglichkeit, diesen Kandidaten zu übernehmen. Vervollständigen Sie die Zeile selbst, beispielsweise const values = [12, 15, 18];.

Übernehmen ist nicht Ausführen. Das Übernehmen eines Vorschlags bearbeitet den Quellcode; die Zelle wird dabei nicht ausgeführt. Die JavaScript- und Python-Beispiele in diesem Abschnitt demonstrieren die Autovervollständigung während der Bearbeitung. Das Ausführen dieser Übungszellen ist nicht Bestandteil dieses Abschnitts. Wenn nur die Offline-Tabellenschicht aktiviert ist, sendet die Eingabe eines Präfixes keine API-Anfrage und startet keine Sprach-Laufzeitumgebung nur zur Erstellung von Vorschlägen.

Künftiges Online-Prefetching: Ein optionaler Modus ist geplant, der Modellanfragen senden könnte, während Sie tippen. Er ist noch nicht verfügbar, und ihm ist noch keine Versionsnummer zugewiesen. Die obige Aussage, dass keine Anfragen gesendet werden, beschreibt die aktuelle Offline-Tabellenschicht, nicht diesen zukünftigen Modus.

Sehen Sie sich die beiden Offline-Darstellungen auf einem Smartphone an. Belassen Sie Vorschlags-Chips → An, wählen Sie Python und tippen Sie pri ein. Das schwache nt hinter der Schreibmarke schlägt print vor; es wird erst Teil Ihres Quellcodes, wenn Sie es übernehmen. Sie müssen Chips nicht deaktivieren, um Ghost-Text zu sehen. Ein einzelner Kandidat kann als Ghost-Text erscheinen, während Chips eine Auswahl bieten, wenn mehrere Kandidaten passen. Behalten Sie KI-Vorschläge und Lokales Modell verwenden für beide Beispiele deaktiviert.

Mit den Chips weiterhin auf An ersetzen Sie die Übungseingabe durch diese drei Zeilen und lassen Sie die Schreibmarke nach dem unvollständigen sample_m stehen. Die Leiste bietet sample_mean und sample_median aus Namen Ihres eigenen Quellcodes an. Tippen Sie auf einen Chip, um einen Kandidaten auszuwählen; anders als Ghost-Text zeigt die Leiste Alternativen an.

sample_mean = 0
sample_median = 0
sample_m

Die Zusatztastenleiste, die in den Python-Smartphone-Bildern zu sehen ist, und Syntaxfarben beim Tippen sind separate, optionale Pro-Bedienelemente. Siehe Erscheinungsbild-Anleitung: Zusatztasten und Syntaxfarben, um diese ein- oder auszuschalten und das separate Hervorhebungs-Kontrollkästchen des Datei-Editors zu finden.

Wechseln Sie nach dem Ausprobieren dieser Vervollständigungsanzeigen zurück zu JavaScript und lassen Sie die Chips für den Rest der Lektion aktiviert.

Die hier gezeigten Offline-Chips, die unter Vervollständigung → Allgemein → Vorschlags-Chips aktiviert werden, kombinieren kuratierte Namenstabellen mit lokalen Code-Informationen. In Python umfasst dies Variablen und Funktionen aus dem Arbeitsmappen-Code sowie zwischengespeicherte Kernel-Namen und Objektattribute einschließlich Methoden. Häufigkeit und Annahmeverlauf helfen bei deren Priorisierung. Andere Sprachen bieten eine abweichende Abdeckung: Statische Listen, nicht ausgeführte Definitionen oder veraltete Snapshots schlagen möglicherweise Namen vor, die im aktuellen Gültigkeitsbereich gar nicht verfügbar sind. Tabellenbasierte Vervollständigung ist kein Sprachmodell und zieht keine logischen Schlüsse über Ihre Aufgabe.

Nur am Zellenende ist eine Alternative, wenn Vorschläge mitten in der Zelle ablenken. Eine Auswahl, eine Zeichenkette, ein Kommentar oder ein unvollständig getrennter Name erzeugt möglicherweise absichtlich keine Vorschläge. Im Querformat mit geringer Höhe können optionale Leisten ausgeblendet werden, um Platz für Code zu sparen; siehe Erscheinungsbildeinstellungen.

Schritt 2 · Online-Einrichtung

Einen API-Schlüssel speichern

Ein API-Schlüssel ermöglicht es SciREPL, ein von Ihnen kontrolliertes Anbieterkonto zu nutzen. Beziehen Sie den Schlüssel von diesem Anbieter, prüfen Sie dessen aktuelle Preise und Kontolimits und verwenden Sie für diese Lektion ausschließlich eine kleine Übungs-Arbeitsmappe mit nicht-privaten Daten.

  1. Öffnen Sie Menü → 🤖 KI-Assistent (Pro). Tippen Sie im Panel auf das ⚙ Zahnrad , um die KI-Einstellungen zu öffnen.

    Zahnrad nicht sichtbar? Die Tastatur kann das Assistenten-Panel verschieben oder scrollen. Ziehen Sie den Inhalt des Panels nach unten, um wieder nach oben zu scrollen und das Zahnrad sichtbar zu machen; das Schließen der Tastatur kann Ihnen ebenfalls mehr Platz verschaffen.

  2. Setzen Sie Modell konfigurieren für → KI-Assistent. Wählen Sie ein Backend (z. B. OpenRouter) und ein Modell aus und überprüfen Sie den Endpunkt, falls Ihr Backend einen konfigurierbaren verwendet.
  3. Geben Sie den passenden API-Schlüssel ein. Verwenden Sie Gespeicherte Schlüssel, um Schlüssel für andere Anbieter-/Endpunkt-Kombinationen zu verwalten. Ein Schlüssel für ein Ziel ist nicht automatisch auch ein Schlüssel für ein anderes.
  4. Tippen Sie auf Speichern. Das bloße Speichern der Einstellungen sendet noch keine Modellanfrage. Lassen Sie das Panel für den nächsten Schritt geöffnet.

Schlüssel nicht in die Arbeitsmappe einfügen. Fügen Sie ihn nicht in eine Zelle, einen Prompt, einen Screenshot oder eine exportierte Datei ein. Gespeicherte Schlüssel verbleiben im lokalen Speicher der App bzw. des Browsers, ohne anwendungsbezogene Verschlüsselung; schützen Sie das Gerät und führen Sie keinen nicht vertrauenswürdigen Code aus. Die Pro-Datenschutzerklärung erläutert, was gespeichert und übertragen wird.

Ein kostengünstiges Modell mit Werkzeugunterstützung ist ein sinnvoller Ausgangspunkt für den Assistenten. Zu den Beispielen für einen Vergleich gehören GLM 5.3 Flash, GPT-6 Luna, Claude Haiku 5.5 und DeepSeek V4 Flash. Genaue Modell-IDs, verfügbare Versionen, Werkzeugunterstützung und Preise hängen von Ihrer App-Version und Ihrem Anbieter ab; prüfen Sie die aktuelle Auswahlliste und die Anbieterdokumentation. Ein neu angekündigtes Modell erfordert möglicherweise ein App-Update, bevor es angezeigt wird. Später können Sie ein anderes preiswertes Modell nur für Vervollständigungen auswählen.

Modell fehlt in der Liste? Wählen Sie unter KI-Einstellungen → Modell konfigurieren für → KI-Assistent zuerst das richtige Backend aus, geben Sie dann die genaue API-Modell-ID des Anbieters in Oder benutzerdefinierte Modell-ID eingeben unter der Modell-Auswahl ein und tippen Sie auf Speichern. Dieses Feld ist bereits in Pro 1.4.0 verfügbar.

Überprüfen Sie die ID bei Ihrem ausgewählten Anbieter, nicht nur den Marketingnamen des Modells. Geben Sie für OpenRouter das Organisationspräfix an – beispielsweise anthropic/claude-haiku-5.5 auf seiner Modellseite. Geben Sie die ID ein, nicht die URL dieser Seite. Die benutzerdefinierte ID hat Vorrang vor dem Dropdown-Menü; die erneute Auswahl eines aufgelisteten Modells leert das benutzerdefinierte Feld.

Eine ID ergänzt keine API-Unterstützung. Das Modell muss Tool-Aufrufe über die API unterstützen, die SciREPL verwendet. Prüfen Sie Anbieterzugang, Kompatibilität und aktuelle Preise; das Speichern validiert diese nicht und sendet keine Modellanfrage.

Schritt 3 · Gezielte Tool-Nutzung

Ein kleines Beispiel mit der Open-Agent-Voreinstellung erstellen

Offen ist die zweitdurchlässigste Sicherheitsvoreinstellung nach Volle Kontrolle. Sie erlaubt standardmäßig Notebook-Bearbeitungen mit weniger Nachfragen als „Cautious“. Ob vor der Ausführung nachgefragt wird, hängt von Ihrer Version und den Berechtigungseinstellungen ab; siehe den Anhang zur bevorstehenden Ausführungsgenehmigung. Verwenden Sie diese Einstellung gezielt in einer Übungs-Arbeitsmappe – nicht als Voraussetzung für die Autovervollständigung.

  1. Wählen Sie in den KI-Einstellungen Sicherheitsstufe → Open und Agent schreibt → Aktives Arbeitsblatt. Lassen Sie das Durchsuchen des Quellcodes deaktiviert und schalten Sie Von KI erstellte Zellen automatisch ausführenaus. Unter Kernel…stellen Sie JavaScript → Nachfragenein und speichern Sie dann. Diese Kernel-Regel fragt auch dann noch nach, wenn zuvor ein „Allow“ für das Ausführungswerkzeug gespeichert wurde.

    Deaktiviertes automatisches Ausführen ist keine Ausführungssperre. Es verhindert nur, dass neu erstellte Zellen automatisch ausgeführt werden; separate execute_cell- oder run_cells-Anfragen werden dadurch nicht deaktiviert. Der Open-Standard des veröffentlichten Pro 1.4.0 kann diese ohne Nachfrage zulassen. Der künftige Open-Standard fragt nach, aber ein explizites „Allow“ für ein Tool oder einen Kernel kann diesen Standard ändern. KI-Einstellungen → Kernel… → JavaScript → Nachfragen stellt sicher, dass die JavaScript-Ausführung in dieser Übung an eine Bestätigung gebunden bleibt. Die eigene manuelle Ausführung einer Zelle bleibt eine separate Aktion. Ausführungssteuerungen der nächsten Version werden im Anhang ausführlich beschrieben.

    Wenn Sie mehr Bestätigungen bevorzugen, verwenden Sie stattdessen Vorsichtig. „Open“ berücksichtigt weiterhin die separaten Steuerungen für das Durchsuchen des Quellcodes und den Schreibbereich; „Full control“ umgeht diese beiden groben Steuerungen. Individuelle Berechtigungen und andere Sicherheitsmechanismen bleiben weiterhin von Bedeutung. Überprüfung ist eine zusätzliche Beschränkung auf weitgehendes Lesen, die diese Zellenerstellungs-Demonstration behindern würde.

    Was die Browser-Sandbox schützt – und was nicht

    Die normale Ausführung der Arbeitsmappe erfolgt im Browser bzw. in der WebView und den zugehörigen Sprach-Laufzeitumgebungen mit einem virtuellen Dateisystem anstelle eines uneingeschränkten Zugriffs auf die Dateien Ihres Smartphones. Das ist eine nützliche Abgrenzung, aber keine Garantie dafür, dass Code keinen Schaden anrichten kann. Zulässiges JavaScript und Brücken dorthin können auf App-Daten und gespeicherte Anmeldedaten zugreifen; Netzwerkbeschränkungen bieten nach dem Start von erlaubtem Code lediglich Best-Effort-Schutz und stellen keine Isolationsgrenze dar, der Sie Geheimnisse anvertrauen sollten. Die bevorstehende Ausführungsabfrage ergänzt einen Bestätigungsschritt, keine Isolation von den Daten der App. Verwenden Sie eine Übungs-Arbeitsmappe und achten Sie darauf, dass deren Inhalte nicht privat sind.

    Remote/MCP-Terminal unterscheidet sich davon: Es kann eine echte Shell auf dem Broker-Host außerhalb der browserlokalen Sandbox bereitstellen. Lassen Sie „Remote“ und „Terminal“ hier deaktiviert. Siehe Remote und Sicherheit (Englische Referenzseite), bevor Sie diese aktivieren. Ein höfliches „Tu nicht…“ im Prompt ist keine Sicherheitsmaßnahme.

  2. Wählen Sie im Assistenten-Panel Diese Arbeitsmappeaus. Lassen Sie Review, Remoteund Terminal für dieses Beispiel mit direktem Anbieter deaktiviert.
  3. Senden Sie den Übungs-Prompt im untenstehenden Hinweisfeld. Die Schaltfläche Senden des Panels startet bereits die agentische Werkzeugschleife: Es gibt hier keinen zusätzlichen Umschalter für den „Agent-Modus“. Die Schaltfläche Agent des Vollbild-Editors ist ein separater Workflow.

    Kopieren Sie diesen Prompt. Fügen Sie ihn in das Nachrichtenfeld des Assistenten ein, nicht in eine Codezelle, und tippen Sie dann auf Senden.

    Fügen Sie in dieser Übungs-Arbeitsmappe eine Markdown-Erklärung ein, gefolgt
von einer JavaScript-Zelle namens summary_demo. Erzeugen Sie ein Eingabearray
aus 10 pseudozufälligen Ganzzahlen von 1 bis einschließlich 20.
Verwenden Sie den Park-Miller-Generator mit dem anfänglichen state 42. Aktualisieren Sie für jeden
Wert zuerst state = (16807 * state) % 2147483647;
hängen Sie dann 1 + Math.floor(20 * state / 2147483647) an.

Geben Sie das erzeugte Eingabearray aus und berechnen Sie anschließend dessen Anzahl (Array-
Länge), das arithmetische Mittel, das Minimum und das Maximum. Geben Sie jedes

  4. Lesen Sie die vorgeschlagene Erklärung und die neue summary_demo-Zelle. Prüfen Sie, ob sie die Eingabe gemäß der angegebenen Regel erzeugt und die Zusammenfassungen aus diesem Array berechnet. Führen Sie die Zelle selbst aus und vergleichen Sie das Ergebnis mit der folgenden Überprüfung. Die erwarteten Ergebnisse sind Anzahl 10, Mittelwert 9.3, Minimum 1, Maximum 20.

Sowohl die Eingabe als auch die Zusammenfassungen prüfen

Der Seed legt die Sequenz fest, sodass diese zufällig wirkende Eingabe reproduzierbar ist. Bei der oben genannten Aktualisieren-vor-Ziehen-Regel ist Folgendes zu erwarten:

Input: [1, 11, 15, 6, 8, 4, 20, 11, 11, 6]
Count: 10
Mean: 9.3
Minimum: 1
Maximum: 20

Die Bezeichnungen in der Ausgabe können abweichen, die Zahlen sollten jedoch übereinstimmen. Ein erneutes Ausführen der Zelle sollte dieselbe Eingabe und dieselben Zusammenfassungen liefern. Ein anderer Seed verändert die Übung; dieser kleine Generator dient einer reproduzierbaren Demonstration, nicht sicherheitskritischer Zufälligkeit.

Vor dem Senden: Der Assistent bezieht die ausgewählte Konversation und eine begrenzte Vorschau der Zellen der aktuellen Arbeitsmappe mit ein (bis zu den ersten 500 Zeichen jeder Zelle plus Metadaten). Erlaubte Werkzeuge können mehr senden. Das Deaktivieren des Durchsuchens des Quellcodes verhindert nicht, dass Arbeitsmappenvorschauen gesendet werden. Dies unterscheidet sich von den kleineren Nutzdaten der aktuellen Zelle, die unten bei der Vervollständigung verwendet werden. Geplante Änderungen am Arbeitsmappen-Kontext werden im Anhang beschrieben.

Pausiert mit einer „Weiter“-Schaltfläche? Das unten hervorgehobene Agenten-Limits (pro Durchlauf) → Max. Schritte steuert das Schrittkontingent für einen begrenzten Durchlauf. Der Agent kann dieses Limit erreichen, bevor er fertig ist. Lesen Sie, was er bereits getan hat, und drücken Sie dann Fortfahren, wenn die Aufgabe noch nicht abgeschlossen ist und Sie einen weiteren begrenzten Durchlauf wünschen. Das Fortsetzen kann weitere API-Gebühren verursachen; nach Fertig ist es nicht mehr erforderlich.

Schritt 4 · Alternativen anfordern, wann immer Sie möchten

API-basierte Vervollständigungen anfordern

  1. Öffnen Sie Menü → Vervollständigung und wählen Sie dann Abschnitt → KI-Vorschläge (online). Setzen Sie KI-Vorschläge → Beim Antippen.
  2. Belassen Sie Vervollständigungsmodell → KI-Assistenten folgen, um dessen Anbieter, Endpunkt und Modell zu übernehmen. Oder wählen Sie Anbieter und Modell wählen, um einen gespeicherten Anbieter/Endpunkt und ein kostengünstiges Modell auszuwählen, das sich für kurze Vorschläge eignet. Auf diesem Bildschirm wird kein Schlüssel eingegeben; über KI-Einstellungen öffnen können Sie zuvor einen hinzufügen.
  3. Öffnen Sie Erweitert dieses Bereichs, um das Antwort-Timeout und die Ausgabenbegrenzungen zu überprüfen. Die Standardwerte sind 6 Sekunden, $0.25/Tag und $5/Monat. Prüfen Sie die Preise, bevor Sie diese Werte erhöhen.
  4. Kehren Sie zu einem JavaScript-Editor zurück und geben Sie dieses Übungs-Snippet ein: 
    const values = [12, 15, 18];
const average =
    Lassen Sie die Schreibmarke hinter der unvollständigen const average = -Zeile stehen. Tippen Sie am Ende der Vorschlagsleiste auf …, verwenden Sie die Zusatztaste …AI oder drücken Sie Ctrl + Shift + Space.
  5. Überprüfen Sie die tatsächlichen Nutzdaten und das Ziel der ersten Anfrage vor dem Senden. KI-Chips sind mit einer ✦-Markierung versehen. Tippen Sie auf einen Chip, um ihn zu übernehmen; ein gekürzter oder mehrzeiliger Chip öffnet zunächst eine Vorschau. Überprüfen Sie den resultierenden Quellcode vor der Ausführung.

Wählen Sie den Code aus, nicht einfach einen KI-Chip. Bei dieser Anfrage schlug der erste Chip values.reduce((a, b) => a + b, 0) / values.length; vor. Tippen Sie darauf, um die vollständige Vorschau zu sehen: Er summiert das Array und teilt durch dessen Länge, was für dieses Beispiel 15 ergibt. Der zweite Chip schlug eval(values.join(' + ')) / values.length; vor. Lehnen Sie diese unnötige eval-Alternative ab: Die Berechnung eines Mittelwerts erfordert es nicht, eine Zeichenkette in ausführbaren Code umzuwandeln. Prüfen Sie Ihren eigenen zurückgegebenen Code vor der Übernahme und führen Sie ihn erst nach der Prüfung aus.

Die Anfrage fordert bis zu fünf Alternativen an, auf Ihren Bildschirm passen jedoch möglicherweise weniger. Ein weiteres Antippen blättert zunächst durch bereits empfangene Alternativen; sind diese erschöpft, können weitere angefordert werden. Tippen Sie während des Ladevorgangs der Anfrage, um sie abzubrechen. Spätere Antworten werden verworfen, sobald das Timeout abläuft, und durch Tippen oder Bewegen der Schreibmarke veralten vorherige Vorschläge.

Unabhängig bedeutet unabhängig: Eine separate Vervollständigungsauswahl bleibt unabhängig, wenn Sie das Modell des Assistenten ändern. Das ist nützlich, wenn Sie einen leistungsfähigen Agenten, aber eine kostengünstige Autovervollständigung wünschen. Das Folgen des Assistenten übernimmt dessen Identität, nicht seine Konversation oder Agentenberechtigungen.

Wissen, wofür Sie bezahlen und was Sie senden

Die Online-Vervollständigung erfolgt auf Abruf: Gewöhnliches Tippen sendet nichts. Prefetch while I type ist in diesem Workflow noch nicht verfügbar. Die Vervollständigung sendet einen begrenzten Kontext der aktuellen Zelle: höchstens 1,500 Zeichen vor der Schreibmarke, 200 danach und bis zu 12 lokale Namen – nicht den Assistenten-Chat oder die gesamte Arbeitsmappe. Das Maskieren von Geheimnissen erfolgt nach dem Best-Effort-Prinzip, überprüfen Sie die Nutzdaten daher selbst.

Immer erlauben erteilt eine dauerhafte Zustimmung für dieses Ziel; bei einem Wechsel von Anbieter, Endpunkt oder Modell wird erneut nachgefragt. Ohne Nachfrage senden schaltet diese Auswahl zunächst scharf, zeigt die ersten echten Nutzdaten jedoch einmalig an. Behalten Sie Jedes Mal fragen während der Einarbeitung bei.

Die Tages- und Monatsbeträge sind weiche Ausgabenbegrenzungen nur für die Vervollständigung, keine garantierten Abrechnungslimits des Anbieters und nicht das Budget für Anfragen an den Assistenten oder KI-Prompts. Fehlgeschlagene und abgebrochene Anfragen können ihre reservierten Gebühren einbehalten. Das Löschen des Ausgabenverlaufs setzt die Limits nicht zurück. Ein Modell ohne angegebenen Preis erfordert explizite Preisobergrenzen für Ein- und Ausgabe, andernfalls verweigert die App das Senden.

Schritt 5 · Optionaler Android-Download

Das On-Device-Modell ausprobieren

Das optionale Modell Qwen2.5-Coder 0.5B schlägt Code lokal vor, wenn die Tabellen unsicher sind. Es ist ein kleines Code-Vervollständigungsmodell, kein Ersatz für den dialogorientierten Agenten. Nach der Installation sendet die Inferenz keinen eingegebenen Code an einen Anbieter und verursacht keine API-Kosten.

  1. Öffnen Sie auf einem geeigneten Android-Smartphone mit Pro, das über Google Play installiert wurde, Menü → Vervollständigung → Abschnitt → Lokales Modell (auf dem Gerät).
  2. Tippen Sie auf Installieren und planen Sie Zeit und Speicherplatz für den etwa 400 MB großen Download ein. Derzeit per Sideload installierte Versionen können das Modell über diesen Ablauf nicht herunterladen.
  3. Behalten Sie nach Fertigstellung Lokales Modell verwenden → Wenn unsicher bei. Tabellen decken einfache Fälle ab; das Modell ergänzt Vorschläge, wenn diese unsicher sind. Immer führt es häufiger aus; Aus stoppt es, ohne den Download zu löschen.
  1. Kehren Sie zu einer Codezelle zurück und halten Sie bei einem unvollständigen Namen oder einer unvollständigen Zeile kurz inne. Die Ergebnisse variieren je nach Kontext; nicht jedes Innehalten erzeugt einen Vorschlag. Übernehmen Sie einen passenden Ghost-Text oder Chip, prüfen Sie den Quellcode und führen Sie ihn anschließend separat aus.

Welches Smartphone bietet ein angenehmes Arbeiten?

Die Mindestvoraussetzung ist 64-Bit-ARM-Android mit mindestens 4 GB RAM, was kein Versprechen für eine reibungslose Leistung darstellt. Ein Smartphone der Galaxy-S24+-Klasse ist ein praxisnaher Richtwert für komfortables Arbeiten: Samsung gibt für das S24+ 12 GB RAM an, was mehr Spielraum für die App, Kernel und das Modell lässt. Dies ist eine Leistungsempfehlung, keine Verpflichtung zum Kauf dieses Modells. Spezifikationen der Samsung-S24-Serie.

Ein Galaxy S10+ verfügt über geeignete Varianten mit 8 GB oder 12 GB. Nach den informellen Erfahrungen des Betreuers kann die lokale Vervollständigung dort funktionieren, sich aber langsamer anfühlen als die API-Vervollständigung; der Vergleich hängt vom Modell und dem Netzwerk ab. Der aufgezeichnete Benchmark der lokalen Engine hat das S10+ nicht gemessen, daher handelt es sich hierbei nicht um einen gemessenen Geschwindigkeitsvergleich oder eine Garantie für jedes Gerät. Achten Sie auf Verzögerungen oder eine nicht reagierende App, wenn Sie das Modell mit großen Arbeitsmappen und speicherintensiven Kerneln kombinieren. Spezifikationen der Samsung-S10-Serie.

Der frühere Test der nativen Engine auf einem Gerät der S24+-Klasse ergab nach dem Laden einen Warm-Start-Median für das erste Wort von rund 0.10 Sekunden und einen Kalt-Start-Median für das erste Wort von rund 0.24 Sekunden. Dies sind exemplarische Benchmark-Ergebnisse, keine Garantien: Ein ungecachtes anfängliches Laden dauerte mehrere Sekunden. Das geladene Modell belegte etwa 460–490 MB Speicher im App-Prozess, zusätzlich zu WebView, Python/R-Laufzeitumgebungen und dem Betriebssystem.

Wenn ein älteres Smartphone träge wird: Setzen Sie Lokales Modell verwenden → Aus und nutzen Sie stattdessen Tabellen oder API-Alternativen auf Abruf. Unter „Lokal“ in Erweitert bewirkt das Einstellen von Keep loaded after leaving the app → 0, dass das Modell beim Verlassen der App freigegeben wird; die Steuerungen für Leerlauf-Entladung und niedrigen Akkustand helfen ebenfalls. Speichern/exportieren Sie Ihre Arbeitsmappe vor der Fehlersuche. Ein Modell ohne API-Kosten beansprucht dennoch Speicherplatz, Arbeitsspeicher und Akku.

Wir werden darstellen, wie sich die geschätzte Varianz über viele kleine Stichproben hinweg verändert. Es handelt sich um neue normalverteilte Stichproben – nicht um das frühere summary_demo-Ganzzahl-Array. Ziel ist es, Konfigurieren → Vorschau → Anwenden → Ausführen kennenzulernen, nicht die Statistik zu meistern.

Varianz ist nicht Student-t. Bei unabhängigen normalverteilten Stichproben des Umfangs 10 folgt 9s² / σ² einer Chi-Quadrat-Verteilung mit 9 Freiheitsgraden. Hier beträgt die wahre Varianz σ² = 1. Die Student-t-Verteilung beschreibt stattdessen den standardisierten Stichprobenmittelwert (mean − μ) / (s / √10) unter Verwendung der geschätzten Standardabweichung s; auch sie hat hier 9 Freiheitsgrade. Keine Offline-Vorschläge auf einem Smartphone

Keine Online-Anfrage
Prüfen Sie „Auf Abruf“, den gespeicherten Schlüssel für den exakten Anbieter/Endpunkt, den Preiseintrag oder die Obergrenzen des gewählten Modells, Einwilligungen und Ausgabensummen. „Open“ ist für die Vervollständigung nicht erforderlich. Der Assistent fragt vor der Ausführung einer Zelle nach – oder fragt nicht nach

Anhang · Bevorstehende Ausführungsgenehmigung · vorgeschlagenes Pro 1.5.0

Unveröffentlicht: Diese Steuerungen beschreiben die Implementierung der nächsten Version, nicht ein Versprechen, dass Ihre 1.4.0-Installation diese bereits enthält. Die Versionsnummer ist vorläufig.

  • KI-Einstellungen → Sicherheit… → execute_cell / run_cells bietet bereits Default / Allow / Ask / Deny. Dieses Update ändert das von „Open“ übernommene „Default“ zu Nachfragen; „Full control“ behält „Allow“ bei. Explizite Tool- oder Kernel-Regeln können übernommene Standardwerte ersetzen; sind beide explizit definiert, greift die sicherere Regel. Behalten Sie während der Einarbeitung „Default“ oder „Ask“ bei. „Allow“ ist eine Außerkraftsetzung, keine stärkere Sandbox; Kernel-Ask/Deny, „Review“ und die globale Deaktivierung von JavaScript gelten weiterhin.
  • Lesen Sie die Ausführungsanfrage, bevor Sie Ausführen wählen; lassen Sie Zukünftige Ausführung von Assistenten-Zellen ohne Nachfrage erlauben unmarkiert, um nur diese eine Anfrage zu genehmigen. Das Markieren ändert die gemeinsame Regel für das Ausführungswerkzeug über alle Arbeitsmappen hinweg bis zum Zurücksetzen – nicht nur für diese Zelle, Konversation oder diesen Anbieter. Ein explizites „Ask“ für den Kernel blendet diese Option aus.
  • Prompts zur Namensraum-Inspektion und für neu erstellte Zellen können diese dauerhafte Freigabe nicht erteilen. Eine Ausführungsabfrage für erstellte Zellen enthält eine begrenzte Code-Vorschau; eine lange Vorschau endet mit Auslassungspunkten. Ist sie gekürzt, wählen Sie „Abbrechen“, prüfen Sie den vollständigen Quellcode der neu erstellten Zelle und führen Sie sie nur dann selbst aus, wenn Sie ihr vertrauen. Ein zuvor gespeichertes „Allow“ für die Ausführung kann bei aktiviertem automatischem Ausführen weiterhin den automatischen Start erstellter Zellen erlauben; belassen Sie das automatische Ausführen hier daher deaktiviert.
  • Wenn Sie eine andere Voreinstellung als „Full control“ wählen, während ein gespeichertes „Allow“ für das Ausführungswerkzeug wirksam bleibt, bietet eine Warnung Auf Standard zurücksetzen, „Erlauben“ beibehalten oder Abbrechen an. „Reset“ stellt die Tool-Regel der gewählten Voreinstellung wieder her, ohne Kernel-Überschreibungen zu löschen. „Keep“ behält die Überschreibung bei. „Cancel“ stellt die vorherige Auswahl der Voreinstellung wieder her. „Reset“ und „Keep“ bleiben Entwurfsänderungen, bis Sie die Einstellungen speichern.

Eine Ausführungsgenehmigung ist keine pauschale Erlaubnis zur Datenweitergabe. Ausgaben von Ausführungswerkzeugen können an das Modell des Assistenten zurückgesendet werden, und erlaubter Code kann das Netzwerk nutzen. Immer erlauben bei der Online-Vervollständigung, die Kontextprüfung bei KI-Prompts sowie die Datenschutzerklärung für Remote/MCP bleiben separat. Die Notebook-Ausführung über MCP verwendet dieselben Ausführungsprüfungen; diese Prüfungen kapseln die Terminal-Shell eines Brokers nicht in einer Sandbox ein.

Anhang · Geplanter Arbeitsmappen-Kontext und Verlauf

Nur ein Design-Entwurf: Diese Funktionen sind weder implementiert noch einem Release zugewiesen. Sie sind unabhängig von den oben genannten bevorstehenden Änderungen zur Ausführungsgenehmigung und blockieren nicht die aktuelle Version.

  • Bei Bedarf eine Arbeitsmappen-Zusammenfassung abrufen. Der Plan ersetzt wiederholte automatische Quellcode-Vorschauen durch ein reines Metadaten-Verzeichniswerkzeug: Zellnamen, optionale Beschreibungen, Sprachen und Typen sowie eine Arbeitsmappen-Revision. Das vorgeschlagene Werkzeug ist list_cells mit view: "metadata"; der Assistent würde ausgewählten Quellcode separat einlesen. Dies ist eine begrenzte Übersicht, keine automatisch generierte KI-Erklärung.
  • Einmal anhängen statt bei jedem Senden. Ein vorgeschlagenes Kontrollkästchen Attach workbook summary this time könnte bei einer neuen Konversation standardmäßig aktiviert sein und sich deaktivieren, nachdem dieser Anhang tatsächlich gesendet wurde. Sie könnten es vor dem Senden deaktivieren oder für eine neue Übersicht erneut aktivieren. Der anfängliche Standardwert muss noch hinsichtlich Datenschutz und Benutzerfreundlichkeit geprüft werden. Fortsetzungen würden keine weitere Zusammenfassung hinzufügen, und ein Tab-Wechsel würde dies nicht unbemerkt wieder aktivieren. Die Vorschau sowie bestehende Lese- und Datenschutzberechtigungen würden weiterhin gelten; eine große Arbeitsmappe könnte weitere Seiten erfordern.
  • Deaktiviert löscht keinen Verlauf. Es würde lediglich einen neuen automatischen Anhang verhindern, nicht jedoch bereits in der Konversation vorhandene Zusammenfassungen entfernen oder erlaubte Werkzeug-Lesezugriffe unterbinden. Bestehende Steuerungen für den Vollbild-Agenten, KI-Prompts und den Vervollständigungskontext blieben weiterhin separat.
  • Änderungen zwischen Sendevorgängen sind eine spätere Option. Kompakte Aktualisierungen würden eine bekannte Ausgangsbasis für den gesendeten Kontext und verlässliche Revisionen erfordern. Manuelle Bearbeitungen durch Menschen könnten hervorgehoben werden, aber auch Bearbeitungen durch Agenten, Importe und unbekannte Änderungen fallen ins Gewicht. Eine Quellcode-Bearbeitung würde die Beschreibung einer Zelle nicht automatisch umschreiben; ein fehlender oder veralteter Verlauf würde eine frische Übersicht erfordern statt einer geratenen Aktualisierung.
  • Ein optionaler lokaler Verlauf und GitHub-Synchronisierung sind längerfristige Pro-Ideen. Lokale Sende-Prüfpunkte könnten Git-basierte Diffs unterstützen, ohne Daten weiterzugeben. Eine unabhängige Synchronisierung könnte eine Arbeitsmappe in einem Gist oder einer ausgewählten Datei in einem Repository veröffentlichen, mit eigener Nutzdaten-Vorschau und Autorisierung. Das Aktivieren des Verlaufs würde weder zu GitHub übertragen noch ein Diff an die KI senden. Git zeigt inhaltliche Änderungen an, keinen Beweis dafür, dass ein Mensch sie vorgenommen hat.

Ein Secret Gist ist nicht privat. Jeder, der dessen URL kennt, kann ihn lesen; nutzen Sie ein privates Repository, wenn der Zugriff beschränkt werden muss. Halten Sie vertrauliche Daten vor der Veröffentlichung aus Quellcode und Beschreibungen der Arbeitsmappe heraus. Dokumentation von GitHub zur Gist-Sichtbarkeit.
