边做边学

命名单元格并连接程序

单元格可以拥有一个有意义的名称（例如 numbers），而不仅仅通过其位置来识别。其他单元格可以通过 /nb/numbers/.output 读取其最新的文本输出，或者通过 /shared/ 中的普通文件交换数据。使用 JavaScript 和 Bash 尝试这两种途径，然后在另一个单元格中生成一个简短的 Bash 程序——且不会自动运行生成的代码。

  • Free + Pro 工作流
  • 经浏览器验证的示例
  • 约 15 分钟

本操作指南与屏幕截图已在 SciREPL Free 浏览器版本中于 6 日（十月 2026 年）经过核验。这些是完整的窄屏浏览器截图，并非 Android 屏幕截图。本指南尚未针对 Pro 及每个已发布版本进行检查。主要练习使用内置的 JavaScript 和 Bash：无需安装软件包、进行模型调用或下载运行环境。Python 是可选的最后一步。

此处“路径”的含义： /nb/ 是当前所选工作簿单元格的虚拟视图，可供程序使用。它不是 Android“下载”中的文件夹，也不是单独的“路径视图”屏幕。所核验的 Free 版本的 文件与存储 屏幕无法浏览 /nb/；稍后我们将特意把一些数据复制到该屏幕可显示的共享文件中。

所有教程

步骤 1

导入示例且不运行它

  1. 下载命名单元格示例工作簿 (.srwb)。保存文件本身并保留其 .srwb 扩展名。如果浏览器显示文本，请使用其保存/下载操作。
  2. 在 SciREPL 的顶部页眉中，找到 ☰ 菜单——即带有三条水平横线的按钮。打开它并选择 📂 导入文件（如 .srwb、.ipynb、.csv、.py、.zip）。如有需要，可在菜单内滚动。
  3. 在设备的文件选择器中选择 named-cell-interop.srwb。如果菜单仍处于打开状态，请退出菜单，然后在工作簿选择器中选择新的 Named Cell Interop 标签页。选择器的 ▾ 箭头位于应用标题附近。您现有的工作簿仍会保留。
  4. 阅读简介，然后找到名为 numbers、inspect_cells、write_shared、read_shared、generate_report、bash_report 和 python_total 的七个代码单元格。它们已经命名完毕，以便您跟进练习。

导入不等于运行。即使启用了自动执行，普通的 .srwb 导入也不会执行代码。本课请勿选择“运行所有单元格”：执行顺序至关重要，且最后一个 Python 单元格是可选的。在运行不熟悉的代码前请先进行检查。

需要更详细的下载和选择器步骤？请参阅手动工作簿导入操作指南。若要跟进本课，请保持选中 Named Cell Interop：/nb/ 指的是当前活动的工作簿，而非每个已打开的标签页。

步骤 2

查找并修改单元格名称

已保存的代码单元格在其自身的页眉中带有 In[…] 提示标签，已命名的单元格还会显示其名称。这个标签才是用于命名的——而不是用于编辑单元格源码的 ✎ 铅笔。显示的数字用于标识已保存的卡片；在重新排序后，它不一定与单元格在 /nb/In[N]/... 路径中的当前位置一致。引用时建议优先使用名称。

  1. 找到 numbers。在桌面端，双击其 In[…] 标签。在触屏设备上，按住该标签。在所核验的版本中，单击并非触发命名的手势。
  2. 在对话框中，将 numbers 替换为 measurements，然后使用 确定 确认。单元格页眉中的名称会更改；源码和语言则保持不变。
  3. 再次打开相同的对话框，将名称改回 numbers，然后选择 确定。后续单元格会使用该名称，因此请在继续之前将其恢复。

请选择独特且简洁的名称，例如 cube_moves 或 check_moves。名称在工作簿内必须唯一；不能包含 /、以 . 开头，或为保留的位置标签（例如 In[2]）。清空名称即可将其移除。

这就是为什么教程中会写道“先运行 cube_moves，再运行 check_moves”：这些是要在工作簿中查找的单元格名称，而不是必须单独下载的文件。当您插入或移动单元格时，名称是比位置更可靠的引用方式。

步骤 3

运行生成数据的单元格

找到 numbers。点击其自身的 ✎ 铅笔，检查源码，并确认该单元格为 代码 → JS - JavaScript。然后使用该已保存单元格的 ▶ 运行 按钮——而不是用于添加另一个单元格的新建单元格面板。

Pro 快捷方式：您还可以通过双击单元格的源码文本在 Pro 中打开已保存单元格的编辑器。✎ 铅笔在两个版本中均可使用。此编辑快捷方式不同于通过双击或长按 In[…] 标签来修改其名称。

console.log(JSON.stringify({values: [3, 5, 8]}));

预期会得到如下单行输出：

{"values":[3,5,8]}

结果是 JSON 文本。其结构使其比普通文字消息更容易被另一种语言读取。我们并非在传递活动的 JavaScript 对象，也未将 JavaScript 变量共享给 Bash 或 Python。

步骤 4

通过虚拟文件系统读取单元格

numbers 的虚拟目录包含带有点前缀的属性。路径由工作簿挂载点、单元格标识符和所需属性组合而成：

/nb/                         current workbook's cells
└── numbers/                 this named cell
    ├── .code                source text
    ├── .output              latest text output
    ├── .language            javascript
    ├── .type                code
    └── .name                numbers
工作簿路径接口所使用的单元格属性
属性读取该属性所获得的内容
.code当前的源码，无论该源码是否运行过。
.output最新的文本输出。它是只读的：由执行操作提供。它可能为空或已过期。
.language存储的语言标识符，例如 javascript 或 bash。
.type单元格类型，例如 code 或 markdown。
.name所分配的名称；若单元格未命名，则为空文本。

现在打开 ✎ 铅笔进入 inspect_cells，检查 代码 → Bash，然后运行它。这将读取生成单元格的源码、其 JSON 输出及其语言，然后列出当前工作簿的单元格标识符。它不会写入或更改任何单元格或文件。

printf 'Source:\n'
cat /nb/numbers/.code
printf '\nOutput:\n'
cat /nb/numbers/.output
printf '\nLanguage:\n'
cat /nb/numbers/.language
printf '\nCell names and positions:\n'
ls /nb/

名称、位置与相对引用

同一个单元格也可以通过其当前基于 1 的位置来寻址，例如 /nb/In[2]/.output 表示当前顺序中的第二个单元格。Markdown 单元格也计入其中。这并非永久的卡片 ID：重新排序后，输出显示的 In[…] 数字可能与该路径所使用的位置不同。当您重排或插入单元格时，位置引用的含义会发生变化；而名称引用则始终能准确定位到该命名单元格。

Bash 和 JavaScript 还支持相对于正在执行的单元格的引用：/nb/-1/.output 表示前一个单元格，而 /nb/./.code 表示当前单元格。它们需要执行上下文并依赖于单元格顺序。本教程使用显式名称代替；不依赖于相对引用在各种语言中表现一致。

步骤 5

通过共享文件交换数据

共享虚拟文件系统存放不同语言内核均可使用的普通文件。在这里，/shared/ 指的是在您的 SciREPL 浏览器/应用会话内部管理的文件存储——而不是 Android 的“下载”文件夹、计算机上的某个文件夹或云端同步。共享文件承载文本或字节；它们不会使某种语言的活动变量对另一种语言可用。

程序引用数据的两种方式
路径所指向的目标触发更新的操作
/nb/numbers/.output所选工作簿中单元格的最新文本输出。再次运行该单元格。
/shared/data/named-cell-tutorial/values.json一个普通的 JSON 文件，可跨内核与工作簿标签页使用。显式写入该文件的程序或文件编辑器。

写入普通的 JSON 文件

打开 ✎ 铅笔进入 write_shared，检查 代码 → JS - JavaScript，然后运行它。这将读取生成单元格的最新文本输出，并将其保存为共享的 JSON 文本文件。共享文件系统会根据需要自动创建父文件夹。

const text = window.notebookVFS.readFile('/nb/numbers/.output');
if (!text) throw new Error('Run numbers first.');
window.sharedVFS.writeFile('/shared/data/named-cell-tutorial/values.json', text, 'javascript');
console.log('Saved JSON to /shared/data/named-cell-tutorial/values.json');

结果是一个包含副本的单独文件（包含 JSON 输出的副本），而不是 /nb/numbers/.output 的另一个别名。专用文件夹可将本示例的小型暂存文件与您的其他数据隔开；重新运行 write_shared 会覆盖这个具体的课时文件。

从另一个程序读取该文件

打开 ✎ 铅笔进入 read_shared，检查 代码 → JS - JavaScript，然后运行它。这个独立的程序读取已保存的文件，而不是 numbers 单元格：

const text = window.sharedVFS.readFile('/shared/data/named-cell-tutorial/values.json', 'utf8');
if (!text) throw new Error('Run write_shared first.');
const record = JSON.parse(text);
console.log(record.values.reduce((sum, value) => sum + value, 0));

预期会得到 16。显式的 'utf8' 会将文件的字节作为文本读取，以便进行 JSON 解析。每个内核都有自己的文件 API：在此处 JavaScript 使用共享文件系统帮助工具；Python 则可以使用 open(...)，如下文的可选步骤所示。这并不是一个完整的操作系统文件系统。

若要进行单独的跨语言检查，您可以添加一个新的 代码 → Bash 单元格并运行此命令。它会读取同一个普通文件并输出 {"values":[3,5,8]}：

cat /shared/data/named-cell-tutorial/values.json

在文件图形界面中查看同一文件

  1. 打开 ☰ 菜单 → 文件与存储。
  2. 找到共享的 data 文件夹，然后找到 named-cell-tutorial 和 values.json。选择该文件以查看其 JSON 文本。
  3. 确认其包含 {"values":[3,5,8]}，然后关闭“文件与存储”以继续操作工作簿。

副本不会自动更新。修改或重新运行 numbers 只会更改其最新的单元格输出，而不会更改已存在的 values.json。重新运行 write_shared 可刷新副本，然后运行 read_shared 根据其重新计算。文件保存在本地应用/浏览器存储中，但清除该存储或卸载应用可能会将其移除。本地持久化存储并非备份；请导出您需要保留的文件。

有关查看、编辑和导出共享文件的信息，请参阅CSV 与“文件和存储”操作指南。仅限工作簿的 .srwb 导出不包含单独的文件（例如这个 JSON 副本）；请使用软件包归档导出将工作簿与所选数据文件一并打包导出。

步骤 6

生成另一个单元格的代码，然后自行运行

到目前为止，Bash 读取了 JavaScript 输出。现在，JavaScript 将使用相同的 JSON 文本来计算总计，并将一个简短的 Bash 程序写入现有的 bash_report 单元格中。编写代码与运行代码是两个独立的操作。

  1. numbers运行 → JSON 文本
  2. generate_report读取 JSON → 写入 Bash 源码
  3. bash_report检查 → 手动运行

此写入操作会替换源码。请使用配套的临时 bash_report 单元格，而不要使用包含您需要保留的工作成果的单元格。在自己的工作簿中尝试源码写入之前，请先做好备份。在本次练习中，请勿覆盖生成器本身，也请勿以编程方式修改 .language。

  1. 确认 bash_report 存在且其语言为 Bash。其初始源码如下所示；先不要运行它。
  2. 打开 ☰ 菜单 → 设置 → 笔记本 VFS。生成器的写入操作必须勾选 允许单元格修改其他单元格。在所核验的版本中该选项默认开启，但请检查您的设置。您无需启用跨笔记本读取、跨笔记本写入或以编程方式执行。关闭“设置”。
  3. 打开 ✎ 铅笔进入 generate_report，检查 代码 → JS - JavaScript，然后运行它。
const text = window.notebookVFS.readFile('/nb/numbers/.output');
if (!text) throw new Error('Run numbers first.');
const data = JSON.parse(text);
const total = data.values.reduce((sum, value) => sum + value, 0);
const updated = window.notebookVFS.writeFile(
  '/nb/bash_report/.code', `echo "Total: ${total}"`
);
if (!updated) throw new Error('Check bash_report exists and cell writes are allowed.');
console.log('Updated bash_report source; inspect it, then run it yourself.');

目标单元格初始包含以下占位内容：

echo "Run generate_report first"

生成器执行成功后，bash_report 的源码变为 echo "Total: 16"。该写入操作并未运行 Bash。打开该单元格的 ✎ 铅笔检查新源码，然后点击其自身的 ▶ 运行。预期会得到 Total: 16。

readFile(...) 返回文本；未知的单元格或属性会返回 null。writeFile(...) 报告写入是否成功。若生产者没有输出或目标位置无法写入，生成器中的检查将阻止其继续执行。名称区分大小写：请保持拼写完全一致。

步骤 7

修改数据并刷新各个依赖步骤

  1. 使用 numbers 的 ✎ 铅笔进行编辑。将 [3, 5, 8] 改为 [4, 5, 8]，然后运行该单元格。其 JSON 现在包含 4。
  2. 在运行其他任何内容之前，先查看 bash_report。其之前的源码和输出保持不变：不存在自动依赖刷新。
  3. 重新运行 generate_report。这会将报告的源码更改为 echo "Total: 17"，但其原有的 Total: 16 输出可能仍然可见。
  4. 检查并重新运行 bash_report。现在其输出为 Total: 17。
  5. 在刷新文件之前，重新运行 read_shared：它仍然显示 16（来自旧 JSON 副本）。现在重新运行 write_shared，然后运行 read_shared；文件途径也会显示 17。在“文件与存储”中重新打开 values.json 以检查已更改的文件。

源码、输出和复制的文件是不同的概念。在其消费者使用之前，请通过该单元格的 ▶ 运行 完成打开的源码编辑；未保存的编辑器草稿不是存储的 .code。源码写入不会执行目标单元格，复制的文件也不会跟随后续的更改。请遵循明确的顺序：生产者 → 生成器 → 报告。可见的旧输出并不能证明当前源码已经运行。

导出工作簿以保留您的源码编辑和名称。普通的 .srwb 导入目前会丢弃已保存的代码输出，因此重新打开后，请在其读取程序之前重新运行 numbers，然后再运行生成器和报告。独立的共享数据文件需要进行文件或软件包导出。请参阅文件与导出参考 (英文参考页面)。

可选

从 Python 读取两种途径

您可以到此为止，而无需启动 Python。若要尝试第三种语言，请先运行 numbers 和 write_shared，然后检查并运行 python_total（作为 代码 → Python）：

import json
record = json.loads(nb_read('numbers', '.output'))
print('Cell output:', sum(record['values']))
with open('/shared/data/named-cell-tutorial/values.json') as source:
    saved = json.load(source)
print('Shared file:', sum(saved['values']))

对于原始数据，预期会得到 Cell output: 16 和 Shared file: 16；或者两行都将为 17（在步骤 7 中刷新两条途径之后）。Python 的 nb_read('numbers', '.output') 用于读取命名单元格的最新文本输出。独立的 open(...) 使用标准 Python 文件语法读取共享文件。标准 json 模块负责解析两者；不需要 %pip install。如果仅刷新了生产者，两个总计可能会有所不同。

首次使用时，Python 可能需要初始化或下载其运行时环境。根据您的版本和现有的许可情况，可能会显示隐私/网络提示；请在同意前仔细阅读。此可选步骤并非 JavaScript/Bash 练习所必需，且仅导入配套工作簿并不会启动 Python。

继续探索

识别其他工作簿中的模式

命名单元格提供了一个简单的互操作边界：一个程序生成文本，另一个程序读取该文本或利用它来生成源码。目录中已有更大的示例可供查看：

  • 预期寿命数据分析 读取普通的 CSV 文件（源自 /shared/data/），使用 Python 与 R：这是共享文件途径，而非命名单元格读取。它会下载数据集并使用软件包；在运行前请阅读其设置和许可要求。
  • Prolog 生成 R 代码 读取已命名的 Prolog 源码（通过 nb_read(..., '.code', ...)），并使用 nb_write('r_factorial', '.code', ...) 写入生成的 R 源码。R 单元格单独运行。
  • Prolog 生成 TypR 代码 将生成的定义与命名的纯源码查询单元格相结合，然后写入 typr_output。#!source 单元格无需执行即可作为源码读取。

在 ☰ 菜单 → 浏览软件包… 中搜索这些标题。它们属于补充阅读材料，并非本指南经过认证的执行操作指引；其适用的版本和设置要求各不相同。Prolog-generates 工作簿需要通过“浏览”安装 unifyweaver-scirepl 依赖项；单独导入原始工作簿不会安装该依赖项。对于手动导入的 .ipynb，请先确认 菜单 → 设置 → 导入与编辑 → 导入工作簿时自动执行单元格 处于关闭状态，因为在此设置下 Jupyter 导入可能会执行代码。请参阅“浏览”操作指南和手动导入指南。

如果显示异常

检查名称、工作簿及运行顺序

  • 命名对话框未打开：双击或长按已保存单元格的 In[…] 标签，而不是其源码、输出或铅笔图标。单击并非触发命名的手势。
  • 找不到生产者：请保持选中 Named Cell Interop，恢复完全一致的名称 numbers，并检查拼写及大小写。重命名不会重写其他单元格中的路径。
  • 生成器提示“先运行 numbers”：检查并运行 numbers。仅导入或编辑其源码并不会填充 .output。
  • JSON 解析失败：请将生产者与完整示例进行比对。其输出必须仅包含 JSON，不能包含标题或额外打印的消息。
  • 无法写入报告：请确认现有的 bash_report 单元格存在于此工作簿中，并且已勾选 允许单元格修改其他单元格。请勿通过启用以编程方式执行来解决源码写入问题。
  • 报告仍显示 16：编辑数据后，请先运行 numbers，然后运行 generate_report，再运行 bash_report。使用 write_shared 单独刷新复制的文件，然后重新运行 read_shared。
  • 在“文件与存储”中找不到 /nb：在所核验的版本中，该屏幕显示的是共享文件，而非这个虚拟单元格挂载点。请改为运行 write_shared 并查找其特意复制的 values.json 副本。
