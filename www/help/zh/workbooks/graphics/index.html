添加图片、图表和公式

工作簿不仅可以用代码解释概念，也可以用图片。尝试通过三种方式展示同一个简单的坐标系：Markdown 中的静态图像、由 JavaScript 绘制的图片，以及用 KaTeX 排版的公式。您不需要 Python、R、安装软件包或 AI 账户。

  • Free + Pro 工作流
  • 经浏览器验证的示例
  • 约 10 分钟

示例和屏幕截图已在 SciREPL Free 浏览器构建版本中于 6 日十月 2026 年完成检查。屏幕截图使用的是较窄的浏览器视口；它们并非 Android 截屏。Android 上使用了相同的控件，但其位置可能会有所不同。本指南未对 Pro 以及每个已发布的应用版本进行测试。

步骤 1

打开示例工作簿

配套文件包含完整的示例，包括一个嵌入式 PNG。它将所有内容保留在一个小型工作簿中，因此您无需输入长长的 Base64 图像字符串。

  1. 下载图形示例工作簿 (.srwb)。保存实际文件并保留其 .srwb 扩展名。如果浏览器显示文本，请使用其保存/下载操作。记下保存文件的文件夹。
  2. 打开 SciREPL。在应用顶部的页眉中，找到 ☰ 菜单（即带有三条水平线的按钮）。轻点或点击它。
  3. 选择 📂 导入文件（如 .srwb、.ipynb、.csv、.py、.zip）。如有需要，可在菜单内部滚动。在设备的文件选择器中，从“下载”或您选择的文件夹中选择 workbook-graphics.srwb。
  4. 如果菜单仍处于打开状态，请将其关闭，并在工作簿选择器中选择新的 Workbook Graphics 标签页。您现有的标签页将被保留。
  5. 找到名为 static_axes、embedded_png、canvas_axes 和 math_axes 的四个单元格。在运行代码前请先阅读它们。静态图表和公式会直接由其 Markdown 源码显示；JavaScript 图片仅在您运行其单元格后才会显示。

导入并不等于运行。即使启用了自动执行设置，.srwb导入也不会执行其代码。在本课中，只有 canvas_axes 需要进行 JavaScript 执行。这里没有 运行所有单元格 步骤。

需要有关下载或选择器的更多详细信息？请遵循手动工作簿导入演练。上述名称会出现在已保存的单元格上；命名单元格路径教程解释了如何分配和使用它们。您也可以使用以下步骤在已打开的工作簿中创建这些示例。

步骤 2 · 方法 1

在 Markdown 中保留静态图表

想象一张正对着您的纸。r 沿纸面指向右方，u 沿纸面指向上方，而 n 则垂直穿出纸面指向您。带有点的圆圈表示朝外的方向，就像看到箭尖朝您指来一样。

编辑导入的图表

  1. 找到 static_axes。在该已保存单元格自身的页眉中轻点其 ✎ 铅笔（位于 ✕ 附近）。这会打开现有单元格的源码；新建单元格面板则会创建另一个单元格。
  2. 将单元格类型按钮保持设置为 Md。在 SVG 文本中，将 r: right 更改为 r: across。
  3. 轻点该单元格的 ▶ 运行 按钮以重新保存并渲染 Markdown。对于 Md 单元格，此按钮用于渲染文本；它不会执行 JavaScript 或启动语言运行时。

或者创建您自己的 Markdown 单元格

  1. 找到用于输入下一个单元格的新建单元格面板。如果它已折叠，请使用应用标题附近的 ⌃ 显示新建单元格面板 按钮。
  2. 轻点标有 代码 的单元格类型按钮，使其变为 Md。Markdown 是一种单元格类型，而不是语言下拉菜单中的条目。
  3. 将下方完整的 SVG 复制到文本字段中，且无需添加 Markdown 代码围栏 (```)。在周围的文本与 SVG 之间保留一行空行。
  4. 轻点 ▶ 运行 添加渲染后的 Markdown 单元格。您应该会看到纸张以及全部三个方向标签。
<svg xmlns="http://www.w3.org/2000/svg"
     viewBox="0 0 360 220" width="100%" height="220"
     role="img" aria-label="Right, up and outward normal on paper">
  <title>A paper coordinate frame</title>
  <rect x="20" y="18" width="320" height="184"
        rx="6" fill="#ffffff" stroke="#526170" stroke-width="2" />
  <path d="M110 145 H280" fill="none" stroke="#075d69" stroke-width="3" />
  <polygon points="280,145 267,138 267,152" fill="#075d69" />
  <path d="M110 145 V48" fill="none" stroke="#064d91" stroke-width="3" />
  <polygon points="110,48 103,61 117,61" fill="#064d91" />
  <circle cx="110" cy="145" r="10" fill="#ffffff" stroke="#14191f" stroke-width="2" />
  <circle cx="110" cy="145" r="3" fill="#14191f" />
  <text x="204" y="168" fill="#14191f" font-size="16">r: right</text>
  <text x="124" y="62" fill="#14191f" font-size="16">u: up</text>
  <text x="42" y="190" fill="#14191f" font-size="16">n: toward you</text>
</svg>

SciREPL 会对 Markdown 进行清理过滤。此示例使用普通的 SVG 形状、文本以及显式的 fill/stroke 属性。其箭头为多边形：请勿依赖 marker-end="url(...)"、<style> 块、脚本或动画能在清理过滤后保留下来。

改用嵌入式 PNG

另一种静态方案是直接在 Markdown 源码中存储 Base64 数据的 PNG。标准的 Markdown 图像语法如下所示：

![Paper axes](data:image/png;base64,PASTE_THE_COMPLETE_BASE64_PNG_HERE)

该行显示的是格式，而不是可正常显示的图片：请将占位符替换为完整编码的 PNG，或者使用已可正常工作的 embedded_png 单元格。base64, 之后的部分是图像数据，而不是文件名。请将其保持在同一行上。

为了让图片在小屏幕上也能适应单元格大小，配套文件中的 embedded_png 单元格使用了下方带有 width="100%" 的等效内联 HTML。它仍存储在 Markdown 内部，而不是作为代码输出：

<img alt="Paper axes" width="100%"
     src="data:image/png;base64,PASTE_THE_COMPLETE_BASE64_PNG_HERE">

选择一种静态途径：使用内联 SVG 元素制作小型可编辑图表，或使用 data:image/png;base64,... 图像制作光栅图片。像 data:image/svg+xml,... 这样的 SVG 数据 URL 与内联 SVG 不同，并且在经过检查的构建版本中会被阻止。远程图像 URL 在该版本中也会被阻止。这两个自包含示例在显示时均无需下载图像。

这两个静态示例均存在于 Markdown 源码中。它们可以在工作簿导入后直接显示，无需运行代码。

步骤 3 · 方法 2

使用 JavaScript 绘制图片

静态图片会一直保持不变，直到您编辑其源码。对于由程序计算或绘制的图片，请使用 代码 单元格并选择 JS - JavaScript。此示例在 canvas 上进行绘制，将其转换为 PNG，并将该图像发送至单元格的输出中。

  1. 在导入的工作簿中，轻点 ✎ 铅笔（在 canvas_axes 上）。检查单元格类型是否为 代码，且其语言为 JS - JavaScript（紧凑选择器可仅显示 JS）。
  2. 阅读下方的代码，它是该单元格中的完整程序。它不需要其他单元格、文件、软件包或网络请求。
  3. 轻点该单元格的 ▶ 运行。JavaScript 源码下方应会出现一张图片。

若要改为创建新单元格，请转到新建单元格面板，根据需要将 Md 改回 代码，并从语言下拉菜单中选择 JS - JavaScript。粘贴代码，然后轻点 ▶ 运行。如果 JavaScript 被隐藏，请找到 ☰ 菜单 → 语言 并将其启用。

(() => {
  const canvas = document.createElement('canvas');
  canvas.width = 360;
  canvas.height = 220;
  const ctx = canvas.getContext('2d');
  ctx.fillStyle = '#ffffff';
  ctx.fillRect(0, 0, 360, 220);
  ctx.strokeStyle = '#526170';
  ctx.lineWidth = 2;
  ctx.strokeRect(20, 18, 320, 184);

  function arrow(x1, y1, x2, y2, color) {
    const angle = Math.atan2(y2 - y1, x2 - x1);
    ctx.strokeStyle = color;
    ctx.fillStyle = color;
    ctx.lineWidth = 3;
    ctx.beginPath();
    ctx.moveTo(x1, y1);
    ctx.lineTo(x2, y2);
    ctx.stroke();
    ctx.beginPath();
    ctx.moveTo(x2, y2);
    ctx.lineTo(x2 - 14 * Math.cos(angle - 0.5),
               y2 - 14 * Math.sin(angle - 0.5));
    ctx.lineTo(x2 - 14 * Math.cos(angle + 0.5),
               y2 - 14 * Math.sin(angle + 0.5));
    ctx.closePath();
    ctx.fill();
  }
  arrow(110, 145, 280, 145, '#075d69'); // right
  arrow(110, 145, 110, 48, '#064d91');  // up
  ctx.fillStyle = '#ffffff';
  ctx.strokeStyle = '#14191f';
  ctx.lineWidth = 2;
  ctx.beginPath();
  ctx.arc(110, 145, 10, 0, 2 * Math.PI);
  ctx.fill();
  ctx.stroke();
  ctx.fillStyle = '#14191f';
  ctx.beginPath();
  ctx.arc(110, 145, 3, 0, 2 * Math.PI);
  ctx.fill();
  ctx.font = '16px sans-serif';
  ctx.fillText('r: right', 204, 168);
  ctx.fillText('u: up', 124, 62);
  ctx.fillText('n: toward you', 42, 190);
  window.renderImage(canvas.toDataURL('image/png'));
})();

尝试修改 r: right（在 ctx.fillText(...) 中），然后再次运行该单元格。函数包装器 (() => { ... })(); 可以使此示例的变量保持为局部变量，因此您可以重新运行它而无需重新声明顶层 const 变量。

display 调用至关重要。请在末尾保留 window.renderImage(canvas.toDataURL('image/png'))。返回普通字符串（如 '<svg>...</svg>'，从 JavaScript 返回）只会显示文本；并不会将该字符串转化为内联图表。您不需要将 canvas 插入到应用的页面中。

步骤 4 · 方法 3

通过公式解释图片

使用 Markdown (Md) 单元格编写 TeX 风格的数学公式。图表的方向构成右手坐标系：右 × 上 = 向外法线。在下方的矩阵中，第一行为 r，第二行为 u，第三行为 n；下标是它们在所选 x、y、z 坐标系中的分量。

  1. 轻点 ✎ 铅笔（在 math_axes 上），或在新建单元格面板中使用 代码 → Md 创建新单元格。
  2. 使用下方的完整文本。$$ 定界符属于 Markdown 源码的一部分；请勿将其包裹在代码围栏中。
  3. 轻点 ▶ 运行 保存并渲染 Markdown。您应该会看到叉积公式和一个三行矩阵，而不是原始的反斜杠命令。此单元格不会运行任何语言内核。
Right, up and outward normal form a right-handed frame.

$$\mathbf{r} \times \mathbf{u} = \mathbf{n}$$

Rows of the frame matrix: right, up, then outward normal.

$$
M = \begin{pmatrix}
r_x & r_y & r_z \\
u_x & u_y & u_z \\
n_x & n_y & n_z
\end{pmatrix}
$$

KaTeX 并不是完整的 TeX 编译器。它仅渲染受支持的数学记号，但不会编译 TikZ 图表或整个 LaTeX 文档。尽管 KaTeX 列出了 \includegraphics，但它需要一个 SciREPL 在经过检查的渲染器中未启用的信任选项；此处它不能作为插入图像的途径。对于图片，请使用 Markdown SVG/PNG 或 JavaScript canvas。

有关其他符号和数学命令，请参阅 KaTeX 支持表；该文档描述的功能可能比 SciREPL 的内置版本更新。有关使用这些方向来解释魔方转动的工作簿，请参阅马尔可夫群演练。

步骤 5

保存副本，明确需重新运行的内容

  1. 打开 ☰ 菜单 → 导出工作簿与软件包。
  2. 为此工作簿选择 工作簿 (.srwb) 和 仅当前标签页，然后轻点 导出。将文件保存在您能掌控的位置。
  3. 要重新打开该副本，请使用 菜单 → 导入文件。这会添加另一个工作簿标签页；它不会替换现有的标签页。
  4. 检查静态 SVG、嵌入式 PNG 和公式。它们来自已保存的 Markdown 源码，无需执行代码。检查 canvas_axes 并再次运行该 JavaScript 单元格以重新生成其图片。

生成的输出不等于源码。在经过检查的 Free 浏览器构建版本中，.srwb 导出可以存储 JavaScript 图像输出，但手动执行 菜单 → 导入文件 并不会恢复该代码输出。JavaScript 源码依然保留，因此请重新运行它。内联 SVG、嵌入式 PNG 和公式属于 Markdown 源码，在导入时即可显示。切勿将先前可见的输出作为代码刚刚运行过的凭据。

这些检查涵盖上述工作簿示例，并不涵盖每种导出格式下的图像保真度。切勿假设 PDF、DOCX、Markdown 和其他文档导出格式都能以相同方式保留每张图像；请检查您导出的文档。有关可用格式，请参阅文件与导出 (英文参考页面)。

导出编辑后的工作簿会为您的更改创建备份；当您编辑单元格时，原来下载的示例不会更新。本地应用存储并不是备份，且 Android 与浏览器会话之间不会自动共享工作成果。

如果出现异常情况

检查单元格类型和源码

  • 如果看到的是 SVG 代码而非图表：请检查单元格类型是否为 Md，移除周围所有的代码围栏，并重新渲染该单元格。请使用完整的内联 <svg>...</svg> 示例，而不是 SVG 数据 URL。
  • 如果 PNG 缺失：请使用配套文件中的 embedded_png 单元格，或检查是否粘贴了完整的 data:image/png;base64,... 字符串且不含空格或换行符。本地文件名并不等于嵌入式图像数据。
  • 如果 canvas 代码未运行：请将其单元格类型设置为 代码，语言设置为 JS - JavaScript，而非 Python。保留整个函数包装器以及最后的 window.renderImage(...) 调用。
  • 导入的 JavaScript 单元格没有图片：导入此工作簿并不会运行它或恢复其代码输出。请检查并重新运行 canvas_axes。
  • 如果看到原始 TeX 或数学公式错误：请使用 Md，包含起始和结束的 $$，并对照示例检查每个反斜杠和大括号。除最后一行外，每个矩阵行均以两个反斜杠结尾，即 \\。
  • 编辑创建了多余的单元格：新建单元格面板会添加单元格。请使用已保存单元格的 ✎ 铅笔 修改该现有单元格，然后使用其自身的 ▶ 运行 按钮。如果您误打开了编辑器，请使用 取消。

有关已保存单元格、铅笔和新建单元格面板的图文指南，请参阅首个工作簿界面演练。如需单元格类型的简明提示，请返回工作簿参考 (英文参考页面)。
