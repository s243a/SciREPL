从离线建议到 AI 辅助编程

首先体验快速且每次请求完全免费的基于表格的建议。然后设置 Assistant，请求在线备选建议，尝试端侧本地模型，最后使用专注的 AI Prompt 单元格来解释您的代码。

  • 仅限 Pro
  • Pro 1.4.0 + 即将推出的执行控制
  • 本地模型：Android

大多数屏幕截图显示的是 Android 应用，部分为浏览器抓取画面。布局可能会因应用版本而异。

请检查您的版本。附录中的执行更改计划用于拟议的 Pro 1.5.0，该版本尚未发布；最终版本号可能会发生变动。

此处的“Free”表示免 API 费用。表格建议和端侧模型不会向服务提供商计费。但这并不代表它们是Free版功能：本演练适用于 SciREPL Pro。在线请求使用的是您自己的服务商账户，可能会产生费用。

第 1 步 · 无需 API 密钥

从离线表格建议开始

在应用顶栏找到 ☰ 菜单：它是带有三条横线的按钮。打开 补全。其 分区： 选择器区分了 通用、AI 建议（联网） 和 本地模型（在设备上）。首先从 General 开始。

  1. 将 本地代码补全： 设置为 开启。否则默认的 自动（桌面端开启，触控端关闭） 会在手机上将其保持关闭。
  2. 设置 建议候选项： → 开启 并保持 建议： → 光标处。若之前启用了任一选项，请在在线部分将 AI 建议 设置为 关闭，并在本地部分将 使用本地模型： 设置为 关闭，以隔离表格建议。然后返回 General。
  1. 关闭 Completion。在新的练习工作簿中，选择 代码 单元格和 JavaScript 语言。键入 cons，光标置于末尾且不选中任何文本。const 的这几个起始字母被称为前缀。注意观察 const。
  2. 在下方屏幕截图中，cons 后面跟有隐约可见的 t——行内幽灵文本。点击 接受 或按 Tab 插入该建议，得到 const。如果出现的是 const 药丸标签，点击它同样可以采纳该候选。自行完成该行代码，例如 const values = [12, 15, 18];。

Accept 不等于 Run。采纳建议只会编辑源码，不会执行单元格。本节中的 JavaScript 和 Python 示例演示了编辑时的自动补全。运行这些练习单元格不属于本节内容。在仅启用离线表格层的情况下，键入前缀不会发送 API 请求，也不会仅仅为了提供建议而启动语言运行时。

未来的在线预取：计划推出一种可选加入的模式，该模式可以在您键入时发送模型请求。目前该功能尚不可用，且尚未分配发布版本号。上述关于不发送请求的说明描述的是当前的离线表格层，而非这种未来模式。

在手机上查看这两种离线显示方式。保持 建议候选项： → 开启，选择 Python，然后键入 pri。光标后隐约可见的 nt 提供了 print；在您采纳之前，它并不属于源码的一部分。无需关闭药丸标签即可看到幽灵文本。单个候选词可以显示为幽灵文本，而当有多个合适候选词时，药丸标签可供选择。在这两个示例中均请保持 AI 建议 和 使用本地模型： 关闭。

在药丸标签仍处于 开启 的情况下，用以下三行替换练习输入，将光标留在未完成的 sample_m 之后。该行根据您自己源码中的名称提供了 sample_mean 和 sample_median。点击药丸标签即可选择候选词；与幽灵文本不同，该行显示了备选项。

sample_mean = 0
sample_median = 0
sample_m

附加按键行（在 Python 手机图片中可见）以及键入时的语法高亮色彩是独立的、可选的 Pro 控件。请参阅外观演练：附加按键与语法色彩以开启或关闭其中任一项，并找到文件编辑器独立的语法高亮复选框。

在体验了这些补全显示方式后，切换回 JavaScript，并在本课余下部分保持药丸标签开启。

此处显示的离线药丸标签在 补全 → 通用 → 建议候选项： 下启用，它结合了精选的名称表格与本地代码信息。在 Python 中，这包括在工作簿代码中找到的变量与函数，以及缓存的内核名称和对象属性（包括方法）。使用频率和采纳历史有助于对它们进行排序。其他语言的覆盖范围有所不同：静态列表、未运行的定义或过期的快照可能会建议当前作用域中不可用的名称。基于表格的补全不是语言模型，不会对您的任务进行推理。

如果单元格中间的建议干扰到您，仅在单元格末尾 是一种替代方案。选中的内容、字符串、注释或拆分了一半的名称可能会有意不产生任何建议。在纵向空间较小的横屏模式下，可选行可能会隐藏以为代码留出空间；请参阅外观设置。

第 2 步 · 在线设置

保存 API 密钥

API 密钥可让 SciREPL 使用由您控制的服务商账户。从该服务商处获取密钥，查看其当前价格和账户限额，并在本课中仅使用包含非私密数据的小型练习工作簿。

  1. 打开 菜单 → 🤖 AI Assistant (Pro)。点击面板的 ⚙ 齿轮图标 以打开 AI 设置。

    看不到齿轮图标？键盘可能会导致 Assistant 面板移位或滚动。向下拖动面板内容以向顶部回滚并露出齿轮图标；收起键盘也可以为您留出更多空间。

  2. 设置 为以下功能配置模型 → AI助手。选择 后端（例如 OpenRouter）和 模型，若您的后端使用可配置的端点，请检查端点。
  3. 输入匹配的 API密钥。使用 已保存的密钥 管理其他服务商/端点组合的密钥。适用于一个目标的密钥并不会自动适用于另一个目标。
  4. 点击 保存。仅保存设置不会发起模型请求。保持面板打开以进行下一步。

请勿将密钥存放在工作簿中。请勿将其粘贴到单元格、提示词、屏幕截图或导出的文件中。已保存的密钥存放在本地应用/浏览器存储中，没有应用层加密；请保护好设备，切勿运行不可信代码。Pro 隐私政策说明了存储和发送的内容。

对于 Assistant 而言，低成本且支持工具调用的模型是合理的起点。可供对比的示例包括 GLM 5.3 Flash、GPT-6 Luna、Claude Haiku 5.5 和 DeepSeek V4 Flash。确切的模型 ID、可用版本、工具支持和价格取决于您的应用版本和服务商；请查看当前选择器和服务商文档。新公布的模型可能需要应用更新后才会显示。稍后，您可以专门为补全选择另一款低成本模型。

列表中缺少该模型？在 AI 设置 → 为以下功能配置模型 → AI助手 中，先选择正确的 后端，然后将服务商的准确 API 模型 ID 输入 Model 选择器下方的 或输入自定义模型ID 中，并点击 保存。该字段在 Pro 1.4.0 中已可用。

请向您选择的服务商核实 ID，而不仅仅依据模型的营销名称。对于 OpenRouter，需包含组织前缀——例如 anthropic/claude-haiku-5.5，如其模型页面所示。输入该 ID，而非该页面的 URL。自定义 ID 的优先级高于下拉菜单；再次选择列表中列出的模型将清空自定义字段。

填写 ID 并不会添加 API 支持。模型必须支持通过 API 进行工具调用，以供 SciREPL 使用。请检查服务商访问权限、兼容性及当前价格；保存并不会验证这些内容或发起模型请求。

第 3 步 · 审慎的工具使用

使用 Open 智能体预设构建一个小示例

开放 是第二宽松的安全预设，仅次于 完全控制。它默认允许编辑笔记本，且提示比 Cautious 更少。执行时是否会弹出确认提示取决于您的版本和权限设置；请参阅即将推出的执行审批附录。请在练习工作簿中审慎使用它——而非作为自动补全的必要条件。

  1. 在 AI Settings 中，选择 Security Level → Open 以及 智能体写入 → 活动工作表。保持源码浏览处于关闭状态，并关闭 自动运行由 AI 创建的单元格。在 Kernels…下，设置 JavaScript → Ask，然后保存。即使此前已保存了执行工具的 Allow 许可，该内核规则仍会弹出提示进行确认。

    关闭自动运行并不等同于执行锁定。它仅阻止新创建的单元格自动运行；并不会禁用单独的 execute_cell 或 run_cells 请求。已发布的 Pro 1.4.0 的 Open 默认设置可能无需询问即可允许它们。即将推出的 Open 默认设置会要求确认，但显式的工具或内核 Allow 设置可以更改该默认行为。AI 设置 → 内核… → JavaScript → 询问 可确保本次练习中的 JavaScript 执行需要经过确认。您自己手动进行的单元格 Run 仍属于独立操作。下一版本的执行控制详见附录。

    如果您希望获得更多确认提示，请改用 谨慎。Open 依然遵循单独的源码浏览和写入范围控制项；Full control 则会绕过这两个粗粒度控制项。具体的各个权限和其他安全防线仍然起作用。审查 是一项额外的以只读为主的限制，它会妨碍本次单元格创建演示。

    浏览器沙盒保护与不保护的内容

    常规的工作簿执行运行在浏览器/WebView 及其语言运行时中，使用虚拟文件系统，而非对您手机文件的无限制访问。这是一个有用的边界，但不能保证代码绝无危害。获得许可的 JavaScript 以及与其连接的桥接程序可以访问应用数据和保存的凭据；一旦允许的代码开始运行，网络限制仅是尽力而为的防护，而非您可以放心托付机密信息的隔离边界。即将推出的执行提示增加的是审批步骤，而非与应用数据的隔离。请使用练习工作簿并确保其内容不涉及隐私。

    Remote/MCP 终端则截然不同：它可能会在代理主机上暴露一个真实的 shell，脱离浏览器本地沙盒。在此处请保持 Remote 和 Terminal 关闭。在启用它们之前，请参阅远程与安全 (英文参考页面)。在提示词中礼貌地写一句“请勿……”绝不是一种安全控制措施。

  2. 在 Assistant 面板中，选择 This workbook。保持 Review, Remote，以及 Terminal 处于关闭状态，以进行此直接服务商示例。
  3. 发送下方标注框中的练习提示词。面板上的 Send 即可启动智能体工具调用循环：此处没有额外的“Agent 模式”开关。全屏编辑器的 Agent 按钮是单独的工作流程。

第 4 步 · 在需要时请求备选方案

请求基于 API 的补全

  1. 打开 菜单 → 补全，然后选择 分区： → AI 建议（联网）。将 AI 建议 设置为 点按时。
  2. 保持 补全模型： → 沿用 AI 助手设置 以继承其服务商、端点和模型。或者选择 选择提供商和模型，挑选已保存的服务商/端点以及适合简短建议的低成本模型。此屏幕无需输入密钥；点击 打开 AI 设置 可让您先添加一个密钥。
  3. 打开该部分的 高级 以检查回复超时和开销保护设置。默认值为 6 秒、$0.25/天 以及 $5/月。在调高这些限制之前，请核对价格。
  4. 返回 JavaScript 编辑器并输入以下练习代码段： 
    const values = [12, 15, 18];
const average =
    将光标留在未完成的 const average = 行后。点击建议行末尾的 …，使用 …AI 附加按键，或者按下 Ctrl + Shift + Space。
  5. 在发送之前，请审查首次请求的实际有效载荷和目标地址。AI 药丸标签带有 ✦ 标记。点击一个标签即可采纳；被截断或多行的标签会先打开预览。在运行（Run）之前，请仔细审查生成的源码。

选择代码本身，而不仅仅是看 AI 药丸标签。在此请求中，第一个标签提议了 values.reduce((a, b) => a + b, 0) / values.length;。点击它可查看完整预览：它对数组求和并除以其长度，在此示例中得出 15。第二个标签提议了 eval(values.join(' + ')) / values.length;。拒绝这种不必要的 eval 备选方案：计算均值无需将字符串转换为可执行代码。在采纳之前请务必检查返回的代码，且仅在审查之后再运行。

该请求最多索取五个备选方案，但您的屏幕可能容纳不下这么多。再次点击会先翻阅已收到的备选方案；一旦浏览完毕，它可以请求更多。在请求加载旋转时点击即可取消。超时后收到的后续回复将被舍弃，而键入文本或移动光标会使旧的建议失效。

独立即真正独立：当您更改 Assistant 的模型时，单独的补全选项仍保持独立。当您需要能力强大的智能体但希望使用低成本的自动补全时，这非常实用。跟随 Assistant 仅继承其模型标识，而非其对话或智能体权限。

清楚了解您的付费内容与发送的数据

在线补全是按需发起的：平常的键盘输入不会发送任何内容。边键入边预取在此工作流中尚不可用。补全仅发送受限的当前单元格上下文：光标前最多 1,500 个字符，光标后最多 200 个字符，以及最多 12 个本地名称——绝不发送 Assistant 聊天记录或整个工作簿。机密信息脱敏是尽力而为的，因此请自行核对发送的载荷。

始终允许 授予对该目标的永久许可；一旦服务商、端点或模型变更，系统将再次询问。无需询问即发送 最初会启用该选择，但仍会展示一次真实的首次载荷。在学习阶段，建议保持 每次询问。

按日/按月限额是仅针对补全的软性开销防护，并非服务商账单上限保证，也不是 Assistant 或 AI Prompt 请求的预算。请求失败和取消操作可能会保留其预扣费用。清除开销历史不会重置上限总计。没有标明价格的模型需要显式设置输入/输出价格上限，否则应用将拒绝发送请求。

第 5 步 · 可选的 Android 下载

体验端侧模型

当表格建议不确定时，可选的 Qwen2.5-Coder 0.5B 模型可在本地提供代码建议。它是一个小型代码补全模型，并非对话智能体的替代品。安装后，推理过程不会向服务商发送任何键入的代码，且不产生任何 API 费用。

  1. 在符合条件的 Android 手机上（已安装 Pro，源自 Google Play），打开 菜单 → 补全 → 分区： → 本地模型（在设备上）。
  2. 点击 安装，并为约 400 MB 的下载预留时间与存储空间。当前侧载安装的版本无法通过此流程下载该模型。
  3. 准备就绪后，保持 使用本地模型： → 不确定时。表格建议负责处理简单情况；当其不确定时，模型会介入补充。始终显示 会更频繁地运行它；关闭 可将其停用而无需删除下载的文件。
  1. 返回代码单元格，并在未完成的名称或行处稍作停顿。结果会因上下文而异；并非每次停顿都会产生建议。采纳合适的幽灵文本或药丸标签，检查源码，然后单独执行运行（Run）。

什么样的手机能流畅运行？

最低适用条件为 64 位 ARM Android 且至少拥有 4 GB RAM，这并不保证性能流畅。Galaxy S24+ 级别的手机是较为实际的舒适运行目标：三星标明 S24+ 拥有 12 GB RAM，能为应用、内核及模型留出更多余量。这是推荐的性能水平，而非要求必须购买该机型。详见三星 S24 系列技术规格。

Galaxy S10+ 拥有符合条件的 8 GB 或 12 GB 规格版本。维护者的日常体验是本地补全可以在其上运行，但感觉比 API 补全慢；具体对比取决于模型与网络状况。记录的本地引擎基准测试未对 S10+ 进行测量，因此这并非实测速度对比，也不对每款机型作保证。当将该模型与大型工作簿及高内存占用的内核结合使用时，请留意卡顿或应用无响应的情况。详见三星 S10 系列技术规格。

此前对 S24+ 级别原生引擎的测试显示，在完成加载后，热启动首词中位数约为 0.10 秒，冷启动首词中位数约为 0.24 秒。这些是基准测试样本结果，并非绝对保证：未缓存的初始加载耗时数秒。加载的模型增加了约 460–490 MB 的应用进程内存，这还不算 WebView、Python/R 运行时以及操作系统本身所占用的内存。

若较旧的手机出现卡顿：请设置 使用本地模型： → 关闭，改用表格建议或按需点击的 API 备选方案。在本地 高级 下，设置 Keep loaded after leaving the app → 0 可在您离开应用时将其释放；空闲卸载和低电量控制项也大有帮助。排查问题之前，请先保存/导出工作簿。免 API 费用的模型仍然会占用存储空间、内存和电池电量。

第 6 步 · 在构建代码的同时理解代码

最后使用专注的 AI Prompt 单元格

Assistant 适用于多步骤工作。而 AI Prompt 单元格更适合针对特定代码段提出简短且可重复的问题：它发起的是一次孤立的请求，不带 Assistant 历史记录或工具。在对计算进行扩展之前，可用它来询问该计算为何能正常运作。

在此我们返回到第 3 步中带种子的随机 summary_demo 单元格。我们请求对该现有计算进行解释——而不是再生成一个随机数组，也不是第 4 步仅计算平均值的补全示例。

  1. 添加一个 AI Prompt 单元格，紧随第 3 步的 summary_demo JavaScript 单元格之后——而非第 4 步仅计算平均值的代码段——以便下方的问题与所选源码相匹配。保持单元格类型为 代码，然后选择 AI Prompt（来自语言/模式下拉菜单）。如果该项不存在，请在 菜单 → 语言与模式 下启用它。
  2. 将下方提示词粘贴到 AI Prompt 单元格中，而不是 Assistant 的消息框中。打开其 Configure 控件。 
    逐行解释所选的 JavaScript 单元格。

解释对于空数组需要做出哪些修改。
仅返回简要解释；请勿重写代码。
  3. 设置 将最终回复放入 → 当前单元格的输出（默认值）。在 要发送的上下文 → 包含源码来源下，选择 Previous 1 cell。取消勾选 包含已保存的输出文本 （用于本次仅针对源码的练习）。确认 Context preview 标明了 summary_demo，然后向下滚动并点击 Save configuration.

控制 API 成本并加深理解的一种方式。相比不断增长的智能体对话，专注的 AI Prompt 可以发送更少的上下文，并避免多步骤工具循环，从而减少输入 token 并可能降低账单费用。在编写代码时，可请求其提供简明推理、假设和预期输出。节约费用是无法保证的：模型费率、回复长度、推理 token 以及您选择的上下文仍然起到决定作用。这些请求使用 Assistant 的服务商/模型，而非独立的补全模型，且不在补全开销保护的控制范围内。

另一个示例 · 在替换单元格之前审查图表

现在请求 AI Prompt 将代码写入一个不同的单元格，在替换任何内容前先进行审查。我们将绘制估计方差在多个小样本中的变化图表。这些是全新生成的正态样本——而非早先的 summary_demo 整数数组。其目标是学习 配置 → 预览 → 应用 → 运行 这一流程，而非掌握统计学。

方差不等同于学生 t 分布。对于容量为 10 的独立正态样本，9s² / σ² 服从自由度为 9 的卡方分布。此处真实方差为 σ² = 1。学生 t 分布则描述标准化样本均值 (mean − μ) / (s / √10)（使用估计标准差 s）；在此处其自由度同样为 9。NIST：方差 · NIST：均值。

    仅返回完整的 JavaScript 源码，不要包含 Markdown 代码块标记。
创建一个可重现的估计样本方差直方图。

不要复用之前来自 summary_demo 的整数数组。

每次抽取正态分布使用两个连续的均匀随机数：sqrt(-2 * log(u1)) * cos(2 * PI * u2)。不要复用多余的正弦结果，也不要使用 Math.random。
针对每个样本计算其均值，然后计算无偏方差 sum((x - mean)^2) / 9。

遇到问题怎么办

手机上没有离线建议
选择 General → Local code completion → On 而非 Auto。检查药丸标签、光标位置、语言以及可选行是否有足够空间。
未发起在线请求
检查 On tap、确切服务商/端点的已保存密钥、所选模型的价格条目或上限、授权许可和开销总计。补全并不需要 Open 预设。需要安全浏览器上下文和 Web Locks 支持；不支持的环境将拒绝请求。
Assistant 在运行单元格前弹出提示——或者未弹出提示

补全无法理解其他单元格

无法点击 Install

附录 · 计划中的工作簿上下文与历史记录

仅为设计方案：这些功能尚未实现，也未分配到任何发布版本中。它们与上述即将推出的执行审批更改各自独立，不会阻碍当前版本的发布。

  • 在需要时获取工作簿摘要。该计划旨在用一个仅包含元数据的目录工具来替代重复的自动源码预览：单元格名称、可选描述、语言和类型，以及工作簿修订版本号。拟议的工具为 list_cells（带有 view: "metadata"）；Assistant 将单独读取选定的源码。这是一个受限的总览，而非自动生成的 AI 解释。
  • 单次附加而非每次发送时均附加。拟议的本次附加工作簿摘要复选框可以在新对话中初始处于勾选状态，并在该附件实际发送后取消勾选。您可以在发送前取消勾选，或再次勾选以获取全新的总览。其初始默认状态仍需进行隐私和易用性审查。后续对话不会添加新的摘要，切换标签页也不会静默重新启用它。预览和现有的读取/隐私权限仍然适用；大型工作簿可能需要更多分页。
  • 未勾选并不代表抹掉历史记录。它只会阻止新的自动附件，而不会移除对话中已有的摘要，也不会阻止已获许可的工具读取。现有的全屏 Agent、AI Prompt 和补全上下文控件仍将各自独立。
  • 两次发送之间的变更是一项后续选项。紧凑的增量更新需要已知的已发送上下文基准和可靠的修订版本号。人工编辑可以高亮显示，但智能体编辑、导入以及未知更改同样重要。源码编辑不会自动重写单元格的描述；缺失或过期的历史记录需要获取全新总览，而非靠猜测来进行更新。
  • 可选的本地历史记录与 GitHub 同步属于更长期的 Pro 设想。本地发送检查点可以支持基于 Git 的 diff 差异对比，而无需共享任何内容。独立的同步功能可以将工作簿发布到 Gist 或代码仓中的选定文件，并带有其专属的载荷预览和授权。启用历史记录不会推送到 GitHub，也不会向 AI 发送 diff。Git 仅展示内容变更，并不能证明该变更由人类做出。
