Apprendre par la pratique

Nommer les cellules et connecter des programmes

Une cellule peut avoir un nom utile tel que numbers, au lieu d'être connue uniquement par sa position. D'autres cellules peuvent lire sa dernière sortie texte via /nb/numbers/.output, ou échanger des données via un fichier ordinaire dans /shared/. Essayez les deux approches avec JavaScript et Bash, puis générez un petit programme Bash dans une autre cellule, sans exécuter automatiquement le code généré.

  • Flux de travail Free + Pro
  • Exemples vérifiés dans le navigateur
  • Environ 15 minutes

Le guide pas à pas et les captures d'écran ont été vérifiés dans la version de navigateur SciREPL Free le 6 octobre 2026. Il s'agit de captures complètes de navigateur étroit, pas de captures d'écran Android. Pro et chaque version publiée n'ont pas été vérifiées pour ce guide. L'exercice principal utilise JavaScript et Bash intégrés : aucun paquet, appel de modèle ou téléchargement d'environnement d'exécution n'est nécessaire. Python est une dernière étape facultative.

Ce que « chemins » signifie ici : /nb/ est une vue virtuelle des cellules du classeur actuellement sélectionné, accessible aux programmes. Ce n'est pas un dossier dans les Téléchargements d'Android, et ce n'est pas un écran « Vue des chemins » distinct. Dans la version Free vérifiée, l'écran Fichiers et stockage ne parcourt pas /nb/ ; plus tard, nous copions délibérément certaines données dans un fichier partagé que l'écran peut afficher.

Dans cette leçon
  1. Importer le petit classeur d'exemple
  2. Trouver et modifier le nom d'une cellule
  3. Exécuter la cellule productrice de données
  4. Lire les cellules via leurs chemins
  5. Échanger des données via un fichier JSON partagé
  6. Générer la source d'une autre cellule, puis l'exécuter vous-même
  7. Modifier les données et actualiser les résultats

Tous les tutoriels

Étape 1

Importer l'exemple sans l'exécuter

  1. Téléchargez le classeur d'exemple de cellules nommées (.srwb). Enregistrez le fichier lui-même et conservez son extension .srwb. Si le navigateur affiche du texte, utilisez son action d'enregistrement ou de téléchargement.
  2. Dans l'en-tête supérieur de SciREPL, recherchez ☰ Menu—le bouton avec trois lignes horizontales. Ouvrez-le et choisissez 📂 Importer un fichier (par exemple .srwb, .ipynb, .csv, .py, .zip). Faites défiler le menu si nécessaire.
  3. Sélectionnez named-cell-interop.srwb dans le sélecteur de fichiers de votre appareil. Quittez le menu s'il reste ouvert, puis sélectionnez le nouvel onglet Named Cell Interop dans le sélecteur de classeur. La flèche ▾ du sélecteur se trouve près du titre de l'application. Vos classeurs existants sont conservés.
  4. Lisez l'introduction, puis repérez les sept cellules de code nommées numbers, inspect_cells, write_shared, read_shared, generate_report, bash_report et python_total. Elles sont déjà nommées afin que vous puissiez suivre l'exercice.

Importer n'est pas Exécuter. L'importation ordinaire .srwb n'exécute pas de code, même lorsque l'exécution automatique est activée. Ne choisissez pas Exécuter toutes les cellules pour cette leçon : l'ordre compte, et la dernière cellule Python est facultative. Inspectez tout code inconnu avant de l'exécuter.

Besoin de plus de détails sur les étapes de téléchargement et de sélection ? Utilisez le guide pas à pas d'importation manuelle d'un classeur. Pour suivre cette leçon, gardez Named Cell Interop sélectionné : /nb/ fait référence au classeur actif, pas à chaque onglet ouvert.

Étape 2

Trouver et modifier le nom d'une cellule

Une cellule de code enregistrée possède une étiquette d'invite In[…] dans son propre en-tête, et une cellule nommée affiche également son nom. C'est l'étiquette à utiliser pour le renommage—non pas le ✎ crayon, qui modifie la source de la cellule. Le nombre affiché identifie la carte enregistrée ; après un réordonnancement, il ne correspond pas nécessairement à la position actuelle de la cellule dans un chemin /nb/In[N]/.... Privilégiez les noms pour les références.

  1. Trouvez numbers. Sur ordinateur, double-cliquez sur son étiquette In[…] . Sur un appareil tactile, maintenez cette étiquette enfoncée. Un simple clic n'est pas le geste de renommage dans la version vérifiée.
  2. Dans la boîte de dialogue, remplacez numbers par measurements, puis confirmez avec OK. Le nom dans l'en-tête de la cellule change ; la source et le langage ne changent pas.
  3. Ouvrez à nouveau la même boîte de dialogue et remettez le nom à numbers, puis choisissez OK. Les cellules suivantes utilisent ce nom, restaurez-le donc avant de continuer.

Choisissez des noms distinctifs et simples tels que cube_moves ou check_moves. Les noms doivent être uniques à l’intérieur du classeur ; ils ne peuvent pas contenir /, commencer par . ou être une étiquette de position réservée telle que In[2]. Vider le nom le supprime.

C’est pourquoi un tutoriel peut indiquer « Exécutez cube_moves, puis check_moves » : ce sont des noms de cellules à trouver dans le classeur, et non des fichiers que vous devez télécharger séparément. Les noms constituent de meilleures références que les positions lorsque vous insérez ou déplacez des cellules.

Étape 3

Exécuter la cellule qui produit des données

Trouvez numbers. Touchez son propre ✎ crayon, inspectez la source et vérifiez que la cellule est code → JS - JavaScript. Puis, pour cette cellule enregistrée, utilisez le bouton ▶ Exécuter—et non le panneau de nouvelle cellule, qui ajoute une autre cellule.

Raccourci Pro : vous pouvez également ouvrir l’éditeur d’une cellule enregistrée en touchant deux fois le texte source de la cellule dans Pro. Le ✎ crayon fonctionne dans les deux éditions. Ce raccourci d’édition est différent d’un double-clic ou d’un appui long sur l’étiquette In[…] pour modifier son nom.

console.log(JSON.stringify({values: [3, 5, 8]}));

Attendez-vous à cette sortie sur une seule ligne :

{"values":[3,5,8]}

Le résultat est du texte JSON. Sa structure le rend plus facile à lire pour un autre langage qu’un message en texte brut. Nous ne transmettons pas d’objet JavaScript actif ni ne partageons de variables JavaScript avec Bash ou Python.

Étape 4

Lire une cellule via le système de fichiers virtuel

Le répertoire virtuel pour numbers comporte des propriétés précédées d’un point. Un chemin combine le point de montage du classeur, l’identifiant de la cellule et la propriété souhaitée :

/nb/                         current workbook's cells
└── numbers/                 this named cell
    ├── .code                source text
    ├── .output              latest text output
    ├── .language            javascript
    ├── .type                code
    └── .name                numbers
Propriétés de cellule utilisées par l’interface de chemin du classeur
PropriétéCe que sa lecture vous fournit
.codeLa source actuelle, que cette source ait été exécutée ou non.
.outputLa dernière sortie textuelle. Elle est en lecture seule : l’exécution la fournit. Elle peut être vide ou obsolète.
.languageL’identifiant de langage stocké, tel que javascript ou bash.
.typeLe type de cellule, tel que code ou markdown.
.nameLe nom attribué, ou un texte vide si la cellule n’est pas nommée.

Ouvrez maintenant le ✎ crayon sur inspect_cells, vérifiez code → Bash, et exécutez-la. Cela lit la source du producteur, sa sortie JSON et son langage, puis liste les identifiants de cellule du classeur actuel. Cela n’écrit ni ne modifie aucune cellule ni aucun fichier.

printf 'Source:\n'
cat /nb/numbers/.code
printf '\nOutput:\n'
cat /nb/numbers/.output
printf '\nLanguage:\n'
cat /nb/numbers/.language
printf '\nCell names and positions:\n'
ls /nb/

Noms, positions et références relatives

La même cellule peut également être ciblée par sa position actuelle basée sur 1, par exemple /nb/In[2]/.output désigne la deuxième cellule dans l'ordre actuel. Comptez également les cellules Markdown. Il ne s'agit pas d'un identifiant de carte permanent : après un réordonnancement, le numéro In[…] affiché peut différer de la position utilisée par ce chemin. Les références de position changent de sens lorsque vous réordonnez ou insérez des cellules ; les références par nom continuent d'identifier la cellule nommée.

Bash et JavaScript prennent également en charge les références relatives à la cellule en cours d'exécution : /nb/-1/.output désigne la cellule précédente, et /nb/./.code désigne la cellule actuelle. Elles nécessitent un contexte d'exécution et dépendent de l'ordre des cellules. Ce tutoriel utilise plutôt des noms explicites ; il ne repose pas sur le fait que les références relatives se comportent de manière identique dans chaque langage.

Étape 5

Échanger des données via un fichier partagé

Le système de fichiers virtuel partagé contient des fichiers ordinaires que les noyaux de différents langages peuvent utiliser. Ici, /shared/ désigne le stockage géré dans votre session de navigateur/application SciREPL—et non les Téléchargements d'Android, un dossier sur votre ordinateur ou une synchronisation dans le cloud. Les fichiers partagés contiennent du texte ou des octets ; ils ne rendent pas les variables actives d'un langage accessibles à un autre.

Deux façons pour les programmes de faire référence aux données
CheminCe qu'il cibleCe qui le met à jour
/nb/numbers/.outputDernière sortie texte d'une cellule dans le classeur sélectionné.Exécuter à nouveau cette cellule.
/shared/data/named-cell-tutorial/values.jsonUn fichier JSON ordinaire, disponible entre les noyaux et les onglets du classeur.Un programme ou un éditeur de fichiers écrivant explicitement dans ce fichier.

Écrire un fichier JSON ordinaire

Ouvrez le ✎ crayon sur write_shared, vérifiez code → JS - JavaScript, puis exécutez-la. Cela lit la dernière sortie texte du producteur et l'enregistre sous la forme d'un fichier texte JSON partagé. Le système de fichiers partagé crée les dossiers parents au besoin.

const text = window.notebookVFS.readFile('/nb/numbers/.output');
if (!text) throw new Error('Run numbers first.');
window.sharedVFS.writeFile('/shared/data/named-cell-tutorial/values.json', text, 'javascript');
console.log('Saved JSON to /shared/data/named-cell-tutorial/values.json');

Le résultat est un fichier distinct contenant une copie de la sortie JSON, et non un autre nom pour /nb/numbers/.output. Le dossier dédié maintient le petit fichier temporaire de l'exemple séparé de vos autres données ; réexécuter write_shared écrase ce fichier de leçon précis.

Lire le fichier depuis un autre programme

Ouvrez le ✎ crayon sur read_shared, vérifiez code → JS - JavaScript, puis exécutez-la. Ce programme indépendant lit le fichier enregistré, et non la cellule numbers :

const text = window.sharedVFS.readFile('/shared/data/named-cell-tutorial/values.json', 'utf8');
if (!text) throw new Error('Run write_shared first.');
const record = JSON.parse(text);
console.log(record.values.reduce((sum, value) => sum + value, 0));

Attendez-vous à 16. Le 'utf8' explicite lit les octets du fichier sous forme de texte pour l'analyse JSON. Chaque noyau possède sa propre API de fichiers : JavaScript utilise ici l'assistant de système de fichiers partagé ; Python peut utiliser open(...), comme illustré dans l'étape facultative ci-dessous. Il ne s'agit pas d'un système de fichiers complet du système d'exploitation.

Pour une vérification interlangages distincte, vous pouvez ajouter une nouvelle cellule code → Bash et exécuter cette commande. Elle lit le même fichier ordinaire et affiche {"values":[3,5,8]} :

cat /shared/data/named-cell-tutorial/values.json

Afficher le même fichier dans l'interface graphique des fichiers

  1. Ouvrez ☰ Menu → Fichiers et stockage.
  2. Trouvez le dossier partagé data, puis named-cell-tutorial et values.json. Sélectionnez le fichier pour afficher son texte JSON.
  3. Vérifiez qu'il contient {"values":[3,5,8]}, puis fermez Fichiers et stockage pour continuer avec le classeur.

Une copie ne se met pas à jour automatiquement. Modifier ou réexécuter numbers modifie sa dernière sortie de cellule, pas le values.json existant. Réexécutez write_shared pour actualiser la copie, puis read_shared pour recalculer à partir de celle-ci. Les fichiers sont conservés dans le stockage local de l'application/navigateur, mais effacer ce stockage ou désinstaller l'application peut les supprimer. La persistance locale n'est pas une sauvegarde ; exportez les fichiers que vous devez conserver.

Pour afficher, modifier et exporter des fichiers partagés, consultez le guide pas à pas CSV et Fichiers et stockage. Une exportation .srwb limitée au classeur n'inclut pas les fichiers distincts tels que cette copie JSON ; utilisez l'Exportation d'archive de paquet pour inclure le classeur et les fichiers de données sélectionnés ensemble.

Étape 6

Générer le code d'une autre cellule, puis l'exécuter vous-même

Jusqu'ici, Bash a lu la sortie de JavaScript. Maintenant, JavaScript va utiliser ce même texte JSON pour calculer un total et écrire un court programme Bash dans la cellule existante bash_report. Écrire du code et exécuter du code sont deux actions distinctes.

  1. numbersExécuter → texte JSON
  2. generate_reportLire JSON → écrire la source Bash
  3. bash_reportInspecter → exécuter manuellement

Cette écriture remplace la source. Utilisez la cellule temporaire bash_report du classeur d'accompagnement, et non une cellule contenant un travail que vous devez conserver. Effectuez une sauvegarde avant d'essayer des écritures de source dans votre propre classeur. N'écrasez pas le générateur lui-même et ne modifiez pas .language par programmation dans cet exercice.

  1. Vérifiez que bash_report existe et que son langage est Bash. Sa source initiale est indiquée ci-dessous ; ne l'exécutez pas encore.
  2. Ouvrez ☰ Menu → Paramètres → VFS du carnet. Autoriser les cellules à modifier d'autres cellules doit être coché pour l'écriture du générateur. Il est activé par défaut dans la version vérifiée, mais vérifiez votre paramètre. Vous n'avez pas besoin d'activer les lectures entre classeurs, les écritures entre classeurs ou l'exécution programmatique. Fermez les Paramètres.
  3. Ouvrez le ✎ crayon sur generate_report, vérifiez code → JS - JavaScript, et exécutez-la.
const text = window.notebookVFS.readFile('/nb/numbers/.output');
if (!text) throw new Error('Run numbers first.');
const data = JSON.parse(text);
const total = data.values.reduce((sum, value) => sum + value, 0);
const updated = window.notebookVFS.writeFile(
  '/nb/bash_report/.code', `echo "Total: ${total}"`
);
if (!updated) throw new Error('Check bash_report exists and cell writes are allowed.');
console.log('Updated bash_report source; inspect it, then run it yourself.');

La cible commence par cet espace réservé :

echo "Run generate_report first"

Une fois que le générateur a réussi, la source de bash_report devient echo "Total: 16". L'écriture n'a pas exécuté Bash. Ouvrez le ✎ crayon de cette cellule pour inspecter la nouvelle source, puis appuyez sur son propre ▶ Exécuter. Attendez-vous à Total: 16.

readFile(...) renvoie du texte ; une cellule ou une propriété inconnue renvoie null. writeFile(...) indique si l'écriture a réussi. Les vérifications dans le générateur l'arrêtent si le producteur n'a pas de sortie ou si la destination ne peut pas être écrite. Les noms sont sensibles à la casse : conservez l'orthographe exacte.

Étape 7

Modifier les données et actualiser chaque étape dépendante

  1. Modifiez numbers avec son ✎ crayon. Remplacez [3, 5, 8] par [4, 5, 8], puis exécutez cette cellule. Son JSON contient désormais 4.
  2. Regardez bash_report avant d'exécuter quoi que ce soit d'autre. Sa source et sa sortie précédentes restent inchangées : il n'y a pas d'actualisation automatique des dépendances.
  3. Réexécutez generate_report. Cela remplace la source du rapport par echo "Total: 17", mais son ancienne sortie Total: 16 peut rester visible.
  4. Inspectez et réexécutez bash_report. Sa sortie est maintenant Total: 17.
  5. Avant d'actualiser le fichier, réexécutez read_shared : il affiche toujours 16 provenant de l'ancienne copie JSON. Maintenant, réexécutez write_shared, puis read_shared ; la voie par fichier affiche également 17. Rouvrez values.json dans Fichiers et stockage pour inspecter le fichier modifié.

La source, la sortie et les fichiers copiés sont des éléments différents. Terminez toute modification de source ouverte avec le bouton ▶ Exécuter de cette cellule avant ses consommateurs ; un brouillon d'éditeur non enregistré ne correspond pas au .code stocké. Une écriture de source n'exécute pas la destination, et un fichier copié ne suit pas les modifications ultérieures. Suivez l'ordre explicite : producteur → générateur → rapport. Une ancienne sortie visible ne prouve pas que la source actuelle a été exécutée.

Exportez le classeur pour conserver vos modifications de source et vos noms. L'importation .srwb ordinaire ignore actuellement les sorties de code enregistrées ; ainsi, après la réouverture, réexécutez numbers avant ses lecteurs, puis le générateur et le rapport. Les fichiers de données partagés distincts nécessitent une exportation de fichier ou de paquet. Consultez la référence des fichiers et de l'exportation (Page de référence en anglais).

Facultatif

Lire les deux voies depuis Python

Vous pouvez vous arrêter ici sans démarrer Python. Pour essayer un troisième langage, exécutez d'abord numbers et write_shared, puis inspectez et exécutez python_total sous forme de code → Python :

import json
record = json.loads(nb_read('numbers', '.output'))
print('Cell output:', sum(record['values']))
with open('/shared/data/named-cell-tutorial/values.json') as source:
    saved = json.load(source)
print('Shared file:', sum(saved['values']))

Attendez-vous à Cell output: 16 et Shared file: 16 pour les données d'origine, ou à 17 sur les deux lignes après avoir actualisé les deux voies à l'Étape 7. Dans Python, nb_read('numbers', '.output') lit la dernière sortie texte de la cellule nommée. L'élément distinct open(...) lit le fichier partagé à l'aide de la syntaxe de fichier habituelle de Python. Le module standard json analyse les deux ; aucun %pip install n'est nécessaire. Si seul le producteur a été actualisé, les deux totaux peuvent différer.

Lors de la première utilisation, Python peut avoir besoin d'initialiser ou de télécharger son environnement d'exécution. Un avis de confidentialité/réseau peut s'afficher selon votre version et vos consentements existants ; lisez-le avant d'accepter. Cette étape facultative n'est pas requise pour l'exercice JavaScript/Bash, et l'importation du classeur d'accompagnement seul ne démarre pas Python.

Continuer l'exploration

Reconnaître le modèle dans d'autres classeurs

Les cellules nommées fournissent une frontière d'interopérabilité simple : un programme produit du texte, un autre le lit ou l'utilise pour générer du code source. Le catalogue contient déjà des exemples plus complets à examiner :

  • Analyse de l'espérance de vie lit des fichiers CSV ordinaires depuis /shared/data/ en Python et en R : la voie du fichier partagé, et non des lectures de cellules nommées. Il télécharge des jeux de données et utilise des paquets ; lisez ses exigences de configuration et de consentement avant de l'exécuter.
  • Prolog génère R lit la source Prolog nommée avec nb_read(..., '.code', ...) et écrit la source R générée avec nb_write('r_factorial', '.code', ...). La cellule R est exécutée séparément.
  • Prolog génère TypR combine des définitions générées avec une cellule de requête nommée contenant uniquement de la source, puis écrit typr_output. Une cellule #!source peut être lue en tant que source sans l'exécuter.

Recherchez ces titres dans ☰ Menu → Parcourir les paquets…. Il s'agit de lectures complémentaires, non pas de guides d'exécution certifiés pour ce tutoriel ; l'édition disponible et les besoins de configuration diffèrent. Les classeurs où Prolog génère du code nécessitent la dépendance unifyweaver-scirepl installée via Parcourir ; l'importation d'un classeur brut seul n'installe pas cette dépendance. Pour un .ipynb importé manuellement, vérifiez d'abord que Menu → Paramètres → Importation et édition → Exécuter automatiquement les cellules à l'import du classeur est désactivé, car les importations Jupyter peuvent exécuter du code avec ce paramètre. Consultez le guide pas à pas Parcourir et le guide d'importation manuelle.

En cas de problème

Vérifier le nom, le classeur et l'ordre d'exécution

  • La boîte de dialogue de renommage ne s'ouvre pas : double-cliquez ou effectuez un appui long sur l'étiquette In[…] de la cellule enregistrée, et non sur sa source, sa sortie ou son crayon. Un simple clic n'est pas le geste de renommage.
  • Le producteur est introuvable : gardez Named Cell Interop sélectionné, rétablissez le nom exact numbers, et vérifiez l'orthographe et la casse. Renommer une cellule ne réécrit pas les chemins dans les autres cellules.
  • Le générateur indique « Run numbers first » : inspectez et exécutez numbers. L'importation ou la simple modification de sa source ne renseigne pas .output.
  • L'analyse JSON échoue : comparez le producteur avec l'exemple complet. Sa sortie doit être uniquement du JSON, et non un en-tête ou un message affiché supplémentaire.
  • Le rapport n'a pas pu être écrit : vérifiez que la cellule bash_report existante se trouve dans ce classeur et que Autoriser les cellules à modifier d'autres cellules est coché. N'activez pas l'exécution programmatique pour résoudre un problème d'écriture de source.
  • Le rapport affiche toujours 16 : après avoir modifié les données, exécutez numbers, puis generate_report, puis bash_report. Actualisez séparément le fichier copié avec write_shared, puis réexécutez read_shared.
  • Vous ne trouvez pas /nb dans Fichiers et stockage : cet écran affiche les fichiers partagés, et non ce montage virtuel de cellules dans la version vérifiée. Exécutez write_shared et recherchez plutôt sa copie values.json délibérée.

Le tutoriel sur l'interface du premier classeur explique l'en-tête et le crayon des cellules enregistrées ; le tutoriel graphique présente d'autres façons pour une cellule de produire un résultat.
