Apprendre par la pratique · Pro

Des suggestions hors ligne au codage assisté par l'IA

Commencez par des suggestions rapides basées sur des tables qui ne coûtent rien par requête. Configurez ensuite l'Assistant, demandez des alternatives en ligne, essayez un modèle sur l'appareil, et terminez par des cellules AI Prompt ciblées qui expliquent votre code.

  • Pro uniquement
  • Pro 1.4.0 + contrôles d'exécution à venir
  • Modèle local : Android

La plupart des captures d'écran montrent l'application Android ; certaines sont des captures de navigateur. Les dispositions peuvent varier selon la version de votre application.

Vérifiez votre version. Les modifications d'exécution dans l'annexe sont prévues pour la version proposée Pro 1.5.0, qui n'est pas encore publiée ; le numéro de version final peut changer.

« Free » signifie ici sans frais d'API. Les suggestions de tables et le modèle sur l'appareil ne facturent aucun fournisseur. Cela n'en fait pas pour autant des fonctionnalités de l'édition Free : ce guide pratique est destiné à SciREPL Pro. Les requêtes en ligne utilisent votre propre compte de fournisseur et peuvent être payantes.

Dans cette leçon
  1. Commencer par les suggestions de tables hors ligne
  2. Enregistrer une clé API
  3. Créer un petit exemple avec le préréglage d'agent Open
  4. Demander des complétions basées sur l'API
  5. Essayer le modèle sur l'appareil
  6. Utiliser une cellule AI Prompt pour comprendre le code

Étape 1 · Aucune clé API requise

Commencer par les suggestions de tables hors ligne

Trouvez ☰ Menu dans l'en-tête de l'application : il s'agit du bouton avec trois lignes horizontales. Ouvrez Complétion. Son sélecteur Section sépare Général, Suggestions IA (en ligne) et Modèle local (sur l’appareil). Commencez par General.

  1. Réglez Complétion locale du code → Activée. Sinon, la valeur par défaut Automatique (activée sur ordinateur, désactivée en mode tactile) le laisserait désactivé sur un téléphone.
  2. Réglez Puces de suggestion → Activée et conservez Suggestions → Au curseur. Pour isoler les tables, réglez Suggestions IA → Désactivé dans la section en ligne et Utiliser le modèle local → Désactivé dans la section locale, si l'une d'elles était activée auparavant. Revenez à General.
  1. Fermez Completion. Dans un nouveau classeur d'exercices, choisissez une cellule code et le langage JavaScript. Saisissez cons, avec le curseur à la fin et sans sélection. Ces premières lettres de const sont appelées un préfixe. Recherchez const.
  2. Dans la capture d'écran ci-dessous, cons est suivi d'un t estompé — du texte fantôme en ligne. Appuyez sur Accepter ou sur Tab pour insérer la suggestion, ce qui donne const. Si une puce const apparaît à la place, appuyer dessus est une autre façon d'accepter ce candidat. Terminez la ligne vous-même, par exemple const values = [12, 15, 18];.

Accepter n'est pas Exécuter. Accepter une suggestion modifie le code source ; cela n'exécute pas la cellule. Les exemples en JavaScript et en Python de cette section illustrent l'autocomplétion pendant la saisie. L'exécution de ces cellules d'exercices ne fait pas partie de cette section. Lorsque seule la couche de tables hors ligne est activée, la saisie d'un préfixe n'envoie aucune requête API et ne démarre aucun environnement d'exécution linguistique uniquement pour générer des suggestions.

Préchargement en ligne futur : un mode facultatif est prévu pour pouvoir envoyer des requêtes au modèle pendant votre saisie. Il n'est pas encore disponible, et aucun numéro de version ne lui est attribué. L'affirmation ci-dessus concernant l'absence de requêtes décrit la couche de tables hors ligne actuelle, et non ce mode futur.

Observez les deux affichages hors ligne sur un téléphone. Laissez Puces de suggestion → Activée, choisissez Python, et saisissez pri. Le nt estompé après le curseur propose print ; il ne fait pas partie de votre code source tant que vous ne l'avez pas accepté. Vous n'avez pas besoin de désactiver les puces pour voir le texte fantôme. Un candidat unique peut apparaître sous forme de texte fantôme, tandis que les puces offrent un choix lorsque plusieurs candidats correspondent. Laissez Suggestions IA et Utiliser le modèle local désactivés pour les deux exemples.

Avec les puces toujours Activée, remplacez la saisie d'exercice par ces trois lignes, en laissant le curseur après l'élément inachevé sample_m. La rangée propose sample_mean et sample_median à partir des noms de votre propre code source. Appuyez sur une puce pour choisir un candidat ; contrairement au texte fantôme, la rangée présente plusieurs alternatives.

sample_mean = 0
sample_median = 0
sample_m

La rangée de touches supplémentaires visible dans les images de téléphone en Python et les couleurs syntaxiques pendant la saisie sont des contrôles Pro distincts et facultatifs. Consultez le Guide pratique de l'apparence : touches supplémentaires et couleurs syntaxiques pour activer ou désactiver l'un ou l'autre, et pour trouver la case à cocher de coloration distincte de l'éditeur de fichiers.

Après avoir essayé ces affichages de complétion, revenez à JavaScript et laissez les puces activées pour le reste de la leçon.

Les puces hors ligne présentées ici, activées sous Complétion → Général → Puces de suggestion , combinent des tables de noms sélectionnées avec des informations de code local. En Python, cela inclut les variables et les fonctions trouvées dans le code du classeur, ainsi que les noms du noyau mis en cache et les attributs d'objets, y compris les méthodes. La fréquence et l'historique d'acceptation aident à les classer. D'autres langages ont une couverture différente : des listes statiques, des définitions non exécutées ou des instantanés obsolètes peuvent suggérer un nom qui n'est pas disponible actuellement dans la portée. La complétion basée sur des tables n'est pas un modèle de langage et ne raisonne pas sur votre tâche.

En fin de cellule uniquement est une alternative si les suggestions au milieu d'une cellule vous distraient. Une sélection, une chaîne, un commentaire ou un nom à moitié scindé peuvent intentionnellement ne produire aucune suggestion. En mode paysage réduit, les rangées optionnelles peuvent disparaître pour libérer de la place pour le code ; consultez les paramètres d'apparence.

Étape 2 · Configuration en ligne

Enregistrer une clé API

Une clé API permet à SciREPL d'utiliser un compte de fournisseur que vous contrôlez. Obtenez la clé auprès de ce fournisseur, vérifiez ses tarifs actuels et les limites de votre compte, et utilisez uniquement un petit classeur d'exercices contenant des données non privées pour cette leçon.

  1. Ouvrez Menu → 🤖 AI Assistant (Pro). Dans le panneau, appuyez sur la ⚙ roue dentée pour ouvrir AI Settings.

    Vous ne voyez pas la roue dentée ? Le clavier peut décaler le panneau de l'Assistant ou le faire défiler. Faites glisser le contenu du panneau vers le bas pour revenir vers le haut et faire apparaître la roue dentée ; masquer le clavier peut également libérer de la place.

  2. Réglez Configurer le modèle pour → Assistant IA. Choisissez un Backend (par exemple OpenRouter) et un Modèle, puis vérifiez le point de terminaison si votre backend en utilise un configurable.
  3. Saisissez la Clé API correspondante. Utilisez Clés enregistrées pour gérer les clés d'autres paires fournisseur/point de terminaison. Une clé pour une destination n'est pas automatiquement valable pour une autre.
  4. Appuyez sur Enregistrer. Enregistrer les paramètres n'effectue à lui seul aucune requête au modèle. Gardez le panneau ouvert pour l'étape suivante.

Ne conservez pas la clé dans le classeur. Ne la collez pas dans une cellule, un prompt, une capture d'écran ou un fichier exporté. Les clés enregistrées restent dans le stockage local de l'application ou du navigateur, sans chiffrement au niveau applicatif ; protégez l'appareil et n'exécutez pas de code non approuvé. La politique de confidentialité de Pro explique ce qui est stocké et envoyé.

Un modèle économique et capable d'utiliser des outils constitue un point de départ judicieux pour l'Assistant. Parmi les exemples à comparer, citons GLM 5.3 Flash, GPT-6 Luna, Claude Haiku 5.5 et DeepSeek V4 Flash. Les identifiants exacts des modèles, les versions disponibles, la prise en charge des outils et les tarifs dépendent de la version de votre application et de votre fournisseur ; vérifiez le sélecteur actuel et la documentation du fournisseur. Un modèle récemment annoncé peut nécessiter une mise à jour de l'application avant d'apparaître. Plus tard, vous pourrez choisir un autre modèle peu coûteux uniquement pour les complétions.

Le modèle ne figure pas dans la liste ? Dans Paramètres de l'IA → Configurer le modèle pour → Assistant IA, choisissez d'abord le bon Backend, puis saisissez l'identifiant de modèle API exact du fournisseur dans Ou saisir un ID de modèle personnalisé, sous le sélecteur Model, et appuyez sur Enregistrer. Ce champ est déjà disponible dans Pro 1.4.0.

Vérifiez l'identifiant auprès de votre fournisseur sélectionné, et pas seulement le nom commercial du modèle. Pour OpenRouter, incluez le préfixe de l'organisation — par exemple, anthropic/claude-haiku-5.5 sur sa page de modèle. Saisissez l'identifiant, et non l'URL de cette page. L'identifiant personnalisé prévaut sur le menu déroulant ; sélectionner à nouveau un modèle répertorié efface le champ personnalisé.

Un identifiant n'ajoute pas la prise en charge de l'API. Le modèle doit prendre en charge les appels d'outils via l'API qu'utilise SciREPL. Vérifiez les accès auprès du fournisseur, la compatibilité et les tarifs actuels ; l'enregistrement ne les valide pas et n'effectue aucune requête au modèle.

Étape 3 · Utilisation délibérée des outils

Créer un petit exemple avec le préréglage d'agent Open

Ouvert est le deuxième préréglage de sécurité le plus permissif, après Contrôle total. Il autorise par défaut les modifications du carnet de notes, avec moins de demandes de confirmation que Cautious. Le fait que l'exécution demande confirmation dépend de votre version et de vos paramètres d'autorisation ; consultez l'annexe sur l'approbation d'exécution à venir. Utilisez-le délibérément dans un classeur d'exercices — et non comme un prérequis pour l'autocomplétion.

  1. Dans AI Settings, sélectionnez Security Level → Open et Écriture de l'agent → Feuille de calcul active. Laissez la navigation dans les sources désactivée et désactivez Exécution automatique des cellules créées par l'IA. Sous Kernels…, réglez JavaScript → Ask, puis enregistrez. Cette règle de noyau demande toujours confirmation même si une autorisation Allow de l'outil d'exécution a été enregistrée précédemment.

    La désactivation d'Auto-run n'est pas un verrouillage d'exécution. Elle empêche les cellules nouvellement créées de s'exécuter automatiquement ; elle ne désactive pas les requêtes execute_cell ou run_cells distinctes. Dans la version publiée de Pro 1.4.0, la valeur par défaut d'Open peut les autoriser sans demander confirmation. La prochaine valeur par défaut d'Open demandera confirmation, mais une autorisation explicite Allow au niveau de l'outil ou du noyau peut modifier cette valeur par défaut. Paramètres de l'IA → Noyaux… → JavaScript → Demander maintient l'exécution JavaScript de cet exercice subordonnée à une confirmation. Votre propre action manuelle Run sur la cellule reste une action distincte. Les contrôles d'exécution de la prochaine version sont détaillés dans l'annexe.

    Si vous préférez davantage de confirmations, utilisez plutôt Prudent. Open respecte toujours les contrôles distincts de navigation dans les sources et de portée d'écriture ; Full control contourne ces deux contrôles généraux. Les autorisations individuelles et les autres garde-fous de sécurité restent importants. Révision constitue une restriction supplémentaire principalement en lecture seule, ce qui ferait obstacle à cette démonstration de création de cellules.

    Ce que le bac à sable du navigateur protège — et ne protège pas

    L'exécution normale d'un classeur s'effectue dans le navigateur/WebView et ses environnements d'exécution linguistique, avec un système de fichiers virtuel plutôt qu'un accès sans restriction aux fichiers de votre téléphone. Il s'agit d'une limite utile, mais pas d'une garantie que le code ne peut causer aucun dommage. Le code JavaScript autorisé et les passerelles vers celui-ci peuvent accéder aux données de l'application et aux identifiants enregistrés ; les restrictions réseau fonctionnent au mieux dès lors que le code autorisé démarre, et ne constituent pas une frontière d'isolation à laquelle vous devriez confier des secrets. La future invite d'exécution ajoute une étape d'approbation, et non une isolation par rapport aux données de l'application. Utilisez un classeur d'exercices et veillez à ce que son contenu ne soit pas privé.

    Remote/MCP Terminal est différent : il peut exposer un véritable shell sur l'hôte relais, en dehors du bac à sable local du navigateur. Laissez Remote et Terminal désactivés ici. Consultez Remote et sécurité (Page de référence en anglais) avant de les activer. Une consigne polie « ne pas… » dans le prompt ne constitue pas un contrôle de sécurité.

  2. Dans le panneau de l'Assistant, choisissez This workbook. Laissez Review, Remote, et Terminal désactivés pour cet exemple avec un fournisseur direct.
  3. Envoyez le prompt d'exercice figurant dans l'encadré ci-dessous. Dans le panneau, Send lance déjà la boucle d'outils agentique : il n'y a pas de bascule « Agent mode » supplémentaire ici. Dans l'éditeur plein écran, le bouton Agent correspond à un flux de travail distinct.

    Copiez ce prompt. Collez-le dans la boîte de message de l'Assistant, et non dans une cellule de code, puis appuyez sur Envoyer.

L'agent peut atteindre cette limite avant de terminer. Lisez ce qu'il a déjà accompli, puis appuyez sur Continuer si la tâche n'est pas terminée et que vous souhaitez une autre exécution délimitée. Poursuivre peut engendrer des frais d'API supplémentaires ; cela n'est pas nécessaire après Terminé.

Étape 4 · Demander des alternatives quand vous le souhaitez

Demander des complétions basées sur l'API

  1. Ouvrez Menu → Complétion, puis choisissez Section → Suggestions IA (en ligne). Réglez Suggestions IA → Sur appui.
  2. Conservez Modèle de complétion → Suivre l'Assistant IA pour hériter de son fournisseur, de son point de terminaison et de son modèle. Vous pouvez aussi choisir Choisir un fournisseur et un modèle, sélectionner une paire fournisseur/point de terminaison enregistrée et un modèle économique adapté aux suggestions courtes. Aucune clé n'est saisie sur cet écran ; Ouvrir les paramètres IA vous permet d'en ajouter une au préalable.
  3. Ouvrez Avancé dans cette section pour examiner le délai d'expiration des réponses et les garde-fous de dépenses. Les valeurs par défaut sont de 6 secondes, $0.25/jour et $5/mois. Vérifiez les tarifs avant de les augmenter.
  4. Revenez à un éditeur JavaScript et saisissez cet extrait d'exercice : 
    const values = [12, 15, 18];
const average =
    Laissez le curseur après la ligne inachevée const average = . Appuyez sur … à la fin de la rangée de suggestions, utilisez la touche supplémentaire …AI, ou appuyez sur Ctrl + Shift + Space.
  5. Vérifiez la charge utile réelle et la destination de la première requête avant de l'envoyer. Les puces d'IA portent un marqueur ✦. Appuyez sur l'une d'elles pour l'accepter ; une puce tronquée ou multiligne ouvre d'abord un aperçu. Examinez le code source obtenu avant Run.

Choisissez le code, pas seulement une puce d'IA. Dans cette requête, la première puce proposait values.reduce((a, b) => a + b, 0) / values.length;. Appuyez dessus pour examiner l'aperçu complet : elle additionne le tableau et le divise par sa longueur, ce qui donne 15 pour cet exemple. La seconde proposait eval(values.join(' + ')) / values.length;. Rejetez cette alternative eval inutile : calculer une moyenne ne nécessite pas de transformer une chaîne en code exécutable. Vérifiez le code renvoyé avant de l'accepter, et n'exécutez (Run) qu'après révision.

La requête sollicite jusqu'à cinq alternatives, mais votre écran peut en accueillir moins. Un nouvel appui fait d'abord défiler les alternatives déjà reçues ; une fois celles-ci épuisées, il peut en demander d'autres. Appuyez pendant que la requête tourne pour l'annuler. Les réponses ultérieures sont ignorées lorsque le délai d'attente expire, et le fait de taper ou de déplacer le curseur rend les anciennes suggestions obsolètes.

Indépendant signifie indépendant : un choix de complétion distinct reste séparé lorsque vous modifiez le modèle de l'Assistant. Cela s'avère utile si vous désirez un agent performant mais une autocomplétion économique. Suivre l'Assistant hérite de son identité, mais pas de sa conversation ni de ses autorisations d'agent.

Savoir ce que vous payez et ce que vous envoyez

La complétion en ligne fonctionne à la demande : la saisie ordinaire n'envoie rien. Le préchargement pendant la saisie n'est pas encore disponible dans ce flux de travail. La complétion envoie un contexte délimité de la cellule actuelle : au maximum 1,500 caractères avant le curseur, 200 après celui-ci, et jusqu'à 12 noms locaux — et non la discussion de l'Assistant ou le classeur entier. Le masquage des secrets fonctionne au mieux, vérifiez donc vous-même la charge utile.

Toujours autoriser accorde un consentement permanent pour cette destination ; tout changement de fournisseur, de point de terminaison ou de modèle redemande confirmation. Envoyer sans demander arme initialement ce choix mais affiche tout de même la première charge utile réelle une fois. Conservez Demander à chaque fois pendant votre apprentissage.

Les montants par jour/mois sont des garde-fous de dépenses indicatifs réservés à la complétion, et non des plafonds de facturation garantis par le fournisseur, ni le budget alloué aux requêtes de l'Assistant ou d'AI Prompt. Les échecs et annulations peuvent conserver leur retenue tarifaire. Effacer l'historique des dépenses ne réinitialise pas les totaux plafonnés. Un modèle sans tarif affiché nécessite des plafonds explicites de prix d'entrée/sortie, sous peine de refus d'envoi par l'application.

Étape 5 · Téléchargement optionnel pour Android

Essayer le modèle sur l'appareil

Le modèle optionnel Qwen2.5-Coder 0.5B suggère du code localement lorsque les tables sont incertaines. Il s'agit d'un petit modèle de complétion de code, et non d'un substitut à l'agent conversationnel. Une fois installé, l'inférence n'envoie aucun code saisi à un fournisseur et ne génère aucuns frais d'API.

  1. Sur un téléphone Android compatible où Pro a été installé depuis Google Play, ouvrez Menu → Complétion → Section → Modèle local (sur l’appareil).
  2. Appuyez sur Installer et prévoyez du temps ainsi que de l'espace de stockage pour le téléchargement d'environ 400 Mo. Les installations actuelles en chargement latéral (sideloading) ne peuvent pas télécharger le modèle via ce flux.
  3. Lorsque tout est prêt, conservez Utiliser le modèle local → En cas de doute. Les tables traitent les cas simples ; le modèle intervient lorsqu'elles sont incertaines. Toujours l'exécute plus souvent ; Désactivé l'arrête sans supprimer le téléchargement.
  1. Revenez à une cellule de code et faites une pause sur un nom ou une ligne inachevé. Les résultats varient selon le contexte ; chaque pause ne produit pas nécessairement une suggestion. Acceptez un texte fantôme ou une puce approprié, examinez le code source, puis lancez Run séparément.

Quel téléphone offre un usage confortable ?

La configuration minimale requise est un appareil Android ARM 64 bits avec au moins 4 Go de RAM, sans que cela ne garantisse des performances fluides. Un téléphone de la catégorie du Galaxy S24+ constitue une cible de confort réaliste : Samsung indique 12 Go de RAM pour le S24+, laissant une marge plus confortable pour l'application, les noyaux et le modèle. Il s'agit d'un niveau de performance recommandé, et non d'une obligation d'acheter ce modèle précis. Caractéristiques de la série Samsung S24.

Le Galaxy S10+ propose des variantes compatibles de 8 Go ou 12 Go. D'après l'expérience informelle du responsable de maintenance, la complétion locale peut y fonctionner mais sembler plus lente que la complétion par API ; la comparaison dépend du modèle et du réseau. Le benchmark enregistré du moteur local n'a pas mesuré le S10+, il ne s'agit donc pas d'une comparaison de vitesse mesurée ni d'une garantie pour chaque appareil. Surveillez les ralentissements ou un éventuel gel de l'application lorsque vous associez le modèle à des classeurs volumineux et à des noyaux gourmands en mémoire. Caractéristiques de la série Samsung S10.

Le test antérieur du moteur natif sur un appareil de classe S24+ a mesuré une médiane à chaud pour le premier mot d'environ 0.10 seconde et une médiane à froid d'environ 0.24 seconde, après chargement. Il s'agit d'exemples de résultats de référence et non de garanties : un chargement initial hors cache a pris plusieurs secondes. Le modèle chargé a ajouté environ 460–490 Mo de mémoire au processus applicatif, en plus de la WebView, des environnements d'exécution Python/R et du système d'exploitation.

Si un téléphone plus ancien devient lent : réglez Utiliser le modèle local → Désactivé et utilisez à la place les tables ou les alternatives API au toucher. Sous la section locale Avancé, régler Keep loaded after leaving the app → 0 libère le modèle lorsque vous quittez ; les contrôles de déchargement en cas d'inactivité et de batterie faible sont également utiles. Enregistrez/exportez votre classeur avant tout dépannage. Un modèle sans frais d'API consomme tout de même du stockage, de la mémoire et de la batterie.

Étape 6 · Comprendre le code au fil de sa création

Terminer par une cellule AI Prompt ciblée

L'Assistant est utile pour un travail en plusieurs étapes. Une cellule AI Prompt est préférable pour une question précise et reproductible sur un extrait de code particulier : elle effectue une requête isolée, sans l'historique ni les outils de l'Assistant. Utilisez-la pour demander pourquoi un calcul fonctionne avant de l'étendre.

Un moyen de maîtriser les coûts d'API et d'approfondir la compréhension. Autre exemple · Examiner un tracé avant de remplacer une cellule

Demandez maintenant à une cellule AI Prompt d'écrire du code dans une cellule différente, avec une vérification préalable avant tout remplacement. Nous allons tracer l'évolution de la variance estimée sur de nombreux petits échantillons. Il s'agit de nouveaux échantillons normaux — et non du tableau d'entiers précédent en summary_demo. L'objectif est d'apprendre la séquence Configurer → aperçu → Appliquer → Exécuter, et non de maîtriser les statistiques.

La variance n'est pas le t de Student. Pour des échantillons normaux indépendants de taille 10, 9s² / σ² suit une loi du khi-deux à 9 degrés de liberté. Ici, la variance réelle σ² = 1. La loi t de Student décrit plutôt la moyenne d'échantillon standardisée (mean − μ) / (s / √10), en utilisant l'écart-type estimé s ; elle a également 9 degrés de liberté ici. NIST : variance · NIST : moyenne.

Appuyez longuement sur son libellé In[…] et nommez-la variance_plot. Veillez à ce que ce nom reste unique dans le classeur ; consultez nommer les cellules.
  2. Ajoutez une cellule AI Prompt distincte et collez-y cette requête : 
    Renvoyez uniquement du code source JavaScript complet, sans blocs de code Markdown.

Ne réutilisez pas le tableau d'entiers précédent de summary_demo.

Pour chaque tirage normal, utilisez deux uniformes successives : sqrt(-2 * log(u1)) * cos(2 * PI * u2). Ne réutilisez pas le résultat sinus restant et n'utilisez pas Math.random.
Pour chaque échantillon, calculez sa moyenne, puis la variance sans biais sum((x - mean)^2) / 9.
Tracez un histogramme sur canvas avec des libellés comportant 40 classes de largeur égale de 0 à 4. L'axe horizontal représente la variance estimée ; l'axe vertical représente le nombre d'échantillons.

Non publié : ces contrôles décrivent l'implémentation de la prochaine version, et non la promesse que votre installation 1.4.0 en dispose. Le numéro de version est provisoire.

Le cocher modifie la règle partagée de l'outil d'exécution dans tous les classeurs jusqu'à réinitialisation — et pas seulement pour cette cellule, cette conversation ou ce fournisseur.   • Les invites d'inspection d'espace de noms et de cellules nouvellement créées ne peuvent pas créer cette autorisation permanente. S'il est tronqué, choisissez Cancel, inspectez le code source complet de la cellule nouvellement créée et exécutez-la vous-même (Run) uniquement si vous lui faites confiance. Annexe · Contexte et historique prévus pour les classeurs

Proposition de conception uniquement : ces fonctionnalités ne sont ni implémentées ni associées à une version. Elles sont distinctes des modifications à venir concernant l'approbation d'exécution ci-dessus et ne bloquent pas la version actuelle.

  • Récupérer un résumé du classeur en cas de besoin. Le projet remplace les aperçus automatiques et répétés du code source par un outil de répertoire limité aux métadonnées : noms des cellules, descriptions facultatives, langages et types, ainsi qu'une révision du classeur. L'outil proposé est list_cells avec view: "metadata" ; l'Assistant lirait séparément le code source sélectionné. Il s'agit d'une vue d'ensemble délimitée, et non d'une explication par l'IA générée automatiquement.
  • Joindre une seule fois plutôt qu'à chaque Send. Une proposition de case à cocher Attach workbook summary this time pourrait être cochée au début d'une nouvelle conversation et se décocher une fois cette pièce jointe effectivement envoyée. Vous pourriez la décocher avant l'envoi ou la recocher pour obtenir une nouvelle vue d'ensemble. Sa valeur par défaut initiale nécessite encore un examen en matière de confidentialité et d'ergonomie. Les suites de conversation n'ajouteraient pas un autre résumé, et changer d'onglet ne la réactiverait pas en silence. L'aperçu ainsi que les autorisations existantes de lecture et de confidentialité s'appliqueraient toujours ; un classeur volumineux pourrait nécessiter des pages supplémentaires.
  • L'état décoché n'efface pas l'historique. Cela empêcherait un nouvel ajout automatique, sans supprimer les résumés figurant déjà dans la conversation ni bloquer les lectures par des outils autorisés. Les contrôles de contexte existants pour l'Agent plein écran, AI Prompt et la complétion resteraient distincts.
  • Les modifications entre les envois constituent une option ultérieure. Des mises à jour compactes nécessiteraient une base de référence connue du contexte envoyé ainsi que des révisions fiables. Les modifications humaines pourraient être mises en évidence, mais les modifications de l'agent, les importations et les changements inconnus comptent également. Une modification du code source ne réécrirait pas automatiquement la description d'une cellule ; un historique manquant ou obsolète exigerait une nouvelle vue d'ensemble plutôt qu'une mise à jour supposée.
  • L'historique local facultatif et la synchronisation avec GitHub sont des idées à plus long terme pour Pro. Les points de contrôle locaux lors de l'envoi (Send) pourraient prendre en charge des diffs basés sur Git sans rien partager. Une synchronisation indépendante pourrait publier un classeur sur un Gist ou dans un fichier déterminé d'un dépôt, avec son propre aperçu de charge utile et sa propre autorisation. Activer l'historique n'effectuerait aucun push vers GitHub ni n'enverrait de diff à l'IA. Git montre les modifications de contenu, et non la preuve qu'un être humain en est l'auteur.

Un Gist secret n'est pas privé. Quiconque dispose de son URL peut le lire ; utilisez un dépôt privé lorsque l'accès doit être restreint. Écartez tout secret du code source et des descriptions du classeur avant publication. Documentation de visibilité des Gists de GitHub.
