자신을 향하고 있는 종이 한 장을 떠올려 보세요. r은 종이를 따라 오른쪽을 가리키고, u는 종이를 따라 위쪽을 가리키며, n은 종이 밖으로 자신을 향합니다. 점이 찍힌 원은 자신을 향해 다가오는 화살표 끝을 보는 것처럼 바깥쪽 방향을 나타냅니다.

대신 포함된 PNG 사용하기

또 다른 정적 옵션은 Base64 데이터가 Markdown 소스에 직접 저장된 PNG입니다. 표준 Markdown 이미지 구문은 다음과 같습니다:

![Paper axes](data:image/png;base64,PASTE_THE_COMPLETE_BASE64_PNG_HERE)

이 줄은 작동하는 그림이 아니라 형식을 보여줍니다. 자리표시자를 인코딩된 완전한 PNG로 바꾸거나 이미 작동하는 embedded_png 셀을 사용하세요. base64, 뒤의 부분은 파일 이름이 아니라 이미지 데이터입니다. 한 줄로 유지하세요.

작은 화면에서 셀에 맞는 그림을 위해, 동반 파일의 embedded_png 셀은 width="100%"이(가) 포함된 아래의 동일한 인라인 HTML을 사용합니다. 이는 코드 출력이 아니라 여전히 Markdown 내부에 저장됩니다:

<img alt="Paper axes" width="100%"
     src="data:image/png;base64,PASTE_THE_COMPLETE_BASE64_PNG_HERE">

정적 경로 중 하나를 선택하세요: 편집 가능한 작은 다이어그램에는 인라인 SVG 요소를 사용하고, 래스터 그림에는 data:image/png;base64,... 이미지를 사용하세요. data:image/svg+xml,...과(와) 같은 SVG 데이터 URL은 인라인 SVG와 동일하지 않으며 검증된 빌드에서 차단됩니다. 원격 이미지 URL 역시 그곳에서 차단됩니다. 이 두 가지 자체 포함 예제는 표시될 때 이미지를 다운로드할 필요가 없습니다.

두 정적 예제는 모두 Markdown 소스에 있습니다. 워크북을 가져온 후 코드를 실행하지 않고도 표시할 수 있습니다.

JavaScript로 그림 그리기

정적 그림은 소스를 편집할 때까지 그대로 유지됩니다. 프로그램으로 계산되거나 그려진 그림의 경우 코드 셀을 사용하고 JS - JavaScript을(를) 선택하세요. 이 예제는 캔버스에 그림을 그리고 이를 PNG로 변환한 후 해당 이미지를 셀의 출력으로 보냅니다.

  1. 가져온 워크북에서 ✎ 연필을 canvas_axes에서 탭하세요. 셀 유형이 코드이고 해당 언어가 JS - JavaScript인지 확인하세요(간단한 선택기에는 JS만 표시될 수 있습니다).
  2. 해당 셀의 완전한 프로그램인 아래 코드를 읽어보세요. 다른 셀, 파일, 패키지 또는 네트워크 요청이 필요하지 않습니다.
  3. 해당 셀의 ▶ 실행을(를) 탭하세요. JavaScript 소스 아래에 그림이 나타납니다.

대신 새 셀을 만들려면 새 셀 패널로 이동하여 필요한 경우 Md를 다시 코드(으)로 변경하고 언어 드롭다운에서 JS - JavaScript을(를) 선택하세요. 코드를 붙여넣은 다음 ▶ 실행을(를) 탭하세요. JavaScript이(가) 숨겨져 있다면 ☰ 메뉴 → 언어을(를) 찾아 활성화하세요.

(() => {
  const canvas = document.createElement('canvas');
  canvas.width = 360;
  canvas.height = 220;
  const ctx = canvas.getContext('2d');
  ctx.fillStyle = '#ffffff';
  ctx.fillRect(0, 0, 360, 220);
  ctx.strokeStyle = '#526170';
  ctx.lineWidth = 2;
  ctx.strokeRect(20, 18, 320, 184);

  function arrow(x1, y1, x2, y2, color) {
    const angle = Math.atan2(y2 - y1, x2 - x1);
    ctx.strokeStyle = color;
    ctx.fillStyle = color;
    ctx.lineWidth = 3;
    ctx.beginPath();
    ctx.moveTo(x1, y1);
    ctx.lineTo(x2, y2);
    ctx.stroke();
    ctx.beginPath();
    ctx.moveTo(x2, y2);
    ctx.lineTo(x2 - 14 * Math.cos(angle - 0.5),
               y2 - 14 * Math.sin(angle - 0.5));
    ctx.lineTo(x2 - 14 * Math.cos(angle + 0.5),
               y2 - 14 * Math.sin(angle + 0.5));
    ctx.closePath();
    ctx.fill();
  }
  arrow(110, 145, 280, 145, '#075d69'); // right
  arrow(110, 145, 110, 48, '#064d91');  // up
  ctx.fillStyle = '#ffffff';
  ctx.strokeStyle = '#14191f';
  ctx.lineWidth = 2;
  ctx.beginPath();
  ctx.arc(110, 145, 10, 0, 2 * Math.PI);
  ctx.fill();
  ctx.stroke();
  ctx.fillStyle = '#14191f';
  ctx.beginPath();
  ctx.arc(110, 145, 3, 0, 2 * Math.PI);
  ctx.fill();
  ctx.font = '16px sans-serif';
  ctx.fillText('r: right', 204, 168);
  ctx.fillText('u: up', 124, 62);
  ctx.fillText('n: toward you', 42, 190);
  window.renderImage(canvas.toDataURL('image/png'));
})();

r: right을(를) ctx.fillText(...)에서 변경해 본 다음, 셀을 다시 실행하세요. 함수 래퍼 (() => { ... })();은(는) 이 예제의 변수를 로컬로 유지하므로, 최상위 const 변수를 다시 선언하지 않고도 다시 실행할 수 있습니다.

표시 호출이 중요합니다. 마지막에 window.renderImage(canvas.toDataURL('image/png'))을(를) 유지하세요. '<svg>...</svg>'과(와) 같은 일반 문자열을 JavaScript에서 반환하는 것은 텍스트를 표시할 뿐이며, 해당 문자열을 인라인 다이어그램으로 변환하지 않습니다. 캔버스를 앱 페이지에 삽입할 필요는 없습니다.

수식으로 그림 설명하기

TeX 스타일 수식에는 Markdown (Md) 셀을 사용하세요. 다이어그램의 방향은 오른손 좌표계를 형성합니다: right × up = outward normal. 아래 행렬에서 첫 번째 행은 r, 두 번째 행은 u, 세 번째 행은 n입니다. 아래 첨자는 선택한 x, y, z 좌표계에서의 성분입니다.

  1. ✎ 연필을 math_axes에서 탭하거나, 새 셀 패널에서 코드 → Md를 사용하여 새 셀을 만드세요.
  2. 아래의 전체 텍스트를 사용하세요. $$ 구분 기호는 Markdown 소스에 속하며, 코드 펜스로 감싸지 마세요.
  3. ▶ 실행을 탭하여 Markdown을 저장하고 렌더링하세요. 원시 역슬래시 명령어가 아니라 외적 방정식과 세 행으로 된 행렬이 표시되어야 합니다. 이 셀에 대해서는 어떤 언어 커널도 실행되지 않습니다.
Right, up and outward normal form a right-handed frame.

$$\mathbf{r} \times \mathbf{u} = \mathbf{n}$$

Rows of the frame matrix: right, up, then outward normal.

$$
M = \begin{pmatrix}
r_x & r_y & r_z \\
u_x & u_y & u_z \\
n_x & n_y & n_z
\end{pmatrix}
$$

KaTeX은 완전한 TeX 컴파일러가 아닙니다. 지원되는 수학 표기법을 렌더링하지만, TikZ 다이어그램이나 전체 LaTeX 문서를 컴파일하지는 않습니다. KaTeX에 \includegraphics이 나열되어 있기는 하지만, 확인된 렌더러에서 SciREPL이 활성화하지 않은 신뢰 옵션이 필요하므로 여기서는 이미지 삽입 경로가 아닙니다. 그림에는 Markdown SVG/PNG 또는 JavaScript 캔버스를 사용하세요.

다른 기호 및 수학 명령어를 보려면 KaTeX 지원 표를 참조하세요. 설명서에는 SciREPL의 번들 버전보다 최신인 기능이 설명되어 있을 수 있습니다. 이러한 방향을 사용하여 큐브 동작을 설명하는 워크북은 마르코프 그룹 둘러보기를 참조하세요.

  3. 해당 사본을 다시 열려면 메뉴 → 파일 가져오기를 사용하세요. 이렇게 하면 다른 워크북 탭이 추가되며 기존 탭을 대체하지 않습니다.
  4. 정적 SVG, 포함된 PNG 및 방정식을 확인하세요. 이 항목들은 저장된 Markdown 소스에서 제공되며 코드를 실행할 필요가 없습니다. canvas_axes을 검사하고 해당 JavaScript 셀을 다시 실행하여 그림을 다시 생성하세요.

생성된 출력은 소스와 동일하지 않습니다. 확인된 Free 브라우저 빌드에서는 .srwb 내보내기가 JavaScript 이미지 출력을 저장할 수 있지만, 수동 메뉴 → 파일 가져오기는 해당 코드 출력을 복원하지 않습니다. JavaScript 소스는 그대로 유지되므로 다시 실행하세요. 인라인 SVG, 포함된 PNG 및 방정식은 Markdown 소스이며 가져올 때 표시됩니다. 이전에 표시된 출력을 코드가 방금 실행되었다는 증거로 사용하지 마세요.

이러한 점검은 위의 워크북 예제를 다루며 모든 내보내기 형식에서의 이미지 충실도를 다루지는 않습니다. PDF, DOCX, Markdown 및 기타 문서 내보내기가 모든 이미지를 동일한 방식으로 유지한다고 가정하지 마세요. 내보낸 문서를 직접 확인하세요. 사용 가능한 형식은 파일 및 내보내기 (영어 참조 페이지)를 참조하세요.

편집된 워크북을 내보내면 변경 사항의 백업이 생성됩니다. 셀을 편집해도 다운로드한 원본 예제는 업데이트되지 않습니다. 로컬 앱 저장소는 백업이 아니며, Android와 브라우저 세션은 작업을 자동으로 공유하지 않습니다.

문제가 있어 보이는 경우

셀 유형 및 소스 확인

  • 다이어그램 대신 SVG 코드가 표시되는 경우: 셀 유형이 Md인지 확인하고, 감싸고 있는 코드 펜스를 모두 제거한 다음 셀을 다시 렌더링하세요. SVG 데이터 URL이 아닌 완전한 인라인 <svg>...</svg> 예제를 사용하세요.
  • PNG가 누락된 경우: 함께 제공되는 embedded_png 셀을 사용하거나 공백이나 줄 바꿈 없이 전체 data:image/png;base64,... 문자열을 붙여넣었는지 확인하세요. 로컬 파일 이름은 포함된 이미지 데이터가 아닙니다.
  • 캔버스 코드가 실행되지 않는 경우: 셀 유형을 코드으로, 언어를 JS - JavaScript로 설정하고 Python은 사용하지 마세요. 전체 함수 래퍼와 마지막 window.renderImage(...) 호출을 유지하세요.
  • 가져온 JavaScript 셀에 그림이 없음: 이 워크북을 가져와도 코드가 실행되거나 코드 출력이 복원되지 않습니다. canvas_axes을(를) 검사하고 다시 실행하세요.
  • 원시 TeX 또는 수학 오류가 표시됨: Md를 사용하고 시작 및 끝 $$을(를) 모두 포함하며 각 백슬래시와 중괄호를 예제와 대조하여 확인하세요. 마지막 행을 제외한 각 행렬 행은 두 개의 백슬래시인 \\(으)로 끝납니다.
  • 편집으로 인해 추가 셀이 생성됨: 새 셀 패널은 셀을 추가합니다. 저장된 셀의 ✎ 연필을 사용하여 해당 기존 셀을 변경한 후 자체 ▶ 실행 버튼을 사용하세요. 실수로 편집기를 열었다면 취소을(를) 사용하세요.

저장된 셀, 연필 및 새 셀 패널에 대한 그림 안내는 첫 번째 워크북 인터페이스 둘러보기를 참조하세요. 셀 유형을 간략히 다시 확인하려면 워크북 참조 자료 (영어 참조 페이지)로 돌아가세요.
