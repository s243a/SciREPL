  1. numbers을(를) 찾습니다. 데스크톱에서는 해당 In[…] 레이블을 더블 클릭하세요. 터치 기기에서는 해당 레이블을 길게 누르세요. 확인된 빌드에서는 한 번 클릭이 이름 지정 동작이 아닙니다.

  3. 동일한 대화상자를 다시 열고 이름을 다시 numbers(으)로 변경한 다음 확인을(를) 선택합니다. 다음 셀들이 이 이름을 사용하므로 계속하기 전에 원래대로 복원하세요.

가상 파일 시스템을 통해 셀 읽기

numbers의 가상 디렉터리에는 점(.)으로 시작하는 속성이 있습니다. 경로는 워크북 마운트, 셀 식별자 및 원하는 속성을 결합합니다.

/nb/                         current workbook's cells
└── numbers/                 this named cell
    ├── .code                source text
    ├── .output              latest text output
    ├── .language            javascript
    ├── .type                code
    └── .name                numbers
워크북 경로 인터페이스에서 사용하는 셀 속성
속성읽었을 때 제공되는 내용
.code해당 소스의 실행 여부와 관계없는 현재 소스입니다.
.output마지막 텍스트 출력입니다. 읽기 전용이며 실행을 통해 제공됩니다. 비어 있거나 최신 상태가 아닐 수 있습니다.
.languagejavascript 또는 bash과(와) 같이 저장된 언어 식별자입니다.
.typecode 또는 markdown과(와) 같은 셀 유형입니다.
.name할당된 이름이며, 셀에 이름이 없으면 빈 텍스트입니다.

이제 ✎ 연필로 inspect_cells을(를) 열고, 코드 → Bash인지 확인한 다음 실행합니다. 이는 생성기 셀의 소스, 해당 JSON 출력 및 언어를 읽은 후 현재 워크북의 셀 식별자를 나열합니다. 셀이나 파일을 쓰거나 변경하지 않습니다.

printf 'Source:\n'
cat /nb/numbers/.code
printf '\nOutput:\n'
cat /nb/numbers/.output
printf '\nLanguage:\n'

이름, 위치 및 상대 참조

동일한 셀을 현재 1 기준 위치로 지정할 수도 있습니다. 예를 들어 /nb/In[2]/.output은(는) 현재 순서에서 두 번째 셀을 의미합니다. Markdown 셀도 개수에 포함됩니다. 이는 영구적인 카드 ID가 아니며, 순서를 바꾼 후에는 출력된 In[…] 번호가 이 경로에서 사용하는 위치와 다를 수 있습니다. 위치 참조는 셀을 재정렬하거나 삽입할 때 의미가 변경되지만, 이름 참조는 이름이 지정된 셀을 계속 식별합니다.

Bash 및 JavaScript은(는) 실행 중인 셀을 기준으로 하는 상대 참조도 지원합니다. /nb/-1/.output은(는) 이전 셀을, /nb/./.code은(는) 현재 셀을 의미합니다. 이러한 참조는 실행 컨텍스트가 필요하며 셀 순서에 의존합니다. 이 튜토리얼에서는 대신 명시적 이름을 사용하며, 모든 언어에서 상대 참조가 동일하게 동작하는 것에 의존하지 않습니다.

일반 JSON 파일 작성하기

✎ 연필로 write_shared을(를) 열고, 코드 → JS - JavaScript인지 확인한 다음 실행합니다. 이렇게 하면 생성기 셀의 마지막 텍스트 출력을 읽어 공유 JSON 텍스트 파일로 저장합니다. 공유 파일 시스템은 필요에 따라 상위 폴더를 생성합니다.

const text = window.notebookVFS.readFile('/nb/numbers/.output');
if (!text) throw new Error('Run numbers first.');
window.sharedVFS.writeFile('/shared/data/named-cell-tutorial/values.json', text, 'javascript');
console.log('Saved JSON to /shared/data/named-cell-tutorial/values.json');

결과는 사본을 담은 별개의 파일이며, 이는 JSON 출력을 복사한 것일 뿐 /nb/numbers/.output의 다른 이름이 아닙니다. 전용 폴더는 예제의 작은 스크래치 파일을 다른 데이터와 분리하여 보관하며, write_shared을(를) 다시 실행하면 이 단원 파일이 덮어쓰기됩니다.

다른 프로그램에서 파일 읽기

✎ 연필로 read_shared을(를) 열고, 코드 → JS - JavaScript인지 확인한 다음 실행합니다. 이 독립된 프로그램은 numbers 셀이 아니라 저장된 파일을 읽습니다.

const text = window.sharedVFS.readFile('/shared/data/named-cell-tutorial/values.json', 'utf8');
if (!text) throw new Error('Run write_shared first.');
const record = JSON.parse(text);
console.log(record.values.reduce((sum, value) => sum + value, 0));

16이(가) 나타납니다. 명시적인 'utf8'은(는) JSON 파싱을 위해 파일의 바이트를 텍스트로 읽습니다. 각 커널에는 고유한 파일 API이(가) 있습니다. 여기서 JavaScript은(는) 공유 파일 시스템 도우미를 사용하고, Python은(는) 아래의 선택적 단계에서 볼 수 있듯이 open(...)을(를) 사용할 수 있습니다. 이는 완전한 운영체제 파일 시스템이 아닙니다.

별도의 언어 간 확인을 위해 새 코드 → Bash 셀을 추가하고 이 명령을 실행할 수 있습니다. 동일한 일반 파일을 읽고 {"values":[3,5,8]}을(를) 출력합니다.

  3. {"values":[3,5,8]}이(가) 포함되어 있는지 확인한 다음, Files & Storage를 닫고 워크북으로 돌아갑니다.

사본은 자동으로 업데이트되지 않습니다. numbers을(를) 변경하거나 다시 실행하면 해당 셀의 최신 출력이 변경될 뿐 기존 values.json이(가) 변경되는 것은 아닙니다. 사본을 새로 고치려면 write_shared을(를) 다시 실행하고, 이를 기반으로 다시 계산하려면 read_shared을(를) 다시 실행하세요. 파일은 로컬 앱/브라우저 스토리지에 보관되지만 해당 스토리지를 지우거나 앱을 제거하면 삭제될 수 있습니다. 로컬 유지는 백업이 아니므로 보관해야 하는 파일은 내보내세요.

공유 파일을 보고 편집하고 내보내는 방법은 CSV 및 Files & Storage 둘러보기를 참조하세요. 워크북 전용 .srwb 내보내기에는 이러한 JSON 사본과 같은 별도 파일이 포함되지 않습니다. 워크북과 선택한 데이터 파일을 함께 포함하려면 Package archive export를 사용하세요.

6단계

이 쓰기 작업은 소스를 대체합니다. 보관해야 할 작업이 있는 셀이 아닌 실습용 임시 bash_report 셀을 사용하세요. 자신의 워크북에서 소스 쓰기를 시도하기 전에 백업을 만드세요. 이번 실습에서는 생성기 자체를 덮어쓰거나 프로그래밍 방식으로 .language을(를) 변경하지 마세요.

  1. bash_report이(가) 존재하고 해당 언어가 Bash인지 확인합니다. 초기 소스는 아래에 나와 있으며, 아직 실행하지 마세요.
  2. ☰ Menu → 설정 → 노트북 VFS을(를) 엽니다. 생성기의 쓰기 작업을 위해 셀이 다른 셀을 수정하도록 허용이(가) 선택되어 있어야 합니다. 확인된 빌드에서는 기본적으로 활성화되어 있지만 설정을 확인하세요. 노트북 간 읽기, 노트북 간 쓰기 또는 프로그래밍 방식 실행을 사용하도록 설정할 필요는 없습니다. 설정을 닫습니다.

const text = window.notebookVFS.readFile('/nb/numbers/.output');

);

readFile(...)은(는) 텍스트를 반환하며, 알 수 없는 셀이나 속성은 null을(를) 반환합니다. writeFile(...)은(는) 쓰기 작업의 성공 여부를 보고합니다. 생성기 내부의 검사 기능은 생성기 셀에 출력이 없거나 대상에 쓸 수 없는 경우 작업을 중단합니다. 이름은 대소문자를 구분하므로 정확한 철자를 유지하세요.

7단계

데이터 변경 및 종속된 각 단계 새로고침

  1. numbers의 ✎ 연필로 편집합니다. [3, 5, 8]을(를) [4, 5, 8](으)로 변경한 다음 해당 셀을 실행합니다. 이제 해당 JSON에 4이(가) 포함됩니다.
  2. 다른 것을 실행하기 전에 bash_report을(를) 살펴보세요. 이전 소스와 출력은 변경되지 않은 상태로 유지됩니다. 즉, 자동 종속성 새로고침은 없습니다.
  3. generate_report을(를) 다시 실행합니다. 이렇게 하면 보고서의 소스가 echo "Total: 17"(으)로 변경되지만, 이전의 Total: 16 출력이 계속 표시될 수 있습니다.
  4. bash_report을(를) 검토하고 다시 실행합니다. 이제 출력은 Total: 17입니다.
  5. 파일을 새로 고치기 전에 read_shared을(를) 다시 실행해 보세요. 여전히 16이(가) 표시되며, 이는 이전의 JSON 사본 기준입니다. 이제 write_shared을(를) 다시 실행한 다음 read_shared을(를) 다시 실행하면 파일 경로에서도 17이(가) 표시됩니다. Files & Storage에서 values.json을(를) 다시 열어 변경된 파일을 확인하세요.

소스, 출력 및 복사된 파일은 서로 다른 개념입니다. 이를 소비하는 셀보다 먼저 해당 셀의 ▶ 실행을(를) 사용하여 열려 있는 소스 편집을 완료하세요. 저장되지 않은 편집기 초안은 저장된 .code이(가) 아닙니다. 소스 쓰기는 대상을 실행하지 않으며, 복사된 파일은 이후의 변경 사항을 반영하지 않습니다. 명시적 순서(생성 셀 → 생성기 → 보고서)를 따르세요. 이전에 표시된 출력이 현재 소스가 실행되었다는 증거는 아닙니다.

소스 편집 내용과 이름을 유지하려면 워크북을 내보내세요. 일반적인 .srwb 가져오기는 현재 저장된 코드 출력을 삭제하므로, 다시 연 후에는 읽기 셀보다 먼저 numbers을(를) 다시 실행한 다음 생성기와 보고서를 실행하세요. 별도의 공유 데이터 파일은 파일 또는 패키지 내보내기가 필요합니다. 파일 및 내보내기 참조 (영어 참조 페이지)를 확인하세요.

  • 기대 수명 데이터 분석은(는) 일반적인 CSV 파일을 /shared/data/에서 읽으며, Python 및 R에서 실행되는 공유 파일 경로이고 이름이 지정된 셀 읽기가 아닙니다. 데이터 세트를 다운로드하고 패키지를 사용하므로 실행하기 전에 설정 및 동의 요구사항을 확인하세요.

  • Prolog가 TypR 생성은(는) 생성된 정의를 이름이 지정된 소스 전용 쿼리 셀과 결합한 다음 typr_output을(를) 작성합니다. #!source 셀은 실행하지 않고도 소스로 읽을 수 있습니다.

문제가 있어 보이는 경우

이름, 워크북 및 실행 순서 확인

  • 이름 지정 대화상자가 열리지 않는 경우: 소스, 출력 또는 연필이 아닌 저장된 셀의 In[…] 레이블을 더블 클릭하거나 길게 누르세요. 한 번 클릭은 이름 지정 동작이 아닙니다.
  • 생성기 셀을 찾을 수 없는 경우: Named Cell Interop이(가) 선택된 상태를 유지하고, 정확한 이름인 numbers을(를) 복원하며, 철자와 대소문자를 확인하세요. 이름을 변경해도 다른 셀의 경로는 다시 작성되지 않습니다.
  • 생성기에 “Run numbers first”라고 표시되는 경우: numbers을(를) 검토하고 실행하세요. 가져오거나 소스를 단순히 편집하는 것만으로는 .output이(가) 채워지지 않습니다.
  • JSON 파싱 실패: 생성기 셀을 전체 예제와 비교하세요. 출력은 제목이나 추가 인쇄 메시지가 아닌 JSON 전용이어야 합니다.
  • 보고서를 작성할 수 없는 경우: 기존 bash_report 셀이 이 워크북에 있는지, 셀이 다른 셀을 수정하도록 허용이(가) 선택되어 있는지 확인하세요. 소스 쓰기 문제를 해결하기 위해 프로그래밍 방식 실행을 활성화하지 마세요.
  • 보고서가 여전히 16인 경우: 데이터를 편집한 후 numbers, generate_report, bash_report 순서로 실행하세요. 복사된 파일은 write_shared을(를) 통해 별도로 새로 고친 다음 read_shared을(를) 다시 실행하세요.
  • Files & Storage에서 /nb를 찾을 수 없는 경우: 확인된 빌드에서 해당 화면은 이 가상 셀 마운트가 아니라 공유 파일을 보여줍니다. 대신 write_shared을(를) 실행하고 의도적으로 복사된 values.json 사본을 찾으세요.
