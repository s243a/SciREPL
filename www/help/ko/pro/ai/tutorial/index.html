요청당 비용이 전혀 들지 않는 빠른 테이블 기반 제안으로 시작해 보세요. 그런 다음 Assistant를 설정하고, 온라인 대안을 요청하고, 온디바이스 모델을 사용해 본 뒤, 코드를 설명해 주는 집중형 AI Prompt 셀로 마무리합니다.

  • Pro 전용
  • Pro 1.4.0 및 출시 예정인 실행 제어 기능
  • 로컬 모델: Android

대부분의 스크린샷은 Android 앱 기준이며, 일부는 브라우저 캡처 화면입니다. 레이아웃은 앱 버전에 따라 다를 수 있습니다.

버전을 확인하세요. 부록의 실행 관련 변경 사항은 제안된 Pro 1.5.0 버전에 맞춰 계획되어 있으며, 현재 미출시 상태이므로 최종 릴리스 번호는 변경될 수 있습니다.

여기서 “Free”는 API 요금이 없음을 의미합니다. 테이블 제안 및 온디바이스 모델은 제공업체 요금을 청구하지 않습니다. 그렇다고 해서 이러한 기능이 Free 에디션 기능인 것은 아닙니다. 이 단계별 안내는 SciREPL Pro용입니다. 온라인 요청은 자체 제공업체 계정을 사용하므로 요금이 발생할 수 있습니다.

오프라인 테이블 제안으로 시작하기

앱 헤더에서 ☰ Menu를 찾으세요. 가로선 세 개가 있는 버튼입니다. 자동완성을 엽니다. 해당 화면의 섹션 선택 도구는 일반, AI 추천(온라인), 로컬 모델(온디바이스) 항목으로 구분되어 있습니다. General부터 시작합니다.

  1. 로컬 코드 자동 완성 → 켜기로 설정합니다. 그렇지 않으면 기본값인 자동(데스크톱에서 켜짐, 터치에서 꺼짐) 설정으로 인해 휴대전화에서 꺼진 상태로 유지됩니다.
  2. 추천 칩 → 켜기로 설정하고 추천 → 커서 위치 상태를 유지합니다. 테이블 기능만 분리하여 확인하려면 온라인 섹션에서 AI 추천 → 꺼짐로 설정하고 로컬 섹션에서 로컬 모델 사용 → 꺼짐로 설정하세요(이전에 활성화되어 있던 경우). 다시 General로 돌아옵니다.
  1. Completion 화면을 닫습니다. 새로운 실습용 워크북에서 코드 셀과 JavaScript 언어를 선택합니다. 선택 영역 없이 커서를 맨 끝에 두고 cons을 입력합니다. const의 이 첫 글자들을 접두사(prefix)라고 합니다. const 항목이 나타나는지 확인하세요.
  2. 아래 스크린샷에서 cons 뒤에는 흐릿한 t이 따라붙는데, 이것이 인라인 고스트 텍스트(ghost text)입니다. 적용을 탭하거나 Tab를 눌러 제안을 삽입하면 const이 됩니다. 대신 const 칩이 나타나는 경우 해당 칩을 탭하는 것도 해당 후보를 수락하는 또 다른 방법입니다. 예를 들어 const values = [12, 15, 18];처럼 직접 줄을 완성해 보세요.

수락(Accept)은 실행(Run)이 아닙니다. 제안을 수락하면 소스 코드가 편집될 뿐, 셀이 실행되지는 않습니다. 이 섹션의 JavaScript 및 Python 예제는 편집 중 자동 완성을 보여줍니다. 이러한 실습용 셀을 실행하는 것은 이번 섹션에서 다루지 않습니다. 오프라인 테이블 레이어만 활성화된 상태에서는 단순히 제안을 생성하기 위해 접두사를 입력하더라도 API 요청을 보내거나 언어 런타임을 시작하지 않습니다.

향후 지원될 온라인 사전 가져오기: 입력 중에 모델 요청을 보낼 수 있는 옵트인 모드가 계획되어 있습니다. 아직 제공되지 않으며 릴리스 번호도 지정되지 않았습니다. 요청을 보내지 않는다는 위의 설명은 이 미래의 모드가 아니라 현재의 오프라인 테이블 레이어에 해당합니다.

휴대전화에서 두 가지 오프라인 표시 방식을 확인하세요. 추천 칩 → 켜기 상태를 그대로 두고, Python를 선택한 후 pri을 입력합니다. 커서 뒤의 흐릿한 nt은 print를 제안합니다. 사용자가 수락하기 전까지는 소스 코드의 일부가 아닙니다. 고스트 텍스트를 보기 위해 칩을 끌 필요는 없습니다. 적합한 후보가 여러 개일 때는 칩이 선택지를 제공하는 반면, 단일 후보는 고스트로 표시될 수 있습니다. 두 예제 모두에서 AI 추천 및 로컬 모델 사용을 꺼 둔 상태로 유지하세요.

칩이 여전히 켜기 상태인 채로, 실습 입력을 이 세 줄로 바꾸고 완성되지 않은 sample_m 뒤에 커서를 둡니다. 이 행은 작성 중인 소스 코드의 이름을 바탕으로 sample_mean 및 sample_median를 제공합니다. 후보를 선택하려면 칩을 탭하세요. 고스트 텍스트와 달리 이 행은 여러 대안을 보여줍니다.

sample_mean = 0
sample_median = 0
sample_m

추가 키 행(Python 휴대전화 사진에 표시됨)과 입력 중 구문 색상 강조는 별도의 선택적 Pro 제어 기능입니다. 둘 중 하나를 켜거나 끄고 파일 편집기의 개별 강조 표시 확인란을 확인하려면 외관 안내: 추가 키 및 구문 색상을 참조하세요.

이러한 자동 완성 화면 표시를 사용해 본 후, 다시 JavaScript로 전환하고 이번 학습의 나머지 부분에서도 칩을 켜 둡니다.

자동완성 → 일반 → 추천 칩에서 활성화된 여기에 표시된 오프라인 칩은 선별된 이름 테이블과 로컬 코드 정보를 결합합니다. Python에서는 워크북 코드에서 발견된 변수 및 함수, 캐시된 커널 이름 및 메서드를 포함한 객체 속성이 여기에 포함됩니다. 사용 빈도 및 수락 기록은 순위를 매기는 데 도움이 됩니다. 다른 언어는 적용 범위가 다릅니다. 정적 목록, 실행되지 않은 정의 또는 오래된 스냅샷으로 인해 현재 범위(scope)에서 사용할 수 없는 이름이 제안될 수도 있습니다. 테이블 기반 자동 완성은 언어 모델이 아니며 사용자의 작업에 대해 추론하지 않습니다.

셀 중간에 제안이 표시되는 것이 방해된다면 셀 끝에서만이 좋은 대안입니다. 선택 영역, 문자열, 주석 또는 중간에 잘린 이름의 경우 의도적으로 제안이 생성되지 않을 수 있습니다. 높이가 낮은 가로 모드에서는 코드 공간을 확보하기 위해 선택적 행이 사라질 수 있습니다. 자세한 내용은 모양 설정을 참조하세요.

2단계 · 온라인 설정

API 키 저장하기

API 키를 사용하면 SciREPL에서 사용자가 관리하는 제공업체 계정을 사용할 수 있습니다. 해당 제공업체로부터 키를 발급받고, 현재 가격과 계정 한도를 확인한 후, 이번 단원에서는 개인 데이터가 포함되지 않은 작은 실습용 워크북만 사용하세요.

  1. 열기: Menu → 🤖 AI Assistant (Pro). 패널의 ⚙ 톱니바퀴 를 탭하여 AI 설정을 엽니다.

    톱니바퀴가 보이지 않나요? 키보드로 인해 Assistant 패널이 이동하거나 스크롤될 수 있습니다. 패널 콘텐츠를 아래로 드래그하여 상단으로 다시 스크롤하면 톱니바퀴가 나타납니다. 키보드를 닫는 것도 공간을 더 확보하는 방법입니다.

  2. 모델 설정 대상 → AI 어시스턴트로 설정합니다. 백엔드(예: OpenRouter) 및 모델을 선택하고, 백엔드가 구성 가능한 엔드포인트를 사용하는 경우 엔드포인트를 확인합니다.
  3. 일치하는 API 키를 입력합니다. 다른 제공업체/엔드포인트 쌍의 키를 관리하려면 저장된 키을 사용하세요. 특정 대상의 키가 다른 대상의 키로 자동 적용되지는 않습니다.
  4. 저장을 탭합니다. 설정을 저장하는 것만으로는 모델 요청이 발생하지 않습니다. 다음 단계를 위해 패널을 열어 둡니다.

키가 워크북에 들어가지 않도록 주의하세요. 셀, 프롬프트, 스크린샷 또는 내보낸 파일에 키를 붙여넣지 마세요. 저장된 키는 애플리케이션 수준의 암호화 없이 로컬 앱/브라우저 스토리지에 유지되므로 기기를 보호하고 신뢰할 수 없는 코드를 실행하지 마세요. 저장 및 전송되는 항목에 대한 자세한 내용은 Pro 개인정보 처리방침에 설명되어 있습니다.

비용이 저렴하고 도구(tool) 사용이 가능한 모델은 Assistant를 시작하기에 합리적인 선택입니다. 비교해 볼 만한 예로는 GLM 5.3 Flash, GPT-6 Luna, Claude Haiku 5.5, DeepSeek V4 Flash 등이 있습니다. 정확한 모델 ID, 사용 가능한 버전, 도구 지원 여부 및 요금은 앱 버전과 제공업체에 따라 다르므로 현재 선택 도구와 제공업체 설명서를 확인하세요. 새로 발표된 모델은 앱을 업데이트해야 목록에 나타날 수 있습니다. 나중에는 자동 완성 전용으로 저렴한 다른 모델을 선택할 수도 있습니다.

목록에 모델이 없나요? AI 설정 → 모델 설정 대상 → AI 어시스턴트에서 먼저 올바른 백엔드를 선택한 다음, 제공업체의 정확한 API 모델 ID를 Model 선택 도구 아래의 또는 사용자 정의 모델 ID 입력에 입력하고 저장를 탭하세요. 이 필드는 Pro 1.4.0에서 이미 지원됩니다.

단순히 모델의 마케팅 이름만이 아니라 선택한 제공업체를 통해 ID를 확인하세요. OpenRouter의 경우 조직 접두사를 포함해야 합니다(예: anthropic/claude-haiku-5.5, 해당 모델 페이지 참조). 해당 페이지의 URL이 아닌 ID를 입력하세요. 사용자 지정 ID는 드롭다운보다 우선 적용되며, 목록에 있는 모델을 다시 선택하면 사용자 지정 필드가 지워집니다.

ID를 입력한다고 해서 API 지원 기능이 추가되는 것은 아닙니다. 해당 모델은 API(SciREPL에서 사용하는 방식)를 통한 도구 호출을 지원해야 합니다. 제공업체 액세스 권한, 호환성 및 현재 요금을 확인하세요. 저장하더라도 해당 항목의 유효성을 검증하거나 모델 요청을 전송하지는 않습니다.

3단계 · 의도적인 도구 사용

Open 에이전트 프리셋으로 간단한 예제 만들기

열림은 두 번째로 허용 범위가 넓은 보안 프리셋이며, 이는 전체 제어 다음입니다. 기본적으로 노트북 편집을 허용하며 Cautious보다 확인 메시지가 적게 표시됩니다. 실행 시 확인 메시지가 표시되는지 여부는 버전 및 권한 설정에 따라 다릅니다. 출시 예정인 실행 승인 부록을 참조하세요. 실습용 워크북에서 신중하게 사용해야 하며, 자동 완성을 위한 필수 요건은 아닙니다.

  1. AI 설정에서 다음을 선택합니다: Security Level → Open 및 에이전트 쓰기 → 활성 워크시트. 소스 탐색은 꺼 둔 상태로 유지하고 다음을 끕니다: AI가 생성한 셀 자동 실행. 그런 다음 Kernels… 아래에서 JavaScript → Ask로 설정한 후 저장합니다. 이전에 실행 도구에 대해 Allow가 저장되어 있었더라도 이 커널 규칙에 따라 여전히 확인을 요청합니다.

    자동 실행 해제가 실행 잠금을 의미하지는 않습니다. 이는 새로 생성된 셀이 자동으로 실행되는 것만 중단할 뿐, 별도의 execute_cell 또는 run_cells 요청을 비활성화하지는 않습니다. 이미 출시된 Pro 1.4.0의 Open 기본값은 확인 없이 이를 허용할 수 있습니다. 향후 출시될 Open 기본값은 확인을 요청하지만, 명시적인 도구 또는 커널 Allow 설정으로 해당 기본값을 변경할 수 있습니다. AI 설정 → 커널… → JavaScript → 확인 설정을 통해 이번 실습의 JavaScript 실행을 확인 단계 뒤로 유지할 수 있습니다. 사용자가 직접 셀을 수동으로 실행(Run)하는 것은 별개의 동작입니다. 다음 릴리스의 실행 제어에 대한 자세한 내용은 부록에 나와 있습니다.

    더 많은 확인 절차를 원하신다면 대신 주의을 사용하세요. Open은 별도의 소스 탐색 및 쓰기 범위 제어를 여전히 준수하지만, Full control은 이 두 가지 포괄적인 제어를 우회합니다. 개별 권한 및 기타 안전장치는 여전히 중요합니다. 검토은 추가적인 읽기 전용에 가까운 제한 사항으로, 이번 셀 생성 시연을 방해할 수 있습니다.

API 기반 자동 완성 요청하기

  1. 메뉴 → 자동완성을 연 다음, 섹션 → AI 추천(온라인)을 선택합니다. AI 추천 → 탭할 때로 설정하세요.
  2. 제공업체, 엔드포인트 및 모델을 상속받으려면 자동완성 모델 → AI 어시스턴트 따르기 상태를 유지합니다. 또는 제공자와 모델 선택를 선택하여 저장된 제공업체/엔드포인트와 짧은 제안에 적합한 저비용 모델을 선택하세요. 이 화면에서는 키를 입력하지 않으며, AI 설정 열기을 통해 먼저 키를 추가할 수 있습니다.
  3. 이 섹션의 고급 항목을 열어 응답 제한 시간과 지출 보호 한도를 확인하세요. 기본값은 6초, $0.25/일, $5/월입니다. 한도를 늘리기 전에 가격을 확인하세요.

    완성되지 않은 const average = 줄 뒤에 커서를 둡니다. 제안 행 끝에 있는 …을 탭하거나, …AI 추가 키를 사용하거나, Ctrl + Shift + Space를 누릅니다.

단순한 AI 칩이 아닌 코드를 선택하세요. 이번 요청에서 첫 번째 칩은 values.reduce((a, b) => a + b, 0) / values.length;을 제안했습니다. 이를 탭하여 전체 미리보기를 확인하세요: 배열을 합산하고 길이로 나누어 이번 예제에서는 15를 반환합니다. 두 번째 칩은 eval(values.join(' + ')) / values.length;을 제안했습니다. 불필요한 eval 대안은 거부하세요: 평균을 계산하는 데 문자열을 실행 가능한 코드로 변환할 필요는 없습니다. 반환된 코드를 수락하기 전에 직접 확인하고, 검토를 마친 후에만 실행(Run)하세요.

요청 시 최대 다섯 개의 대안을 요청하지만 화면에는 더 적게 표시될 수 있습니다. 한 번 더 탭하면 먼저 이미 수신된 대안 페이지를 넘겨 보여주며, 이를 모두 확인한 후에는 추가 요청을 보낼 수 있습니다. 요청 로딩 표시가 돌아가는 동안 탭하면 요청이 취소됩니다. 제한 시간이 만료되면 늦게 도착한 응답은 버려지며, 글자를 입력하거나 커서를 이동하면 이전 제안은 만료되어 사라집니다.

독립적이라는 것은 완전히 독립되어 있음을 뜻합니다: Assistant 모델을 변경하더라도 별도의 자동 완성 선택 항목은 그대로 유지됩니다. 이는 뛰어난 성능의 에이전트와 저렴한 자동 완성을 함께 사용하고 싶을 때 유용합니다. Assistant를 따르도록 설정하면 식별 정보만 상속될 뿐, 대화 내용이나 에이전트 권한은 상속되지 않습니다.

비용을 지불하는 대상과 전송되는 데이터 확인하기

온라인 자동 완성은 온디맨드 방식입니다: 일반적인 입력 중에는 아무것도 전송되지 않습니다. 입력 중 사전 가져오기 기능은 이 워크플로에서 아직 제공되지 않습니다. 자동 완성은 제한된 현재 셀 컨텍스트(Assistant 채팅이나 전체 워크북이 아닌, 커서 앞 최대 1,500자, 커서 뒤 200자, 최대 12개의 로컬 이름)만 전송합니다. 비밀 정보 마스킹은 최선형(best-effort)으로 이루어지므로 전송되는 페이로드를 직접 검토하세요.

항상 허용은 해당 대상에 대한 상시 동의를 부여하며, 제공업체, 엔드포인트 또는 모델이 변경되면 다시 확인을 요청합니다. 묻지 않고 보내기은 처음에 해당 선택을 준비하지만 여전히 첫 번째 실제 페이로드를 한 번 표시합니다. 학습 중에는 매번 묻기 상태를 유지하세요.

일별/월별 금액은 자동 완성 전용 소프트 지출 보호 한도이며, 보장된 제공업체 청구 상한선이 아니며 Assistant 또는 AI Prompt 요청을 위한 예산도 아닙니다. 실패 및 취소 시에도 예약된 요금이 유지될 수 있습니다. 지출 내역 지우기(Clear spending history)를 실행해도 한도 누적 금액이 재설정되지는 않습니다. 가격이 표시되지 않은 모델의 경우 명시적인 입력/출력 가격 상한선을 설정해야 하며, 그렇지 않으면 앱에서 전송을 거부합니다.

5단계 · 선택적 Android 다운로드

온디바이스 모델 사용해 보기

선택 사항인 Qwen2.5-Coder 0.5B 모델은 테이블이 확실하지 않을 때 로컬에서 코드를 제안합니다. 이는 소형 코드 자동 완성 모델이며, 대화형 에이전트를 대체하는 것이 아닙니다. 설치가 완료되면 추론 시 입력된 코드를 제공업체로 전송하지 않으며 API 요금도 발생하지 않습니다.

  1. Pro 앱을 Google Play에서 설치한 적격 Android 휴대전화에서, 메뉴 → 자동완성 → 섹션 → 로컬 모델(온디바이스)을 엽니다.
  2. 설치을 탭하고 약 400 MB의 다운로드를 위한 시간과 저장 공간을 확보하세요. 현재 사이드로드(sideload)된 설치 버전은 이 경로를 통해 모델을 다운로드할 수 없습니다.
  3. 준비가 되면 로컬 모델 사용 → 확실하지 않을 때 설정을 유지합니다. 간단한 사례는 테이블이 처리하고, 확실하지 않을 때 모델이 제안을 제공합니다. 항상는 모델을 더 자주 실행하며, 꺼짐은 다운로드된 파일을 삭제하지 않고 모델 실행을 중지합니다.
  1. 코드 셀로 돌아가 완성되지 않은 이름이나 줄에서 입력을 잠시 멈춥니다. 결과는 컨텍스트에 따라 다르며 모든 멈춤에서 제안이 생성되는 것은 아닙니다. 적절한 고스트나 칩을 수락하고 소스 코드를 검사한 다음 별도로 실행(Run)하세요.

분산은 스튜던트 t-분포가 아닙니다. 크기 10인 독립 정규 표본의 경우, 9s² / σ²은 자유도 9인 카이제곱 분포를 따릅니다. 여기서 모분산은 σ² = 1입니다. 반면 스튜던트 t-분포는 표준화된 표본 평균 (mean − μ) / (s / √10)(추정 표준편차 s 사용)를 설명하며, 여기서도 자유도는 9입니다. NIST: 분산 · NIST: 평균.

  • AI 설정 → 보안… → execute_cell / run_cells에서는 이미 Default / Allow / Ask / Deny를 제공합니다. 이번 업데이트를 통해 Open이 상속하는 Default가 확인로 변경됩니다. Full control은 계속 Allow를 유지합니다. 명시적인 도구 또는 커널 규칙은 상속된 기본값을 대체할 수 있으며, 둘 다 명시적인 경우 더 안전한 규칙이 우선 적용됩니다. 학습 중에는 Default 또는 Ask 상태를 유지하세요. Allow는 재정의(override)일 뿐 더 강력한 샌드박스를 의미하지 않습니다. 커널의 Ask/Deny, Review 및 전역 JavaScript 비활성화는 여전히 적용됩니다.
  • 실행을 선택하기 전에 실행 요청을 읽어보세요. 해당 요청만 승인하려면 앞으로 확인 없이 어시스턴트 셀 실행 허용을 선택 해제된 상태로 둡니다. 이를 선택하면 초기화할 때까지 이 셀, 대화 또는 제공업체뿐만 아니라 모든 워크북에 걸쳐 공유 실행 도구 규칙이 변경됩니다. 명시적인 커널 Ask 설정이 있으면 해당 옵션이 숨겨집니다.
  • 네임스페이스 검사 및 새로 생성된 셀 프롬프트는 이러한 상시 동의 권한을 생성할 수 없습니다. 생성된 셀의 실행 프롬프트에는 제한된 코드 미리보기가 포함되며, 긴 미리보기는 말줄임표로 끝납니다. 내용이 잘린 경우 Cancel을 선택하고 새로 생성된 셀의 전체 소스 코드를 검사한 뒤 신뢰할 수 있는 경우에만 직접 실행(Run)하세요. 이전에 저장된 실행 Allow는 자동 실행(Auto-run)이 켜져 있을 때 생성된 셀의 자동 실행을 여전히 허용할 수 있으므로 여기서는 자동 실행을 꺼 두세요.
  • 저장된 실행 도구 Allow가 유효한 상태에서 Full control 이외의 프리셋을 선택하면 경고창에 기본값으로 복원, ‘허용’ 유지, 또는 취소 옵션이 표시됩니다. Reset은 커널 재정의를 지우지 않고 선택한 프리셋의 도구 규칙을 복원합니다. Keep은 재정의를 유지합니다. Cancel은 이전 프리셋 선택을 복원합니다. Reset 및 Keep은 설정을 저장할 때까지 초안 변경 상태로 유지됩니다.

실행 승인이 데이터 공유를 위한 포괄적 허가를 의미하지는 않습니다. 실행 도구의 출력은 Assistant 모델로 반환될 수 있으며, 허용된 코드는 네트워킹을 사용할 수 있습니다. 온라인 자동 완성의 항상 허용, AI Prompt의 컨텍스트 검토, Remote/MCP의 개인정보 공개 설정은 별개로 유지됩니다. MCP 노트북 실행은 동일한 실행 검사를 사용하며, 이러한 검사가 브로커의 Terminal 셸을 샌드박스로 격리하지는 않습니다.

부록 · 계획된 워크북 컨텍스트 및 히스토리

설계 제안 단계: 이러한 기능은 아직 구현되지 않았으며 특정 릴리스에 할당되지도 않았습니다. 위의 예정된 실행 승인 변경 사항과는 별개이며 현재 릴리스를 차단하지 않습니다.

  • 필요할 때 워크북 요약 가져오기. 이 계획은 반복되는 자동 소스 미리보기를 메타데이터 전용 디렉터리 도구(셀 이름, 선택적 설명, 언어 및 유형, 워크북 리비전)로 대체합니다. 제안된 도구는 list_cells(view: "metadata" 포함)이며, Assistant는 선택된 소스를 별도로 읽게 됩니다. 이는 제한된 개요이며 자동으로 생성된 AI 설명이 아닙니다.
  • 매번 전송할 때마다 첨부하는 대신 한 번만 첨부. 제안된 Attach workbook summary this time 확인란은 새로운 대화에서 선택된 상태로 시작하여 해당 첨부 파일이 실제로 전송된 후 선택 해제될 수 있습니다. 전송하기 전에 선택을 해제하거나 최신 개요를 위해 다시 선택할 수 있습니다. 초기 기본값에 대해서는 여전히 개인정보 보호 및 사용성 검토가 필요합니다. 대화가 이어질 때는 다른 요약이 추가되지 않으며, 탭을 전환해도 자동으로 다시 활성화되지 않습니다. 미리보기 및 기존 읽기/개인정보 보호 권한은 여전히 적용되며, 대용량 워크북은 추가 페이지가 필요할 수 있습니다.
  • 선택을 해제해도 기록이 지워지지는 않습니다. 새로운 자동 첨부만 중단될 뿐, 대화에 이미 포함된 요약이 제거되거나 허용된 도구 읽기가 차단되지는 않습니다. 기존 전체 화면 Agent, AI Prompt 및 자동 완성 컨텍스트 제어는 별개로 유지됩니다.
  • 전송 간 변경 사항 추적은 추후 옵션입니다. 간결한 업데이트를 위해서는 전송된 컨텍스트의 알려진 기준점과 신뢰할 수 있는 리비전이 필요합니다. 사용자의 편집 내용이 강조 표시될 수 있지만, 에이전트의 편집, 가져오기 및 알 수 없는 변경 사항도 중요합니다. 소스 편집이 셀 설명을 자동으로 다시 작성하지는 않으며, 누락되거나 오래된 기록이 있는 경우 추측성 업데이트 대신 새로운 개요를 가져와야 합니다.
  • 선택적 로컬 히스토리 및 GitHub 동기화는 장기적인 Pro 아이디어입니다. 로컬 Send 체크포인트를 사용하면 외부와 아무것도 공유하지 않고도 Git 기반의 diff를 지원할 수 있습니다. 독립적인 동기화를 통해 자체 페이로드 미리보기 및 권한 부여를 거쳐 워크북을 Gist 또는 리포지토리의 선택한 파일에 게시할 수 있습니다. 히스토리를 활성화하더라도 GitHub에 푸시하거나 AI에 diff를 전송하지는 않습니다. Git은 콘텐츠 변경 사항을 보여줄 뿐 사람이 직접 작성했다는 증거는 아닙니다.

Secret Gist는 비공개가 아닙니다. URL을 알고 있는 사람이라면 누구나 읽을 수 있습니다. 접근을 제한해야 하는 경우에는 비공개 리포지토리를 사용하세요. 게시하기 전에 워크북 소스 및 설명에서 비밀 정보를 제외하세요. GitHub의 Gist 가시성 설명서.
