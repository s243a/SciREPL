実践しながら学ぶ

セルに名前を付けてプログラムを連携する

セルには位置だけで識別される代わりに、numbersのような便利な名前を付けることができます。他のセルは/nb/numbers/.outputを通じてその最新のテキスト出力を読み取ったり、/shared/内の通常のファイルを介してデータを交換したりできます。JavaScriptとBashで両方のルートを試してから、別のセルで小さなBashプログラムを生成してください—生成されたコードを自動実行することはありません。

  • Free + Proのワークフロー
  • ブラウザで検証済みの例
  • 約15分

ウォークスルーとスクリーンショットは、SciREPL Freeブラウザビルドにおいて6日 十月 2026年に確認されました。これらは幅の狭いブラウザの完全なキャプチャであり、Androidのスクリーンショットではありません。Proおよびすべてのリリース済みバージョンについて、このガイドでの確認は行われていません。メインの演習では同梱のJavaScriptおよびBashを使用します。パッケージ、モデルの呼び出し、ランタイムのダウンロードは不要です。Pythonは任意の最終ステップです。

ここでの「パス」の意味:/nb/はプログラムから利用可能な、現在選択されているワークブックのセルの仮想ビューです。これはAndroidの「ダウンロード」内のフォルダではなく、独立した「パスビュー」画面でもありません。確認済みのFreeバージョンのファイルとストレージ画面では/nb/を閲覧できません。後ほど、その画面で表示できる共有ファイルに意図的に一部のデータをコピーします。

このレッスンで学ぶこと
  1. 小さなサンプルワークブックをインポートする
  2. セルの名前を見つけて変更する
  3. データ生成セルを実行する
  4. パスを通じてセルを読み取る
  5. 共有JSONファイルを介してデータをやり取りする
  6. 別のセルのソースを生成し、自身で実行する
  7. データを変更して結果を更新する

すべてのチュートリアル

ステップ1

実行せずに例をインポートする

  1. 名前付きセルのサンプルワークブック（.srwb）をダウンロードします。ファイル自体を保存し、その.srwb拡張子を保持してください。ブラウザにテキストが表示される場合は、保存またはダウンロード機能を使用してください。
  2. SciREPLの上部ヘッダーで、☰ Menu（三本の水平線があるボタン）を見つけます。これを開いて📂 ファイルをインポート (例: .srwb, .ipynb, .csv, .py, .zip)を選択してください。必要に応じてメニュー内をスクロールします。
  3. デバイスのファイルピッカーでnamed-cell-interop.srwbを選択します。メニューが開いたままの場合は閉じ、ワークブックセレクターで新しいNamed Cell Interopタブを選択してください。セレクターの▾矢印はアプリタイトルの近くにあります。既存のワークブックは保持されます。
  4. はじめにを読み、numbers、inspect_cells、write_shared、read_shared、generate_report、bash_report、python_totalという名前の七つのコードセルを見つけます。演習を進められるよう、これらにはあらかじめ名前が付けられています。

インポートは実行ではありません。通常の.srwbインポートでは、自動実行が有効になっている場合でもコードは実行されません。このレッスンではRun All Cellsを選択しないでください。順序が重要であり、最後のPythonセルは任意です。見慣れないコードは実行前に確認してください。

ダウンロードとピッカーの手順についての詳細が必要ですか？手動ワークブックインポートのウォークスルーをご利用ください。このレッスンを進めるには、Named Cell Interopを選択したままにしてください。/nb/は開いているすべてのタブではなく、アクティブなワークブックを指します。

ステップ2

セルの名前を見つけて変更する

保存されたコードセルのヘッダーにはIn[…]プロンプトラベルがあり、名前付きセルにはその名前も表示されます。名前付けに使用するのはこのラベルであり、セルのソースを編集する✎ 鉛筆ではありません。表示される番号は保存されたカードを識別するものであり、並べ替え後に/nb/In[N]/...パス内のセルの現在位置と一致する必要はありません。参照には名前を使用することをお勧めします。

  1. numbersを見つけます。デスクトップでは、そのIn[…]ラベルをダブルクリックします。タッチデバイスでは、そのラベルを長押しします。確認済みのビルドでは、シングルクリックは名前付け操作ではありません。
  2. ダイアログでnumbersをmeasurementsに置き換え、OKで確定します。セルヘッダー内の名前が変更されます。ソースと言語は変更されません。
  3. もう一度同じダイアログを開いて、名前を再びnumbersに戻し、OKを選択してください。後続のセル群がその名前を使用するため、続ける前に元に戻しておきます。

cube_movesやcheck_movesのような、わかりやすくシンプルな名前を選びます。名前はワークブック内で一意である必要があり、/を含めたり、.で始めたり、In[2]のような予約済みの位置ラベルにすることはできません。名前を空にすると削除されます。

チュートリアルで「cube_movesを実行し、次にcheck_movesを実行する」と指示できるのはこのためです。これらはワークブック内で探すべきセル名であり、別途ダウンロードが必要なファイルではありません。セルを挿入または移動する際、位置よりも名前の方が優れた参照手段になります。

ステップ3

データを生成するセルを実行する

numbersを探します。そのセル自体の✎ 鉛筆をタップしてソースを確認し、セルがコード → JS - JavaScriptであることを確認してください。それから、別のセルを追加してしまう新規セルパネルではなく、その保存済みセルの ▶ 実行ボタンを使用します。

Proのショートカット：保存済みセルのエディタは、セルのソーステキストをダブルタップすることによってもProで開けます。✎ 鉛筆は両方のエディションで動作します。この編集ショートカットは、名前を変更するためにIn[…]ラベルをダブルクリックまたは長押しする操作とは異なります。

console.log(JSON.stringify({values: [3, 5, 8]}));

次のような単一行の出力を想定してください：

{"values":[3,5,8]}

結果はJSONテキストです。その構造により、散文のメッセージよりも他の言語から読み取りやすくなっています。生きたJavaScriptオブジェクトを渡したり、JavaScript変数をBashやPythonと共有したりしているわけではありません。

ステップ4

仮想ファイルシステム経由でセルを読み取る

numbersの仮想ディレクトリにはドット接頭辞付きのプロパティがあります。パスは、ワークブックのマウント、セル識別子、および必要なプロパティを組み合わせたものです：

/nb/                         current workbook's cells
└── numbers/                 this named cell
    ├── .code                source text
    ├── .output              latest text output
    ├── .language            javascript
    ├── .type                code
    └── .name                numbers
ワークブックパスインターフェースで使用されるセルプロパティ
プロパティ読み取りによって取得できる内容
.codeそのソースが実行されたかどうかに関わらず、現在のソース。
.output最新のテキスト出力。これは読み取り専用であり、実行によって提供されます。空であったり古くなっていたりする場合があります。
.languagejavascriptやbashなどの保存された言語識別子。
.typecodeやmarkdownなどのセルタイプ。
.name割り当てられた名前。セルに名前がない場合は空のテキスト。

今度は✎ 鉛筆をinspect_cellsで開き、コード → Bashを確認して実行します。これはプロデューサーのソース、そのJSON出力、およびその言語を読み取った後、現在のワークブックのセル識別子を一覧表示します。セルやファイルを書き込んだり変更したりすることはありません。

printf 'Source:\n'
cat /nb/numbers/.code
printf '\nOutput:\n'
cat /nb/numbers/.output
printf '\nLanguage:\n'
cat /nb/numbers/.language
printf '\nCell names and positions:\n'
ls /nb/

名前、位置、および相対参照

同じセルは現在の1始まりの位置で指定することもでき、たとえば/nb/In[2]/.outputは現在の順序で二番目のセルを意味します。Markdownセルも数えます。これは恒久的なカード識別子ではありません。順序を並べ替えた後、表示されるIn[…]の番号はこのパスで使用される位置と異なる場合があります。位置参照はセルの並べ替えや挿入を行うと意味が変わりますが、名前参照は指定された名前のセルを特定し続けます。

BashとJavaScriptは実行中セルからの相対参照もサポートしています。/nb/-1/.outputは前のセルを意味し、/nb/./.codeは現在のセルを意味します。これらには実行コンテキストが必要であり、セルの順序に依存します。本チュートリアルでは代わりに明示的な名前を使用しており、相対参照があらゆる言語で同一に動作することに依存していません。

ステップ 5

共有ファイルを介してデータを交換する

共有仮想ファイルシステムには、異なる言語カーネルが使用できる通常のファイルが保持されます。ここでの/shared/は、お使いのSciREPLブラウザ／アプリセッションの内部で管理されるストレージを意味し、Androidのダウンロードやパソコン上のフォルダ、クラウド同期ではありません。共有ファイルはテキストまたはバイトを保持しますが、ある言語の実行中変数を別の言語で利用できるようにするものではありません。

プログラムがデータを参照する二つの方法
パス指定する対象更新するもの
/nb/numbers/.output選択したワークブック内のセルの最新のテキスト出力。そのセルを再実行すること。
/shared/data/named-cell-tutorial/values.jsonカーネルやワークブックのタブをまたいで利用可能な通常のJSONファイル。そのファイルに明示的に書き込むプログラムまたはファイルエディタ。

通常のJSONファイルを書き込む

✎ 鉛筆をwrite_sharedで開き、コード → JS - JavaScriptを確認して実行します。これにより作成元の最新のテキスト出力が読み取られ、共有JSONテキストファイルとして保存されます。共有ファイルシステムは必要に応じて親フォルダを作成します。

const text = window.notebookVFS.readFile('/nb/numbers/.output');
if (!text) throw new Error('Run numbers first.');
window.sharedVFS.writeFile('/shared/data/named-cell-tutorial/values.json', text, 'javascript');
console.log('Saved JSON to /shared/data/named-cell-tutorial/values.json');

その結果はコピーを含む別のファイル（JSON出力）であり、/nb/numbers/.outputの別名ではありません。専用フォルダによって、この例の小さな一時ファイルが他のデータと分けて保持されます。write_sharedを再実行すると、まさにこのレッスンファイルが上書きされます。

別のプログラムからファイルを読み取る

✎ 鉛筆をread_sharedで開き、コード → JS - JavaScriptを確認して実行します。この独立したプログラムは、numbersセルではなく保存されたファイルを読み取ります:

const text = window.sharedVFS.readFile('/shared/data/named-cell-tutorial/values.json', 'utf8');
if (!text) throw new Error('Run write_shared first.');
const record = JSON.parse(text);
console.log(record.values.reduce((sum, value) => sum + value, 0));

16が出力されることを想定します。明示的な'utf8'は、JSONによる解析のためにファイルのバイト列をテキストとして読み取ります。各カーネルには独自のファイルAPIがあります。ここではJavaScriptが共有ファイルシステムのヘルパーを使用し、下のオプションのステップに示すように、Pythonはopen(...)を使用できます。これは完全なオペレーティングシステムのファイルシステムではありません。

言語間の別の確認として、新しいコード → Bashセルを追加してこのコマンドを実行できます。同じ通常のファイルを読み取り、{"values":[3,5,8]}を出力します:

cat /shared/data/named-cell-tutorial/values.json

ファイルGUIで同じファイルを表示する

  1. ☰ メニュー → ファイルとストレージを開きます。
  2. 共有 data フォルダを見つけ、次に named-cell-tutorial と values.json を見つけます。ファイルを選択してその JSON テキストを表示します。
  3. {"values":[3,5,8]} が含まれていることを確認し、Files & Storage を閉じてワークブックの作業を続行します。

コピーは自動的には更新されません。numbers を変更または再実行すると、その最新のセル出力は変更されますが、既存の values.json は変更されません。コピーを更新するには write_shared を再実行し、その後そこから再計算するために read_shared を実行します。ファイルはローカルのアプリ/ブラウザストレージに保持されますが、そのストレージを消去したりアプリをアンインストールしたりすると削除される可能性があります。ローカルでの永続化はバックアップではありません。保持する必要があるファイルはエクスポートしてください。

共有ファイルの表示、編集、エクスポートについては、CSV および Files & Storage のウォークスルー を参照してください。ワークブックのみの .srwb エクスポートには、この JSON コピーのような個別のファイルは含まれません。ワークブックと選択したデータファイルを一緒に含めるには、Package archive エクスポート を使用してください。

ステップ 6

別のセルのコードを生成し、自分で実行する

これまで Bash は JavaScript の出力を読み取ってきました。今度は JavaScript がその同じ JSON テキストを使用して合計を計算し、短い Bash プログラムを 既存の bash_report セルに書き込みます。コードの記述とコードの実行は二つの別々のアクションです。

  1. numbers実行 → JSON テキスト
  2. generate_reportJSON を読み取り → Bash ソースを書き込み
  3. bash_report確認 → 手動で実行

この書き込みはソースを置き換えます。保持する必要がある作業を含むセルではなく、コンパニオンのスクラッチ bash_report セルを使用してください。独自のワークブックでソースの書き込みを試す前にバックアップを作成してください。この演習では、ジェネレータ自体を上書きしたり、.language をプログラムで変更したりしないでください。

  1. bash_report が存在し、その言語が Bash であることを確認します。その初期ソースは以下に示されています。まだ実行しないでください。
  2. ☰ Menu → 設定 → ノートブック VFS を開きます。ジェネレータの書き込みには セルが他のセルを変更することを許可 がオンになっている必要があります。チェック済みのビルドではデフォルトでオンになっていますが、設定を確認してください。ノートブック間の読み取り、ノートブック間の書き込み、またはプログラムによる実行を有効にする必要はありません。Settings を閉じます。
  3. ✎ 鉛筆を generate_report 上で開き、コード → JS - JavaScript を確認して実行します。
const text = window.notebookVFS.readFile('/nb/numbers/.output');
if (!text) throw new Error('Run numbers first.');
const data = JSON.parse(text);
const total = data.values.reduce((sum, value) => sum + value, 0);
const updated = window.notebookVFS.writeFile(
  '/nb/bash_report/.code', `echo "Total: ${total}"`
);
if (!updated) throw new Error('Check bash_report exists and cell writes are allowed.');
console.log('Updated bash_report source; inspect it, then run it yourself.');

ターゲットはこのプレースホルダーで始まります:

echo "Run generate_report first"

ジェネレータが成功すると、bash_report のソースは echo "Total: 16" になります。この書き込みによって Bash が実行されたわけではありません。そのセルの ✎ 鉛筆 を開いて新しいソースを確認し、それ自体の ▶ 実行 をタップします。Total: 16 となるはずです。

readFile(...) はテキストを返します。未知のセルまたはプロパティは null を返します。writeFile(...) は書き込みが成功したかどうかを報告します。ジェネレーター内のチェックにより、プロデューサーに出力がない場合や宛先に書き込めない場合は停止します。名前は大文字と小文字が区別されます。正確な綴りを維持してください。

ステップ 7

データを変更し、依存する各ステップを更新する

  1. numbers をその ✎ 鉛筆 で編集します。[3, 5, 8] を [4, 5, 8] に変更し、そのセルを実行します。その JSON には 4 が含まれるようになります。
  2. 他のものを実行する前に bash_report を確認してください。以前のソースと出力は変更されないままです。依存関係の自動更新はありません。
  3. generate_report を再実行します。これによりレポートのソースが echo "Total: 17" に変更されますが、古い Total: 16 の出力が表示されたままになることがあります。
  4. bash_report を検査して再実行します。出力が Total: 17 になります。
  5. ファイルを更新する前に read_shared を再実行します。以前のまま 16 が表示されますが、これは古い JSON コピーによるものです。次に write_shared を再実行し、続いて read_shared を再実行します。ファイルルートにも 17 が表示されます。Files & Storage で values.json を再度開いて、変更されたファイルを確認します。

ソース、出力、コピーされたファイルは異なるものです。 コンシューマーの前に、そのセルの ▶ 実行 で開いているソースの編集を完了してください。保存されていないエディターの下書きは、保存されている .code ではありません。ソースの書き込みによって宛先が実行されることはなく、コピーされたファイルがその後の変更に追従することもありません。プロデューサー → ジェネレーター → レポートという明示的な順序に従ってください。古い出力が見えていることは、現在のソースが実行されたことの証明にはなりません。

ソースの編集内容と名前を保持するには、ワークブックをエクスポートします。通常の .srwb インポートでは現在、保存されたコード出力が破棄されるため、再度開いた後は、リーダーの前に numbers を再実行し、次にジェネレーターとレポートを再実行してください。個別の共有データファイルには、ファイルまたはパッケージのエクスポートが必要です。ファイルとエクスポートのリファレンス (英語のリファレンスページ) を参照してください。

オプション

Python から両方のルートを読み取る

Python を開始せずにここで終了することもできます。三番目の言語を試すには、まず numbers と write_shared を実行し、次に python_total を コード → Python として検査して実行します:

import json
record = json.loads(nb_read('numbers', '.output'))
print('Cell output:', sum(record['values']))
with open('/shared/data/named-cell-tutorial/values.json') as source:
    saved = json.load(source)
print('Shared file:', sum(saved['values']))

元のデータには Cell output: 16 と Shared file: 16、あるいは両方の行に 17 が表示されるのは、ステップ 7 で両方のルートを更新した後です。Python の nb_read('numbers', '.output') は、名前付きセルの最後のテキスト出力を読み取ります。独立した open(...) は、通常の Python ファイル構文を使用して共有ファイルを読み取ります。標準の json モジュールが両方を解析するため、%pip install は不要です。プロデューサーのみが更新された場合、二つの合計は異なる場合があります。

初回使用時、Python はランタイムの初期化またはダウンロードが必要になる場合があります。ビルドや既存の同意状況に応じてプライバシー／ネットワークに関する通知が表示されることがあります。同意する前にお読みください。このオプションのステップは JavaScript／Bash の演習には必須ではなく、コンパニオンをインポートしただけでは Python は起動しません。

他のワークブックでパターンを認識する

名前付きセルはシンプルな相互運用の境界を提供します。一つのプログラムがテキストを生成し、別のプログラムがそれを読み取るか、ソースの生成に使用します。カタログには、確認できるより大きな例がすでに用意されています:

  • 平均余命の分析 は通常の CSV ファイルを /shared/data/ から、Python および R で読み取ります。これは名前付きセルの読み取りではなく、共有ファイルルートです。データセットをダウンロードし、パッケージを使用します。実行する前にセットアップと同意の要件をお読みください。
  • Prolog が R を生成 は名前付き Prolog ソースを nb_read(..., '.code', ...) で読み取り、生成された R ソースを nb_write('r_factorial', '.code', ...) で書き込みます。R セルは個別に実行されます。
  • Prolog が TypR を生成 は生成された定義を名前付きのソース専用クエリセルと結合し、typr_output を書き込みます。#!source セルは実行しなくてもソースとして読み取り可能です。

これらのタイトルは☰ Menu → Browse Packages…で検索してください。これらは発展的な読書資料であり、本ガイド向けに認定された実行ウォークスルーではありません。利用可能なエディションや必要な設定が異なります。Prologが生成するワークブックには、Browse経由でインストールされるunifyweaver-scireplの依存関係が必要です。生のワークブックを単にインポートするだけでは、この依存関係はインストールされません。手動でインポートした.ipynbについては、その設定下でJupyterのインポートがコードを実行する可能性があるため、まずメニュー → 設定 → インポートと編集 → ワークブックのインポート時にセルを自動実行がオフになっていることを確認してください。Browseのウォークスルーおよび手動インポートガイドを参照してください。

何か問題が発生した場合は

名前、ワークブック、および実行順序を確認する

  • 命名ダイアログが開かない場合：保存済みセルのソース、出力、鉛筆アイコンではなく、In[…]ラベルをダブルクリックまたは長押ししてください。シングルクリックは命名の操作ではありません。
  • プロデューサーが見つからない場合：Named Cell Interopを選択したままにし、正確な名前numbersを復元して、スペルと大文字・小文字を確認してください。名前を変更しても、他のセル内のパスは書き直されません。
  • ジェネレーターに「Run numbers first」と表示される場合：numbersを確認して実行してください。ソースをインポートしたり単に編集したりするだけでは、.outputには値が設定されません。
  • JSONの解析に失敗する場合：プロデューサーを完全な例と比較してください。その出力は見出しや余分な出力メッセージではなく、JSONのみである必要があります。
  • レポートを書き込めなかった場合：既存のbash_reportセルがこのワークブック内に存在し、セルが他のセルを変更することを許可がオンになっていることを確認してください。ソース書き込みの問題を解決するためにプログラムによる実行を有効にしないでください。
  • レポートが依然として16のままである場合：データを編集した後、numbersを実行し、次にgenerate_report、続いてbash_reportを実行してください。コピーされたファイルはwrite_sharedで個別に更新し、その後read_sharedを再実行してください。
  • Files & Storageに /nb が見つからない場合：その画面には共有ファイルが表示され、チェック対象ビルドにおけるこの仮想セルマウントは表示されません。代わりにwrite_sharedを実行し、意図的に作成されたそのvalues.jsonコピーを探してください。

最初のワークブックのインターフェースチュートリアルではヘッダーと保存済みセルの鉛筆アイコンについて説明しており、グラフィックチュートリアルではセルが結果を生成するその他の方法を示しています。
