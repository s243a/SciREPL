画像、図、数式を追加する

ワークブックでは、コードだけでなく画像を使ってアイデアを説明できます。同じ単純な座標系を表示する三つの方法を試してみましょう。Markdownの静止画像、JavaScriptで描画された画像、そしてKaTeXで組版された数式です。Python、R、パッケージのインストール、AIアカウントは不要です。

  • ブラウザで検証済みの例
  • 約10分

例とスクリーンショットは、SciREPL Free ブラウザビルドにおいて6日 十月 2026年に確認されました。スクリーンショットは幅の狭いブラウザ表示領域を使用しており、Androidのキャプチャではありません。Androidでも同じ操作部が使用されますが、その配置は異なる場合があります。このガイドでは、Proおよびリリースされたすべてのアプリバージョンについてテストされているわけではありません。

すべてのチュートリアル

ステップ 1

サンプルワークブックを開く

付属ファイルには、埋め込みPNGを含む完全なサンプルが含まれています。すべてが一つの小さなワークブックにまとめられているため、長いBase64画像文字列を入力する必要はありません。

  1. グラフィックのサンプルワークブック (.srwb) をダウンロードします。.srwb拡張子を維持したまま、実際のファイルを保存してください。ブラウザにテキストが表示される場合は、その保存／ダウンロード機能を使用してください。保存したフォルダを控えておいてください。
  2. SciREPLを開きます。アプリ上部のヘッダーにある☰ Menu（三本の水平線のボタン）を見つけます。それをタップまたはクリックします。
  3. 📂 ファイルをインポート (例: .srwb, .ipynb, .csv, .py, .zip) を選択します。必要に応じてメニュー内をスクロールしてください。お使いの端末のファイルピッカーで、ダウンロードまたは選択したフォルダーから workbook-graphics.srwb を選択します。
  4. メニューが開いたままの場合は閉じ、ワークブックセレクターで新しい Workbook Graphics タブを選択します。既存のタブは保持されます。
  5. static_axes、embedded_png、canvas_axes、math_axes という名前の四つのセルを見つけます。コードを実行する前にそれらを確認してください。静的な図や数式はそれらの Markdown ソースから表示されます。JavaScript の画像は、そのセルを実行した後にのみ表示されます。

インポートは実行ではありません。 自動実行設定が有効になっている場合でも、.srwb のインポートによってそのコードが実行されることはありません。このレッスンで canvas_axes のみ JavaScript の実行が必要です。すべてのセルを実行 の手順はありません。

ダウンロードまたはピッカーに関する詳細情報が必要ですか？手動ワークブックインポートのウォークスルーに従ってください。上記の名前は保存されたセルに表示されます。名前付きセルパスのチュートリアルでは、それらを割り当てて使用する方法を説明しています。以下の手順を使用して、すでに開いているワークブック内にこれらの例を作成することもできます。

ステップ 2 · 方法 1

Markdown に静的な図を保持する

自分に向いている一枚の紙を思い浮かべてください。r は紙に沿って右を指し、u はそれに沿って上を指し、n は紙から自分に向かう外側を指します。点のある円はその外向きの方向を表しており、手前に向かってくる矢印の先端を見るようなものです。

インポートした図を編集する

  1. static_axes を見つけます。その保存されたセル自体のヘッダーにある ✎ 鉛筆（✕ の近く）をタップします。これにより既存のセルのソースが開きます。新規セルパネルでは別のセルが作成されます。
  2. セルタイプボタンを Md に設定したままにします。SVG テキスト内で、r: right を r: across に変更します。
  3. そのセルの ▶ 実行 ボタンをタップして保存し、Markdown を再度レンダリングします。Md セルの場合、このボタンはテキストをレンダリングし、JavaScript を実行したり言語ランタイムを起動したりすることはありません。

または独自の Markdown セルを作成する

  1. 次のセルを入力する新規セルパネルを見つけます。折りたたまれている場合は、アプリタイトルの近くにある ⌃ 新規セルパネルを表示 ボタンを使用します。
  2. コード と記されたセルタイプボタンをタップして、Md に切り替えます。Markdown は言語ドロップダウンのエントリではなく、セルタイプです。
  3. 以下の完全な SVG を、Markdown コードフェンスを追加せずに (```)、テキストフィールドにコピーします。周囲の文章と SVG の間には空行を空けてください。
  4. ▶ 実行 をタップして、レンダリングされた Markdown セルを追加します。紙と三つの方向ラベルがすべて表示されます。
<svg xmlns="http://www.w3.org/2000/svg"
     viewBox="0 0 360 220" width="100%" height="220"
     role="img" aria-label="Right, up and outward normal on paper">
  <title>A paper coordinate frame</title>
  <rect x="20" y="18" width="320" height="184"
        rx="6" fill="#ffffff" stroke="#526170" stroke-width="2" />
  <path d="M110 145 H280" fill="none" stroke="#075d69" stroke-width="3" />
  <polygon points="280,145 267,138 267,152" fill="#075d69" />
  <path d="M110 145 V48" fill="none" stroke="#064d91" stroke-width="3" />
  <polygon points="110,48 103,61 117,61" fill="#064d91" />
  <circle cx="110" cy="145" r="10" fill="#ffffff" stroke="#14191f" stroke-width="2" />
  <circle cx="110" cy="145" r="3" fill="#14191f" />
  <text x="204" y="168" fill="#14191f" font-size="16">r: right</text>
  <text x="124" y="62" fill="#14191f" font-size="16">u: up</text>
  <text x="42" y="190" fill="#14191f" font-size="16">n: toward you</text>
</svg>

SciREPL は Markdown をサニタイズします。この例では、通常の SVG 図形、テキスト、および明示的な fill/stroke 属性を使用しています。その矢じりはポリゴンです。サニタイザーを通過することについて marker-end="url(...)"、<style> ブロック、スクリプト、またはアニメーションに依存しないでください。

代わりに埋め込み PNG を使用する

もう一つの静的な選択肢は、Base64 データを Markdown ソースに直接保存した PNG です。標準的な Markdown の画像構文は次のようになります。

![Paper axes](data:image/png;base64,PASTE_THE_COMPLETE_BASE64_PNG_HERE)

この行が示しているのは動作する画像ではなく書式です。プレースホルダーを完全なエンコード済みPNGに置き換えるか、すでに動作しているembedded_pngセルを使用してください。base64,以降の部分はファイル名ではなく画像データです。改行せず一行のままにしてください。

小さな画面でセルに収まる画像にするため、付属のembedded_pngセルではwidth="100%"を含む以下の同等なインラインHTMLを使用しています。これはコード出力としてではなく、依然としてMarkdown内に保存されます。

<img alt="Paper axes" width="100%"
     src="data:image/png;base64,PASTE_THE_COMPLETE_BASE64_PNG_HERE">

いずれか一つの静的ルートを選択してください：編集可能な小さな図にはインラインSVG要素を使用し、ラスター画像にはdata:image/png;base64,...画像を使用します。data:image/svg+xml,...などのSVGデータURLはインラインSVGとは異なり、チェック済みビルドではブロックされます。リモート画像URLも同様にブロックされます。これらの自己完結した二つの例は、表示時に画像のダウンロードを必要としません。

どちらの静的な例もMarkdownソース内に存在します。コードを実行することなく、ワークブックのインポート後に表示できます。

ステップ 3 · 方法 2

JavaScriptで画像を描画する

静的な画像は、ソースを編集するまで変化しません。プログラムによって計算または描画される画像の場合は、コードセルを使用してJS - JavaScriptを選択してください。この例ではキャンバスに描画し、それをPNGに変換して、その画像をセルの出力に送信します。

  1. インポートしたワークブックで、✎ 鉛筆をcanvas_axes上でタップします。セルの種類がコードであり、言語がJS - JavaScript（コンパクトセレクターではJSのみが表示される場合があります）であることを確認してください。
  2. そのセルの完全なプログラムである以下のコードをお読みください。他のセル、ファイル、パッケージ、ネットワークリクエストは不要です。
  3. そのセルの ▶ 実行をタップします。JavaScriptソースの下に画像が表示されるはずです。

代わりに新しいセルを作成するには、新規セルパネルに移動し、必要に応じてMdをコードに戻して、言語ドロップダウンからJS - JavaScriptを選択します。コードを貼り付けてから▶ 実行をタップしてください。JavaScriptが非表示の場合は、☰ メニュー → 言語を見つけて有効にします。

(() => {
  const canvas = document.createElement('canvas');
  canvas.width = 360;
  canvas.height = 220;
  const ctx = canvas.getContext('2d');
  ctx.fillStyle = '#ffffff';
  ctx.fillRect(0, 0, 360, 220);
  ctx.strokeStyle = '#526170';
  ctx.lineWidth = 2;
  ctx.strokeRect(20, 18, 320, 184);

  function arrow(x1, y1, x2, y2, color) {
    const angle = Math.atan2(y2 - y1, x2 - x1);
    ctx.strokeStyle = color;
    ctx.fillStyle = color;
    ctx.lineWidth = 3;
    ctx.beginPath();
    ctx.moveTo(x1, y1);
    ctx.lineTo(x2, y2);
    ctx.stroke();
    ctx.beginPath();
    ctx.moveTo(x2, y2);
    ctx.lineTo(x2 - 14 * Math.cos(angle - 0.5),
               y2 - 14 * Math.sin(angle - 0.5));
    ctx.lineTo(x2 - 14 * Math.cos(angle + 0.5),
               y2 - 14 * Math.sin(angle + 0.5));
    ctx.closePath();
    ctx.fill();
  }
  arrow(110, 145, 280, 145, '#075d69'); // right
  arrow(110, 145, 110, 48, '#064d91');  // up
  ctx.fillStyle = '#ffffff';
  ctx.strokeStyle = '#14191f';
  ctx.lineWidth = 2;
  ctx.beginPath();
  ctx.arc(110, 145, 10, 0, 2 * Math.PI);
  ctx.fill();
  ctx.stroke();
  ctx.fillStyle = '#14191f';
  ctx.beginPath();
  ctx.arc(110, 145, 3, 0, 2 * Math.PI);
  ctx.fill();
  ctx.font = '16px sans-serif';
  ctx.fillText('r: right', 204, 168);
  ctx.fillText('u: up', 124, 62);
  ctx.fillText('n: toward you', 42, 190);
  window.renderImage(canvas.toDataURL('image/png'));
})();

r: rightをctx.fillText(...)内で変更してみてから、セルを再度実行してください。関数ラッパー(() => { ... })();はこの例の変数をローカルに保つため、トップレベルのconst変数を再宣言することなく再実行できます。

表示の呼び出しが重要です。末尾にwindow.renderImage(canvas.toDataURL('image/png'))を維持してください。'<svg>...</svg>'のような通常の文字列をJavaScriptから返すとテキストが表示されますが、その文字列がインラインの図に変換されるわけではありません。アプリのページにキャンバスを挿入する必要はありません。

ステップ 4 · 方法 3

数式を用いて画像を説明する

TeXスタイルの数式にはMarkdown (Md)セルを使用します。図の方向は右手系を形成します：右 × 上 = 外向き法線。下の行列において、一行目はr、二行目はu、三行目はnです。下付き文字は、選択したx、y、z座標系におけるそれらの成分です。

  1. ✎ 鉛筆をmath_axes上でタップするか、新規セルパネルでコード → Mdを使用して新しいセルを作成します。
  2. 以下の完全なテキストを使用してください。$$区切り文字はMarkdownソースに含めるものであり、コードフェンスで囲まないでください。
  3. ▶ 実行 をタップして Markdown を保存し、レンダリングします。生のバックスラッシュコマンドではなく、外積の方程式と三行の行列が表示されるはずです。このセルに対して言語カーネルは実行されません。
Right, up and outward normal form a right-handed frame.

$$\mathbf{r} \times \mathbf{u} = \mathbf{n}$$

Rows of the frame matrix: right, up, then outward normal.

$$
M = \begin{pmatrix}
r_x & r_y & r_z \\
u_x & u_y & u_z \\
n_x & n_y & n_z
\end{pmatrix}
$$

KaTeX は完全な TeX コンパイラではありません。 サポートされている数学表記をレンダリングしますが、TikZ 図や LaTeX ドキュメント全体をコンパイルすることはありません。KaTeX には \includegraphics が記載されていますが、これには確認済みのレンダラーで SciREPL が有効にしていない trust オプションが必要です。ここでは画像を挿入する手段にはなりません。画像には Markdown の SVG/PNG または JavaScript の canvas を使用してください。

他の記号や数式コマンドについては、KaTeX サポート表 を参照してください。ドキュメントには、SciREPL に同梱されているバージョンよりも新しい機能が記載されている場合があります。これらの指示を使用してキューブの動きを説明するワークブックについては、Markov Groups のウォークスルー を参照してください。

ステップ 5

コピーを保存してから、何を再実行すべきかを把握する

  1. ☰ メニュー → ワークブックとパッケージをエクスポート を開きます。
  2. このワークブックで ワークブック (.srwb) と 現在のタブのみ を選択し、エクスポート をタップします。ご自身で管理できる場所にファイルを保存してください。
  3. そのコピーを再度開くには、メニュー → ファイルをインポート を使用します。これにより別のワークブックタブが追加され、既存のタブが置き換えられることはありません。
  4. 静的な SVG、埋め込み PNG、および数式を確認します。これらは保存された Markdown ソースに由来し、コードの実行は不要です。canvas_axes を調べ、その JavaScript セルを再度実行して画像を再生成します。

生成された出力はソースと同じではありません。 確認済みの Free ブラウザビルドでは、.srwb エクスポートによって JavaScript 画像出力を保存できますが、手動での メニュー → ファイルをインポート ではそのコード出力は復元されません。JavaScript ソースは残るため、再実行してください。インライン SVG、埋め込み PNG、および数式は Markdown ソースであり、インポート時に表示されます。以前表示されていた出力を、コードが実行されたばかりであることの証拠として使用しないでください。

これらの確認は上記のワークブックの例を対象としており、すべてのエクスポート形式における画像の再現性を網羅しているわけではありません。PDF、DOCX、Markdown、およびその他のドキュメントエクスポートがすべての画像を同じように保持すると想定せず、エクスポートされたドキュメントを確認してください。利用可能な形式については、ファイルとエクスポート (英語のリファレンスページ) を参照してください。

編集したワークブックをエクスポートすると、変更内容のバックアップが作成されます。セルを編集しても、ダウンロードした元のサンプルは更新されません。ローカルアプリのストレージはバックアップではなく、Android とブラウザのセッション間で作業が自動的に共有されることもありません。

表示がおかしい場合

セルの種類とソースを確認する

  • 図の代わりに SVG コードが表示される場合: セルの種類が Md であることを確認し、囲んでいるコードフェンスを削除して、セルを再度レンダリングします。SVG データ URL ではなく、完全なインライン <svg>...</svg> の例を使用してください。
  • PNG が表示されない場合: コンパニオンの embedded_png セルを使用するか、スペースや改行を入れずに data:image/png;base64,... 文字列全体を貼り付けたか確認してください。ローカルのファイル名は埋め込み画像データではありません。
  • canvas コードが実行されない場合: セルの種類を コード に設定し、言語には JS - JavaScript を指定し、Python にはしないでください。関数ラッパー全体と最後の window.renderImage(...) 呼び出しを維持してください。
  • インポートされたJavaScriptセルに画像が表示されない場合:このワークブックをインポートしても実行されたり、コードの出力が復元されたりすることはありません。確認してcanvas_axesを再実行してください。
  • 未加工のTeXまたは数式エラーが表示される場合:Mdを使用し、開始と終了の両方の$$を含め、各バックスラッシュと中括弧を例と照合してください。最後の行を除き、各行列の行は二本のバックスラッシュ\\で終わります。
  • 編集によって余分なセルが作成された場合:新規セルパネルはセルを追加します。保存済みセルの✎ 鉛筆を使用してその既存セルを変更し、それ自体の▶ 実行ボタンを使用してください。誤ってエディタを開いた場合はキャンセルを使用します。

保存されたセル、鉛筆、および新規セルパネルの図解ツアーについては、最初のワークブックインターフェースのウォークスルーを参照してください。セルタイプの簡潔なまとめについては、ワークブックリファレンス (英語のリファレンスページ)に戻ってください。
