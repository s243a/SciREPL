オフラインの入力候補からAI支援コーディングまで

まずはリクエストごとのコストがかからない、高速なテーブルベースの入力候補から始めましょう。次にアシスタントを設定し、オンラインの代替候補をリクエストし、オンデバイスモデルを試して、最後にコードを解説する焦点を絞ったAI Promptセルで仕上げます。

  • Pro限定
  • Pro 1.4.0 + 今後提供される実行コントロール
  • ローカルモデル: Android

ほとんどのスクリーンショットはAndroidアプリを示していますが、一部はブラウザのキャプチャです。レイアウトはお使いのアプリのバージョンによって異なる場合があります。

バージョンを確認してください。 付録にある実行に関する変更は、提案中のPro 1.5.0向けに計画されており、これは未リリースです。最終的なリリース番号は変更される可能性があります。

ここでの「Free」はAPI料金が発生しないことを意味します。テーブルの候補やデバイス上のモデルではプロバイダーへの請求は発生しません。だからといってこれらがFree版の機能というわけではありません。このチュートリアルはSciREPL Pro向けです。オンラインリクエストはお客様独自のプロバイダーアカウントを使用するため、費用が発生する可能性があります。

ステップ1 · APIキーは不要

オフラインのテーブル候補から始める

アプリのヘッダーにある☰ Menuを見つけます。これは三本の水平線があるボタンです。補完を開きます。そのセクションピッカーによって全般、AI 候補（オンライン）、ローカルモデル（端末上）に分かれています。Generalから始めます。

  1. ローカルコード補完： → オンに設定します。そうしない場合、デフォルトの自動（デスクトップではオン、タッチ操作ではオフ）ではスマートフォン上でオフのままになります。
  2. 候補チップ → オンに設定し、候補： → カーソル位置のままにします。テーブルを分離するには、以前に有効にしていた場合、オンラインセクションでAI候補 → オフに設定し、ローカルセクションでローカルモデルを使う → オフに設定します。Generalに戻ります。
  1. Completionを閉じます。新しい練習用ワークブックで、コードセルとJavaScript言語を選択します。末尾にキャレットを置き、選択を行わずにconsと入力します。このconstの先頭の文字はプレフィックスと呼ばれます。constを探します。
  2. 下のスクリーンショットでは、consの後に薄いt（インラインのゴーストテキスト）が続いています。採用をタップするかTabを押して候補を挿入し、constにします。代わりにconstチップが表示された場合は、それをタップすることでもその候補を受け入れることができます。例えばconst values = [12, 15, 18];のように、行をご自身で完成させてください。

AcceptはRunではありません。候補を受け入れるとソースが編集されますが、セルは実行されません。このセクションのJavaScriptおよびPythonの例は、編集中におけるオートコンプリートを示しています。これらの練習用セルを実行することは本セクションの対象外です。オフラインテーブルレイヤーのみが有効になっている場合、プレフィックスを入力しても候補を表示するためだけにAPIリクエストを送信したり言語ランタイムを起動したりすることはありません。

将来のオンラインプリフェッチ: 入力中にモデルリクエストを送信できるオプトインモードが計画されています。まだ利用できず、リリース番号も割り当てられていません。上記のリクエストを行わないという記述は、この将来のモードではなく、現在のオフラインテーブル層に関するものです。

スマートフォンで二つのオフライン表示を確認します。 候補チップ → オンのままにして、Pythonを選択し、priを入力します。キャレットの後の薄いntはprintを提示します。受け入れるまではソースの一部にはなりません。ゴーストテキストを確認するためにチップをオフにする必要はありません。 単一の候補はゴーストとして表示される場合があり、複数の候補が当てはまる場合はチップによって選択肢が提供されます。両方の例でAI候補とローカルモデルを使うはオフのままにしてください。

チップがオンのままの状態で、練習用の入力をこれら三行に置き換え、未完成のsample_mの後にキャレットを残します。この行は自身のソース内の名前からsample_meanおよびsample_medianを提示します。チップをタップして候補を選択します。ゴーストテキストとは異なり、この行には選択肢が表示されます。

sample_mean = 0
sample_median = 0
sample_m

拡張キー行（Pythonのスマートフォンの画像に表示）および入力中の構文の色は、別個のオプションのProコントロールです。いずれかをオンまたはオフにする方法、およびファイルエディタの独立したハイライトチェックボックスを見つけるには、外観のウォークスルー: 拡張キーと構文の色を参照してください。

これらの補完表示を試した後、JavaScriptに戻し、レッスンの残りの部分ではチップをオンにしたままにしてください。

補完 → 全般 → 候補チップで有効化される、ここに示されたオフラインチップは、精選された名前テーブルとローカルコード情報を組み合わせたものです。Pythonでは、これにはワークブックのコード内で見つかった変数や関数、キャッシュされたカーネル名やメソッドを含むオブジェクト属性が含まれます。頻度と受け入れ履歴はそれらの順位付けに役立ちます。他の言語では対応範囲が異なります。静的リスト、未実行の定義、または古いスナップショットによって、スコープ内で現在利用できない名前が提案されることがあります。テーブルベースの補完は言語モデルではなく、タスクについての推論は行いません。

セル内での提案が邪魔になる場合、セルの末尾のみが代替手段となります。選択範囲、文字列、コメント、または途中で分割された名前では、意図的に提案が生成されないことがあります。縦幅の短い横画面では、コード用のスペースを確保するためにオプションの行が表示されなくなることがあります。外観設定を参照してください。

ステップ2 · オンライン設定

APIキーの保存

APIキーを使用すると、SciREPLが管理下のプロバイダーアカウントを利用できるようになります。そのプロバイダーからキーを取得し、現在の価格やアカウントの上限を確認した上で、このレッスンでは非公開データを含まない小規模な練習用ワークブックのみを使用してください。

  1. 開く： メニュー → 🤖 AI Assistant (Pro)。パネルの ⚙ 歯車 をタップしてAI Settingsを開きます。

    歯車アイコンが見当たらない場合 キーボードによってAssistantパネルの位置がずれたりスクロールしたりすることがあります。パネルのコンテンツを下にドラッグして上部へスクロールし、歯車アイコンを表示させてください。キーボードを閉じることでも表示スペースを広げられます。

  2. モデルを設定する対象 → AIアシスタントを設定します。バックエンド（例：OpenRouter）とモデルを選択し、バックエンドで設定可能なエンドポイントを使用している場合はエンドポイントを確認してください。
  3. 一致するAPIキーを入力します。他のプロバイダーとエンドポイントの組み合わせのキーを管理するには保存済みのキーを使用します。ある送信先用のキーが、別の送信先用のキーとして自動的に使えるわけではありません。
  4. 保存をタップします。設定を保存するだけではモデルへのリクエストは行われません。次のステップのためにパネルを開いたままにしておいてください。

キーをワークブックに入れないでください。セル、プロンプト、スクリーンショット、またはエクスポートしたファイルに貼り付けないでください。保存されたキーは、アプリケーションレベルの暗号化なしでローカルのアプリ/ブラウザストレージに保存されます。デバイスを保護し、信頼できないコードを実行しないでください。保存および送信される内容については、Proプライバシーポリシーで説明されています。

低コストでツール利用が可能なモデルは、Assistantの出発点として妥当な選択肢です。比較対象の例としては、GLM 5.3 Flash、GPT-6 Luna、Claude Haiku 5.5、DeepSeek V4 Flashなどが挙げられます。正確なモデルID、利用可能なバージョン、ツールのサポート状況、価格は、お使いのアプリのバージョンやプロバイダーによって異なります。最新の選択画面やプロバイダーのドキュメントを確認してください。新しく発表されたモデルは、表示されるまでにアプリのアップデートが必要な場合があります。後から、補完専用として別の安価なモデルを選択することもできます。

モデルが一覧に見当たらない場合 AI設定 → モデルを設定する対象 → AIアシスタントで、最初に正しいバックエンドを選択し、次にプロバイダーの正確なAPIモデルIDをModel選択ツールの下にあるまたはカスタムモデルIDを入力に入力して、保存をタップします。このフィールドはPro 1.4.0ですでに利用可能です。

モデルのマーケティング名だけでなく、選択したプロバイダーでIDを確認してください。OpenRouterの場合、組織のプレフィックスを含めます。たとえば、anthropic/claude-haiku-5.5（そのモデルページ上）のようになります。そのページのURLではなく、IDを入力してください。カスタムIDはドロップダウンより優先されます。一覧にあるモデルを再度選択すると、カスタムフィールドはクリアされます。

IDを指定してもAPIのサポートが追加されるわけではありません。モデルは、API（SciREPLが使用）を介したツール呼び出しに対応している必要があります。プロバイダーへのアクセス権、互換性、現在の価格を確認してください。保存してもこれらは検証されず、モデルへのリクエストも送信されません。

ステップ3 · 慎重なツール使用

Openエージェントプリセットを使用して小さな例を作成する

オープンは二番目に制限の緩いセキュリティプリセットであり、フルコントロールに次ぐものです。デフォルトでノートブックの編集を許可し、Cautiousよりも確認の頻度が少なくなっています。実行時に確認を求めるかどうかは、お使いのバージョンと権限設定に依存します。今後の実行承認に関する付録を参照してください。オートコンプリートの要件としてではなく、練習用のワークブックで意図的に使用してください。

  1. AI Settingsで、次を選択します セキュリティレベル → オープン および エージェントの書き込み → アクティブなワークシート。ソースの閲覧はオフのままにし、次をオフにします AIが作成したセルの自動実行。次項目の下で、 カーネル…、次を設定します JavaScript → 確認、その後に保存します。実行ツールのAllowが以前に保存されていた場合でも、このカーネルルールは引き続き確認を求めます。

    自動実行の無効化は実行ロックではありません。これにより新しく作成されたセルが自動的に実行されるのを防ぎますが、個別のexecute_cellまたはrun_cellsリクエストは無効になりません。リリース済みのPro 1.4.0のOpenデフォルトでは、確認なしでそれらを許可できます。今後のOpenデフォルトでは確認を求めますが、明示的なツールまたはカーネルのAllowによりそのデフォルトを変更できます。AI設定 → カーネル… → JavaScript → 確認により、この演習のJavaScript実行には確認が必要な状態が保たれます。ユーザー自身による手動のセルRunは引き続き別の操作です。次期リリースの実行制御の詳細は付録に記載されています。

    より多くの確認を希望する場合は、代わりに慎重を使用してください。Openは引き続き個別のソース閲覧および書き込みスコープの制御を尊重します。Full controlはこれら二つの大まかな制御をバイパスします。個別の権限やその他の安全対策も引き続き重要です。レビューは読み取り主体とする追加の制限であり、このセル作成のデモを妨げることになります。

    ブラウザサンドボックスが保護するもの、および保護しないもの

    通常のワークブックの実行はブラウザ／WebViewおよびその言語ランタイム内で実行され、スマートフォンのファイルへの無制限のアクセスではなく仮想ファイルシステムを使用します。これは有用な境界ですが、コードが悪影響を及ぼさない保証ではありません。許可されたJavaScriptおよびそこへのブリッジはアプリデータや保存された認証情報にアクセスできます。許可されたコードが開始されると、ネットワーク制限はベストエフォートとなり、機密情報を委ねるべき隔離境界ではありません。これから行う実行プロンプトは承認手順を追加するものであり、アプリのデータからの隔離ではありません。練習用ワークブックを使用し、その内容にはプライベートな情報を含めないようにしてください。

    リモート／MCPターミナルは異なります。ブラウザローカルのサンドボックス外にあるブローカーホスト上の実際のシェルを公開する可能性があります。ここではリモートとターミナルをオフのままにしてください。これらを有効にする前にリモートとセキュリティ (英語のリファレンスページ)を確認してください。プロンプトに丁寧な「…しないでください」と記述しても、セキュリティ制御にはなりません。

  2. アシスタントパネルで、 このワークブックを選択します。 レビュー, リモート、および ターミナル はこの直接プロバイダーの例ではオフのままにします。

ステップ 4 · 必要なときに代替案をリクエストする

API ベースの補完をリクエストする

  1. メニュー → 補完 を開き、セクション → AI 候補（オンライン） を選択します。AI候補 → タップ時 に設定します。
  2. そのプロバイダー、エンドポイント、モデルを継承するには、補完モデル： → AIアシスタントに従う のままにします。または プロバイダーとモデルを選ぶ を選択し、保存済みのプロバイダー／エンドポイントと、短い提案に適した低コストのモデルを選択します。この画面ではキーを入力しません。AIアシスタント設定を開く で最初に追加できます。
  3. このセクションの 詳細設定 を開いて、応答タイムアウトと利用額制限を確認します。デフォルトは 6 秒、$0.25／日、$5／月 です。上限を増やす前に価格を確認してください。
  4. JavaScript エディタに戻り、この練習用スニペットを入力します。 
    const values = [12, 15, 18];
const average =
    未完成の const average = 行の後にキャレットを残します。候補行の末尾にある … をタップするか、…AI エクストラキーを使用するか、Ctrl + Shift + Space を押します。
  5. 送信する前に、最初のリクエストの実際のペイロードと宛先を確認してください。AIチップには ✦ マーカーが付いています。タップして受け入れます。切り詰められたチップや複数行のチップは、最初にプレビューを開きます。Run の前に結果のソースを確認してください。

単なるAIチップではなく、コードを選択してください。 このリクエストでは、最初のチップが values.reduce((a, b) => a + b, 0) / values.length; を提案しました。タップして完全なプレビューを確認します。配列を合計してその長さで除算し、この例では 15 になります。二番目のチップは eval(values.join(' + ')) / values.length; を提案しました。その不要な eval の代替案を拒否してください。平均の計算で文字列を実行可能コードに変換する必要はありません。受け入れる前に返された独自のコードを確認し、レビュー後にのみ Run してください。

リクエストは最大五つの代替案を求めますが、画面に収まる数はそれより少ない場合があります。もう一度タップすると、まず受信済みの代替案が順に表示され、それらを使い果たすとさらにリクエストできます。リクエストの処理中にタップするとキャンセルされます。タイムアウトが切れるとそれ以降の返答は破棄され、入力したりキャレットを移動したりすると古い提案は無効になります。

独立とは独立を意味します：アシスタントのモデルを変更しても、個別の補完の選択肢は分離されたままになります。これは、高性能なエージェントを求めつつ安価なオートコンプリートを使用したい場合に役立ちます。アシスタントに従うと、そのアイデンティティが継承されますが、その会話やエージェントの権限は継承されません。

支払っている対象と送信している内容を把握する

オンライン補完はオンデマンドです。通常の入力では何も送信されません。このワークフローでは、入力中のプリフェッチはまだ利用できません。補完では制限された現在のセルコンテキストが送信されます。キャレットの前は最大1,500文字、後ろは200文字、ローカル名は最大12個までであり、アシスタントのチャットやワークブック全体は送信されません。シークレットのマスキングはベストエフォートであるため、ペイロードはご自身で確認してください。

常に許可はその送信先に対する恒久的な同意を付与します。プロバイダー、エンドポイント、またはモデルが変更された場合は、再度確認が行われます。確認せずに送信は最初にその選択肢を有効化しますが、実際の初回ペイロードは一度表示されます。学習中は毎回確認のままにしておいてください。

日／月ごとの金額は補完専用のソフトな支出制限ガードであり、プロバイダーの請求上限を保証するものではなく、アシスタントやAIプロンプトリクエストの予算でもありません。失敗やキャンセルによって予約された料金が維持される場合があります。支出履歴を消去しても上限合計はリセットされません。価格が記載されていないモデルには明示的な入力／出力の上限価格が必要であり、設定されていない場合アプリは送信を拒否します。

オプションのQwen2.5-Coder 0.5Bモデルは、テーブルでは判断がつかない場合にローカルでコードを提案します。これは小規模なコード補完モデルであり、対話型エージェントの代わりとなるものではありません。インストール後は、推論によって入力されたコードがプロバイダーに送信されることはなく、APIの料金も発生しません。

  1. ProがGoogle Playからインストールされている対象のAndroidスマートフォンで、メニュー → 補完 → セクション → ローカルモデル（端末上）を開きます。
  2. インストールをタップし、約400 MBのダウンロードに必要な時間とストレージを確保してください。現在サイドロードされたインストールでは、このフローを通じてモデルをダウンロードすることはできません。

どのスマートフォンが快適ですか？

最低要件は64ビットARM Androidおよび少なくとも4 GBのRAMですが、これはスムーズなパフォーマンスを保証するものではありません。Galaxy S24+クラスのスマートフォンが、実用面で快適な目安となります。SamsungはS24+向けに12 GBのRAMを記載しており、アプリ、カーネル、モデル用により多くの余裕を残しています。これは推奨されるパフォーマンス水準であり、そのモデルの購入を義務付けるものではありません。SamsungのS24シリーズ仕様。

Galaxy S10+には、対象となる8 GBまたは12 GBのバリエーションがあります。メンテナーの非公式な使用感としては、ローカル補完は動作するもののAPI補完より遅く感じられる場合があります。この比較はモデルやネットワークに依存します。記録されたローカルエンジンのベンチマークではS10+は測定されていません。そのため、これは実測された速度の比較ではなく、すべての端末に対する保証でもありません。大規模なワークブックやメモリを大量に消費するカーネルとモデルを組み合わせる場合は、遅延やアプリの応答停止に注意してください。SamsungのS10シリーズ仕様。

以前のS24+クラスのネイティブエンジンテストでは、ロード後のウォーム状態における最初の単語の中央値がおよそ0.10秒、コールド状態における最初の単語の中央値がおよそ0.24秒と測定されました。これらはベンチマーク結果の例であり、保証ではありません。キャッシュされていない初回ロードには数秒かかりました。ロードされたモデルは、約460〜490 MBのアプリプロセスメモリを追加しました。これは次のものに加えてです：WebView、Python/Rランタイム、およびオペレーティングシステム。

古いスマートフォンで動作が重くなった場合：ローカルモデルを使う → オフに設定し、代わりにテーブルまたはタップ時のみのAPI代替手段を使用してください。ローカルの詳細設定で、アプリを離れた後もロード状態を維持 → 0に設定すると、離脱時にモデルが解放されます。アイドル時アンロードや低バッテリー制御も役立ちます。トラブルシューティングを行う前にワークブックを保存またはエクスポートしてください。API費用ゼロのモデルであっても、ストレージ、メモリ、バッテリーは消費します。

正常に動作しない場合

スマートフォンでオフライン候補が表示されない
「一般」→「ローカルコード補完」で「自動」ではなく「オン」を選択します。チップ、キャレット位置、言語、およびオプション行に空きがあるかどうかを確認してください。
オンラインリクエストが送信されない
「タップ時」、対象プロバイダー／エンドポイントの保存されたキー、選択したモデルの価格エントリまたは上限、同意状況、および支出合計を確認してください。補完には「開く」は必要ありません。安全なブラウザコンテキストとWeb Locksが必要です。サポートされていないコンテキストではリクエストが拒否されます。
アシスタントがセルを実行する前に確認する、または確認しない
アプリのバージョン、「セキュリティ…」の実行権限、および「カーネル…」のルールを確認してください。今後提供される「開く」のデフォルトは「確認」です。Pro 1.4.0のデフォルトでは実行を許可できる場合があります。「自動実行オフ」は実行ツールの「拒否」ではありません。オンライン補完の「常に許可」はセルの実行権限を付与しません。実行の承認を参照してください。
補完が別のセルを認識しない
オンライン代替候補はノートブック全体ではなく、現在のセルの限定されたコンテキストを使用します。より広範な説明が必要な場合は、明示的にソースを選択したAIプロンプト、またはアシスタントを使用してください。
インストールを利用できない場合
ネイティブのローカルモデルのフローは、対象となるAndroidのGoogle Playインストール向けであり、デスクトップ/ブラウザや現在のサイドロード配信向けではありません。最小RAM要件を満たしていても、速度は保証されません。
生成された回答がもっともらしく見えるが誤っている場合
既知の小さな例と比較してください。実行する前に、インポート、単位、空の入力時の動作、および副作用を確認してください。モデルの応答は正しさの証明ではありません。

  • 名前空間の検査および新しく作成されたセルのプロンプトは、そのような恒久的な許可を作成することはできません。作成されたセルの実行プロンプトには制限付きのコードプレビューが含まれ、長いプレビューの末尾には省略記号が表示されます。省略されている場合は、Cancelを選択し、新しく作成されたセルの完全なソースを確認した上で、信頼できる場合にのみご自身でRunを実行してください。以前に保存された実行のAllowは、Auto-runがオンになっている場合に作成されたセルの自動実行を引き続き許可する可能性があるため、ここではAuto-runをオフのままにしてください。
  • 保存された実行ツールのAllowが有効なままFull control以外のプリセットを選択すると、警告によりデフォルトに戻す、「許可」を維持、またはキャンセルが提示されます。Resetは、カーネルのオーバーライドをクリアすることなく、選択したプリセットのツールルールを復元します。Keepはオーバーライドを保持します。Cancelは以前のプリセット選択を復元します。ResetおよびKeepは、Settingsを保存するまで下書きの変更のままとなります。

実行の承認は、データを共有するための包括的な許可ではありません。 実行ツールの出力はAssistantのモデルに返される可能性があり、許可されたコードはネットワークを使用できます。オンライン補完の常に許可、AI Promptのコンテキスト確認、およびRemote/MCPのプライバシー開示は別個のままです。MCPノートブックの実行でも同じ実行チェックが使用されます。これらのチェックはブローカーのTerminalシェルをサンドボックス化するものではありません。

付録 · 計画中のワークブックのコンテキストと履歴

設計提案のみ：これらの機能は実装されておらず、リリースも割り当てられていません。これらは上記の今後提供される実行承認の変更とは別個のものであり、現在のリリースをブロックするものではありません。

  • 必要なときにワークブックの概要を取得します。 この計画では、繰り返される自動ソースプレビューを、セル名、オプションの説明、言語、タイプ、およびワークブックのリビジョンを含むメタデータのみのディレクトリツールに置き換えます。提案されているツールはlist_cells（view: "metadata"付き）であり、Assistantは選択されたソースを別途読み取ります。これは範囲が限定された概要であり、自動生成されたAIの説明ではありません。
  • 送信ごとではなく一度だけ添付します。 提案されている今回はワークブックの概要を添付チェックボックスは、新しい会話ではチェックされた状態で開始し、その添付ファイルが実際に送信された後にチェックが外れるようにすることができます。送信前にチェックを外すことも、新しい概要を取得するために再度チェックを入れることも可能です。その初期デフォルトについては、プライバシーと使いやすさのレビューが引き続き必要です。会話を継続しても別の概要が追加されることはなく、タブを切り替えてもサイレントに再度有効化されることはありません。プレビューおよび既存の読み取り/プライバシー権限は引き続き適用され、大規模なワークブックでは追加のページが必要になる場合があります。
  • チェックを外しても履歴は消去されません。 これにより新しい自動添付は停止されますが、すでに会話内にある概要が削除されたり、許可されたツールの読み取りが妨げられたりすることはありません。既存のフルスクリーンのAgent、AI Prompt、および補完のコンテキストコントロールは、引き続き別個のものとして維持されます。
  • 送信間の変更の差分は将来のオプションです。 コンパクトな更新には、既知の送信済みコンテキストのベースラインと信頼性の高いリビジョンが必要になります。人間の編集を強調表示することは可能ですが、エージェントによる編集、インポート、未知の変更も重要です。ソースの編集によってセルの説明が自動的に書き換えられることはありません。履歴が欠落しているか古い場合は、推測による更新ではなく、新しい概要が必要になります。
  • オプションのローカル履歴とGitHub同期は、より長期的なProのアイデアです。 ローカルの送信チェックポイントは、何も共有することなくGitベースのdiffをサポートできます。独立した同期により、独自のペイロードプレビューと認証を使用して、ワークブックをGistまたはリポジトリ内の選択したファイルに公開できます。履歴を有効にしても、GitHubにプッシュされたり、AIにdiffが送信されたりすることはありません。Gitはコンテンツの変更を示すものであり、人間がそれを作成したことの証明ではありません。

シークレットGistは非公開ではありません。 そのURLを知っている人なら誰でも閲覧できます。アクセスを制限する必要がある場合は、プライベートリポジトリを使用してください。公開する前に、ワークブックのソースや説明にシークレットを含めないようにしてください。GitHubのGistの可視性に関するドキュメント。
