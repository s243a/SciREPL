De sugestões offline à programação assistida por IA

Comece com sugestões rápidas baseadas em tabelas que não custam nada por solicitação. Em seguida, configure o Assistente, solicite alternativas online, experimente um modelo no dispositivo e finalize com células de Prompt de IA focadas que explicam seu código.

  • Apenas Pro
  • Pro 1.4.0 + próximos controles de execução
  • Modelo local: Android

A maioria das capturas de tela mostra o aplicativo Android; algumas são capturas do navegador. Os layouts podem variar de acordo com a versão do seu aplicativo.

Verifique sua versão. As alterações de execução no apêndice estão planejadas para o proposto Pro 1.5.0, que não foi lançado; o número final da versão pode mudar.

“Free” aqui significa nenhuma cobrança de API. As sugestões de tabela e o modelo no dispositivo não cobram de um provedor. Isso não faz com que sejam recursos da edição Free: este passo a passo é para o SciREPL Pro. As solicitações online usam sua própria conta de provedor e podem custar dinheiro.

Etapa 1 · Nenhuma chave de API necessária

Comece com sugestões de tabela offline

Localize ☰ Menu no cabeçalho do aplicativo: é o botão com três linhas horizontais. Abra Autocompletar. Seu seletor de Seção separa Geral, Sugestões de IA (online) e Modelo local (no dispositivo). Comece com General.

  1. Defina Conclusão local de código → Ativado. Caso contrário, o padrão Automático (ativado no computador, desativado no toque) o deixaria desativado em um telefone.
  2. Defina Chips de sugestão → Ativado e mantenha Sugestões → Na posição do cursor. Para isolar as tabelas, defina Sugestões de IA → Desativada na seção online e Usar o modelo local → Desativada na seção local, se algum deles tiver sido ativado anteriormente. Retorne para General.
  1. Feche Completion. Em uma nova pasta de trabalho prática, escolha uma célula de código e o idioma JavaScript. Digite cons, com o cursor no final e sem seleção. Essas primeiras letras de const são chamadas de prefixo. Procure por const.
  2. Na captura de tela abaixo, cons é seguido por um t fraco—texto fantasma em linha. Toque em Aceitar ou pressione Tab para inserir a sugestão, resultando em const. Se um chip const aparecer em vez disso, tocar nele é outra maneira de aceitar esse candidato. Termine a linha você mesmo, por exemplo const values = [12, 15, 18];.

Accept não é Run. Aceitar uma sugestão edita o código-fonte; não executa a célula. Os exemplos em JavaScript e Python nesta seção demonstram o preenchimento automático durante a edição. A execução dessas células de prática não faz parte desta seção. Com apenas a camada de tabela offline ativada, digitar um prefixo não envia uma solicitação de API nem inicia um ambiente de execução de linguagem apenas para fazer sugestões.

Pré-busca online futura: um modo opcional está planejado para enviar solicitações de modelo enquanto você digita. Ele ainda não está disponível e nenhum número de lançamento foi atribuído a ele. A declaração de ausência de solicitações acima descreve a camada atual de tabela offline, não este modo futuro.

Veja as duas exibições offline em um telefone. Deixe Chips de sugestão → Ativado, escolha Python e digite pri. O nt esmaecido após o cursor oferece print; ele não faz parte do seu código-fonte até que você o aceite. Você não precisa desativar os chips para ver o texto fantasma. Um único candidato pode aparecer como texto fantasma, enquanto os chips oferecem uma escolha quando vários candidatos se encaixam. Mantenha Sugestões de IA e Usar o modelo local desativados para ambos os exemplos.

Com os chips ainda Ativado, substitua a entrada de prática por estas três linhas, deixando o cursor após o sample_m inacabado. A linha oferece sample_mean e sample_median a partir de nomes do seu próprio código-fonte. Toque em um chip para escolher um candidato; ao contrário do texto fantasma, a linha mostra alternativas.

sample_mean = 0
sample_median = 0
sample_m

A linha de teclas extras visível nas imagens do telefone em Python e as cores de sintaxe ao digitar são controles opcionais e separados do Pro. Consulte Guia de aparência: teclas extras e cores de sintaxe para ativar ou desativar qualquer um deles e para encontrar a caixa de seleção de realce separada do editor de arquivos.

Depois de testar essas exibições de conclusão, volte para JavaScript e deixe os chips ativados durante o restante da lição.

Os chips offline mostrados aqui, ativados em Autocompletar → Geral → Chips de sugestão, combinam tabelas de nomes selecionadas com informações locais do código. Em Python, isso inclui variáveis e funções encontradas no código do caderno de exercícios, além de nomes do kernel em cache e atributos de objetos, incluindo métodos. A frequência e o histórico de aceitação ajudam a classificá-los. Outras linguagens têm coberturas diferentes: listas estáticas, definições não executadas ou instantâneos desatualizados podem sugerir um nome que não está disponível no escopo no momento. A conclusão baseada em tabela não é um modelo de linguagem e não raciocina sobre sua tarefa.

Somente no fim da célula é uma alternativa se sugestões no meio da célula distraírem você. Uma seleção, cadeia de caracteres, comentário ou nome dividido ao meio pode intencionalmente não produzir sugestões. No modo paisagem curto, linhas opcionais podem desaparecer para manter espaço para o código; consulte Configurações de aparência.

Etapa 2 · Configuração online

Salvar uma chave de API

Uma chave de API permite que o SciREPL use uma conta de provedor que você controla. Obtenha a chave desse provedor, verifique seus preços atuais e limites de conta, e use apenas uma pequena pasta de trabalho prática com dados não privados para esta lição.

  1. Abra Menu → 🤖 Assistente de IA (Pro). No painel, toque na ⚙ engrenagem para abrir as Configurações de IA.

    Não consegue ver a engrenagem? O teclado pode deslocar ou rolar o painel do Assistente. Arraste o conteúdo do painel para baixo para rolar de volta para o topo e revelar a engrenagem; fechar o teclado também pode liberar mais espaço.

  2. Defina Configurar modelo para → Assistente de IA. Escolha um Backend (por exemplo, OpenRouter) e Modelo, e verifique o endpoint se o seu back-end usar um configurável.
  3. Insira a Chave de API correspondente. Use Chaves salvas para gerenciar chaves de outros pares de provedor/endpoint. Uma chave para um destino não serve automaticamente para outro.
  4. Toque em Salvar. Apenas salvar as configurações não faz uma solicitação ao modelo. Mantenha o painel aberto para a próxima etapa.

Mantenha a chave fora da pasta de trabalho. Não a cole em uma célula, prompt, captura de tela ou arquivo exportado. As chaves salvas permanecem no armazenamento local do aplicativo/navegador, sem criptografia no nível do aplicativo; proteja o dispositivo e não execute código não confiável. A política de privacidade do Pro explica o que é armazenado e enviado.

Um modelo de baixo custo e compatível com ferramentas é um ponto de partida sensato para o Assistente. Exemplos para comparar incluem GLM 5.3 Flash, GPT-6 Luna, Claude Haiku 5.5 e DeepSeek V4 Flash. Os IDs exatos dos modelos, versões disponíveis, suporte a ferramentas e preços dependem da versão do seu aplicativo e do provedor; consulte o seletor atual e a documentação do provedor. Um modelo recém-anunciado pode exigir uma atualização do aplicativo antes de aparecer. Mais tarde, você poderá escolher um modelo econômico diferente apenas para conclusões.

O modelo não está na lista? Em Configurações de IA → Configurar modelo para → Assistente de IA, escolha primeiro o Backend correto, depois insira o ID exato de modelo da API do provedor em Ou insira o ID de modelo personalizado, abaixo do seletor Modelo, e toque em Salvar. Este campo já está disponível no Pro 1.4.0.

Verifique o ID com o provedor selecionado, não apenas o nome comercial do modelo. Para o OpenRouter, inclua o prefixo da organização — por exemplo, anthropic/claude-haiku-5.5 em sua página de modelo. Insira o ID, não a URL dessa página. O ID personalizado tem precedência sobre o menu suspenso; escolher novamente um modelo listado limpa o campo personalizado.

Um ID não adiciona suporte a API. O modelo deve oferecer suporte a chamadas de ferramentas por meio da API que o SciREPL usa. Verifique o acesso ao provedor, a compatibilidade e os preços atuais; salvar não os valida nem faz uma solicitação ao modelo.

Etapa 3 · Uso deliberado de ferramentas

Crie um pequeno exemplo com a predefinição de agente Open

O Aberto é a segunda predefinição de segurança mais permissiva, depois de Controle total. Ele permite edições no caderno por padrão, com menos avisos do que o Cautious. Se a execução solicita confirmação depende da sua versão e das configurações de permissão; consulte o apêndice de aprovação de execução planejado. Use-o deliberadamente em uma pasta de trabalho prática — não como um requisito para o preenchimento automático.

  1. Nas Configurações de IA, selecione Nível de segurança → Open e Gravações do agente → Planilha ativa. Deixe a navegação de código-fonte desativada e desative Executar automaticamente células criadas por IA. Em Kernels…, defina JavaScript → Perguntar, depois salve. Esta regra de kernel ainda solicita confirmação mesmo se um Permitir de ferramenta de execução tiver sido salvo anteriormente.

    Desativar a execução automática não é um bloqueio de execução. Isso impede que células recém-criadas sejam executadas automaticamente; não desativa solicitações separadas de execute_cell ou run_cells. O padrão Open do Pro 1.4.0 lançado pode permiti-las sem perguntar. O próximo padrão Open perguntará, mas uma permissão explícita de ferramenta ou kernel pode alterar esse padrão. Configurações de IA → Kernels… → JavaScript → Perguntar mantém a execução de JavaScript deste exercício mediante confirmação. Sua própria execução manual de célula permanece uma ação separada. Os controles de execução da próxima versão são detalhados no apêndice.

    Se você preferir mais confirmações, use Cauteloso. O Open ainda respeita os controles separados de navegação no código-fonte e escopo de gravação; o Full control ignora esses dois controles amplos. As permissões individuais e outras barreiras de segurança ainda são importantes. O Revisão é uma restrição adicional prioritariamente de leitura, o que prejudicaria esta demonstração de criação de células.

    O que o sandbox do navegador protege — e o que não protege

    A execução normal da pasta de trabalho ocorre no navegador/WebView e em seus ambientes de execução de linguagem, com um sistema de arquivos virtual em vez de acesso irrestrito aos arquivos do seu telefone. Esse é um limite útil, não uma garantia de que o código não possa causar danos. O JavaScript permitido e as pontes para ele podem alcançar dados do aplicativo e credenciais salvas; as restrições de rede funcionam com base no melhor esforço quando o código permitido é iniciado, e não como um limite de isolamento em que você deva confiar para dados confidenciais. A futura solicitação de execução adiciona uma etapa de aprovação, não isolamento em relação aos dados do aplicativo. Use uma pasta de trabalho prática e mantenha seu conteúdo não privado.

    O Terminal Remoto/MCP é diferente: ele pode expor um shell real no host intermediário, fora do sandbox local do navegador. Mantenha Remoto e Terminal desativados aqui. Consulte Remoto e segurança (Página de referência em inglês) antes de ativá-los. Um educado “não…” no prompt não é um controle de segurança.

  2. No painel do Assistente, escolha Esta pasta de trabalho. Deixe Revisão, Remoto, e Terminal desativados para este exemplo de provedor direto.
  3. Envie o prompt de prática no destaque abaixo. O botão Enviar do painel já inicia o loop de ferramentas do agente: não há nenhuma alternância extra de “Modo agente” aqui. O botão Agente do editor em tela cheia é um fluxo de trabalho separado.

A semente fixa a sequência, portanto essa entrada de aparência aleatória é reproduzível. Com a regra de atualização antes do sorteio acima, espere:

Os rótulos de saída podem diferir, mas os números devem coincidir. Executar a célula novamente deve produzir a mesma entrada e resumos. Uma semente diferente altera o exercício; este gerador pequeno serve para uma demonstração reproduzível, não para aleatoriedade sensível à segurança.

Antes de Enviar: o Assistente inclui a conversa selecionada e uma prévia limitada das células da pasta de trabalho atual (até os primeiros 500 caracteres de cada célula, mais metadados). Isso é diferente da carga útil menor da célula atual usada pelo preenchimento abaixo. As alterações planejadas para o contexto da pasta de trabalho estão descritas no apêndice.

Pausado com um botão Continuar? Limites do agente (por execução) → Máximo de passos, destacado abaixo, controla o limite de etapas para uma execução restrita. O agente pode atingir esse limite antes de terminar. Leia o que ele já fez e pressione Continuar se a tarefa não estiver concluída e você desejar outra execução restrita. Continuar pode gerar mais cobranças de API; isso não é necessário após Concluir.

Etapa 4 · Solicite alternativas quando desejar

Solicite preenchimentos baseados em API

  1. Abra Menu → Autocompletar e depois escolha Seção → Sugestões de IA (online). Defina Sugestões de IA → Ao tocar.
  2. Mantenha Modelo para autocompletar → Seguir o Assistente de IA para herdar o provedor, o endpoint e o modelo dele. Ou escolha Escolher provedor e modelo, selecione um provedor/endpoint salvo e um modelo de baixo custo adequado para sugestões curtas. Nenhuma chave é inserida nesta tela; Abrir Configurações de IA permite adicionar uma primeiro.
  3. Abra Avançado desta seção para inspecionar o tempo limite de resposta e as proteções de gastos. Os padrões são 6 segundos, $0.25/dia e $5/mês. Verifique os preços antes de aumentá-los.
  4. Retorne a um editor JavaScript e insira este trecho de prática: 
    const values = [12, 15, 18];
const average =
    Deixe o cursor após a linha const average = inacabada. Toque em … no final da linha de sugestões, use a tecla extra …AI ou pressione Ctrl + Shift + Space.
  5. Revise o payload real da primeira solicitação e o destino antes de enviá-la. Os chips de IA contêm um marcador ✦. Toque em um para aceitá-lo; um chip truncado ou de várias linhas abre uma prévia primeiro. Revise o código-fonte resultante antes de executar.

Escolha o código, não apenas um chip de IA. Nesta solicitação, o primeiro chip propôs values.reduce((a, b) => a + b, 0) / values.length;. Toque nele para inspecionar a prévia completa: ele soma o array e o divide pelo seu comprimento, resultando em 15 para este exemplo. O segundo propôs eval(values.join(' + ')) / values.length;. Rejeite essa alternativa desnecessária com eval: calcular uma média não precisa transformar uma cadeia de caracteres em código executável. Verifique o código retornado antes de aceitá-lo e execute apenas após a revisão.

A solicitação pede até cinco alternativas, mas a tela pode comportar menos. Outro toque primeiro percorre as alternativas já recebidas; depois que elas se esgotarem, é possível solicitar mais. Toque enquanto a solicitação está em andamento para cancelá-la. Respostas posteriores são descartadas quando o tempo limite expira, e digitar ou mover o cursor torna as sugestões antigas obsoletas.

Independente significa independente: uma escolha de preenchimento separada permanece separada quando você altera o modelo do Assistente. Isso é útil quando você deseja um agente com boa capacidade, mas um preenchimento automático econômico. Seguir o Assistente herda sua identidade, não sua conversa ou permissões de agente.

Saiba pelo que você está pagando e o que está enviando

O preenchimento online funciona sob demanda: a digitação comum não envia nada. A opção Pré-busca enquanto digito ainda não está disponível neste fluxo de trabalho. O preenchimento envia um contexto delimitado da célula atual: no máximo 1,500 caracteres antes do cursor, 200 depois dele e até 12 nomes locais — não o chat do Assistente nem a pasta de trabalho inteira. O mascaramento de segredos funciona com base no melhor esforço, portanto revise o payload você mesmo.

Sempre permitir concede consentimento permanente para esse destino; uma alteração de provedor, endpoint ou modelo solicita confirmação novamente. Enviar sem perguntar ativa inicialmente essa escolha, mas ainda exibe o primeiro payload real uma vez. Mantenha Perguntar sempre enquanto estiver aprendendo.

Os valores diários/mensais são proteções flexíveis de gastos apenas para preenchimento, não limites de faturamento garantidos pelo provedor e não o orçamento para solicitações do Assistente ou de Prompt de IA. Falhas e cancelamentos podem reter a cobrança reservada. Limpar o histórico de gastos não redefine os totais dos limites. Um modelo sem preço listado precisa de limites explícitos de preço de entrada/saída, caso contrário o aplicativo se recusará a enviar.

Etapa 5 · Download opcional no Android

Experimente o modelo no dispositivo

O modelo opcional Qwen2.5-Coder 0.5B sugere código localmente quando as tabelas estão incertas. É um modelo pequeno de preenchimento de código, não um substituto para o agente conversacional. Uma vez instalado, a inferência não envia nenhum código digitado para um provedor e não tem custo de API.

  1. Em um telefone Android qualificado com o Pro instalado a partir do Google Play, abra Menu → Autocompletar → Seção → Modelo local (no dispositivo).
  2. Toque em Instalar e reserve tempo e armazenamento para o download de aproximadamente 400 MB. As instalações atuais feitas por sideload não podem baixar o modelo por este fluxo.
  3. Quando estiver pronto, mantenha Usar o modelo local → Quando houver dúvida. As tabelas atendem aos casos fáceis; o modelo contribui quando elas estão incertas. Sempre o executa com mais frequência; Desativada o interrompe sem excluir o download.
  1. Retorne a uma célula de código e faça uma pausa em um nome ou linha inacabada. Os resultados variam com o contexto; nem toda pausa produz uma sugestão. Aceite um texto fantasma ou chip apropriado, inspecione o código-fonte e execute separadamente.

Qual telefone oferece uma experiência confortável?

A elegibilidade mínima é um Android ARM de 64 bits com pelo menos 4 GB de RAM, o que não é garantia de desempenho fluido. Um telefone da classe do Galaxy S24+ é uma meta prática de conforto: a Samsung lista 12 GB de RAM para o S24+, deixando mais margem livre para o aplicativo, os kernels e o modelo. Esse é um nível de desempenho recomendado, não uma exigência para comprar esse modelo. Especificações da série S24 da Samsung.

Um Galaxy S10+ possui variantes elegíveis de 8 GB ou 12 GB. A experiência informal do mantenedor é de que o preenchimento local pode funcionar nele, mas parecer mais lento do que o preenchimento via API; a comparação depende do modelo e da rede. O benchmark registrado do mecanismo local não mediu o S10+, portanto esta não é uma comparação medida de velocidade nem uma garantia para todos os aparelhos. Fique atento a lentidão ou a um aplicativo sem resposta ao combinar o modelo com pastas de trabalho grandes e kernels que consomem muita memória. Especificações da série S10 da Samsung.

O teste anterior do mecanismo nativo na classe do S24+ mediu uma mediana de primeira palavra a quente em torno de 0.10 segundos e uma mediana de primeira palavra a frio em torno de 0.24 segundos, após o carregamento. Estes são resultados de benchmark de amostra, não garantias: um carregamento inicial não armazenado em cache levou vários segundos. O modelo carregado adicionou cerca de 460–490 MB de memória ao processo do aplicativo, além do WebView, dos ambientes de execução de Python/R e do sistema operacional.

Se um telefone mais antigo ficar lento: defina Usar o modelo local → Desativada e use tabelas ou alternativas com API sob toque. Em Avançado local, definir Manter carregado após sair do aplicativo → 0 libera-o quando você sai; os controles de descarregamento por ociosidade e bateria fraca também ajudam. Salve/exporte sua pasta de trabalho antes de solucionar problemas. Um modelo sem custo de API ainda consome armazenamento, memória e bateria.

Etapa 6 · Entenda o código enquanto o constrói

Finalize com uma célula de Prompt de IA focada

O Assistente é útil para trabalhos em várias etapas. Uma célula de Prompt de IA é melhor para uma pergunta pequena e repetível sobre um trecho específico de código: ela faz uma solicitação isolada, sem histórico do Assistente ou ferramentas. Use-a para perguntar por que um cálculo funciona antes de estendê-lo.

Aqui retornamos à célula da Etapa 3 com o summary_demo aleatório baseado em semente. Pedimos uma explicação desse cálculo existente — não outro array aleatório, e não o exemplo de preenchimento apenas com a média da Etapa 4.

  1. Adicione uma célula de Prompt de IA imediatamente após a célula da Etapa 3 de summary_demo JavaScript — não o trecho apenas com a média da Etapa 4 — para que a pergunta abaixo corresponda ao código-fonte selecionado. Mantenha o tipo de célula como código, depois escolha Prompt de IA no menu suspenso de idioma/modo. Se estiver ausente, ative-o em Menu → Linguagens e modos.
  2. Cole o prompt abaixo na célula de Prompt de IA, não na caixa de mensagem do Assistente. Abra o controle Configurar dela. 
    Explique a célula JavaScript selecionada linha por linha.
Como a regra do gerador e a semente 42 determinam seu array de entrada?
Por que ela deve relatar contagem 10, média 9.3, mínimo 1 e máximo 20?
Por que redefinir a semente torna o resultado repetível?
Explique o que precisa ser alterado para um array vazio.
Retorne apenas uma explicação curta; não reescreva o código.
  3. Defina Colocar resposta final em → Saída desta célula, o padrão. Em Contexto a enviar → Incluir código-fonte de, escolha 1 célula anterior. Desmarque Incluir texto de saída salvo para este exercício exclusivo de código-fonte. Verifique se Prévia do contexto identifica summary_demo, depois role para baixo e toque em Salvar configuração.
  4. Toque no Executar da célula de Prompt de IA. Verifique o contexto selecionado na revisão e escolha Enviar ao provedor de IA. Leia a explicação ao lado do código-fonte e compare-a com os resultados conhecidos.

Uma forma de controlar custos de API e melhorar o entendimento. Um Prompt de IA focado pode enviar menos contexto do que uma conversa crescente com o agente e evitar um loop de ferramentas em várias etapas, reduzindo os tokens de entrada e potencialmente a conta. Peça raciocínio conciso, premissas e saída esperada enquanto programa. A economia não é garantida: as tarifas do modelo, o comprimento da resposta, os tokens de raciocínio e o contexto escolhido continuam sendo importantes. Essas solicitações usam o provedor/modelo do Assistente, não o modelo de preenchimento independente, e estão fora das proteções de gastos de preenchimento.

Outro exemplo · Revise um gráfico antes de substituir uma célula

Agora peça a um Prompt de IA para escrever código em uma célula diferente, com uma revisão antes que qualquer coisa seja substituída. Plotaremos como a variância estimada muda em muitas amostras pequenas. Estas são novas amostras normais — não o array de inteiros summary_demo anterior. O objetivo é aprender Configurar → prévia → Aplicar → Executar, não dominar a estatística.

Variância não é o t de Student. Para amostras normais independentes de tamanho 10, 9s² / σ² segue uma distribuição qui-quadrado com 9 graus de liberdade. Aqui, a variância real σ² = 1. O t de Student, em vez disso, descreve a média amostral padronizada (mean − μ) / (s / √10), usando o desvio padrão estimado s; ele também tem 9 graus de liberdade aqui. NIST: variância · NIST: média.

Se algo não funcionar

Nenhuma sugestão offline no telefone
Escolha General → Local code completion → On em vez de Auto. Verifique os chips, a posição do cursor, o idioma e se a linha opcional tem espaço.
Nenhuma solicitação online
Verifique On tap, a chave salva para o par provedor/endpoint exato, a entrada de preço ou limites máximos do modelo selecionado, o consentimento e os totais de gastos. Open não é obrigatório para preenchimento. Um contexto seguro de navegador e Web Locks são necessários; contextos não compatíveis recusam solicitações.
O Assistente pergunta antes de executar uma célula — ou não pergunta
Verifique a versão do seu aplicativo, as permissões de execução em Security… e as regras de Kernels…. O próximo padrão Open é Ask; o padrão do Pro 1.4.0 pode permitir a execução. Desativar a execução automática não é um Deny da ferramenta de execução. O Always allow do preenchimento online não concede permissão de execução de células; consulte aprovação de execução.
O preenchimento não compreende outra célula
As alternativas online usam o contexto delimitado da célula atual, não o caderno inteiro. Use um Prompt de IA com código-fonte explicitamente selecionado ou o Assistente quando precisar de uma explicação mais ampla.
Install não está disponível
O fluxo nativo de modelo local é para instalações qualificadas do Android pelo Google Play, não para desktop/navegador ou distribuição atual por sideload. Atender ao requisito mínimo de RAM não garante velocidade.
A resposta gerada parece plausível, mas incorreta
Compare-a com exemplos pequenos e conhecidos. Verifique importações, unidades, comportamento com entrada vazia e efeitos colaterais antes de executar. A resposta de um modelo não é prova de exatidão.

Apêndice · Aprovação futura de execução · proposto Pro 1.5.0

Não lançado: estes controles descrevem a implementação da próxima versão, não uma garantia de que sua instalação do 1.4.0 os possua. O número da versão é provisório.

  • Configurações de IA → Segurança… → execute_cell / run_cells já oferece Default / Allow / Ask / Deny. Esta atualização altera o Default herdado do Open para Perguntar; o Full control mantém Allow. Regras explícitas de ferramenta ou kernel podem substituir padrões herdados; quando ambas são explícitas, a regra mais segura prevalece. Deixe Default ou Ask enquanto estiver aprendendo. Allow é uma substituição de preferência, não um sandbox mais robusto; Ask/Deny do kernel, Review e a desativação global de JavaScript ainda se aplicam.
  • Leia a solicitação de execução antes de escolher Executar; deixe Permitir a execução futura de células do Assistente sem perguntar desmarcado para aprovar apenas essa solicitação. Marcá-lo altera a regra compartilhada da ferramenta de execução em todas as pastas de trabalho até ser redefinida — não apenas nesta célula, conversa ou provedor. Um Ask explícito do kernel oculta essa opção.
  • Prompts de inspeção de namespace e de células recém-criadas não podem criar essa concessão permanente. Um prompt de execução de célula criada inclui uma prévia delimitada de código; uma prévia longa termina com reticências. Se estiver truncada, escolha Cancel, inspecione o código-fonte completo da célula recém-criada e execute-a você mesmo apenas se confiar nela. Uma permissão Allow de execução salva anteriormente ainda pode permitir a execução automática de células criadas quando Auto-run está ativado, portanto mantenha Auto-run desativado aqui.
  • Se você selecionar uma predefinição diferente de Full control enquanto um Allow da ferramenta de execução salvo permanecer em vigor, um aviso oferecerá Restaurar para o padrão, Manter Permitir ou Cancelar. Reset restaura a regra de ferramenta da predefinição selecionada sem limpar as substituições do kernel. Keep mantém a substituição. Cancel restaura a seleção anterior da predefinição. Reset e Keep permanecem alterações de rascunho até que você salve as Configurações.

A aprovação de execução não é uma permissão ampla para compartilhar dados. As saídas das ferramentas de execução podem retornar ao modelo do Assistente, e o código permitido pode usar recursos de rede. O Sempre permitir do preenchimento online, a revisão de contexto do Prompt de IA e a divulgação de privacidade de Remoto/MCP permanecem separados. A execução de cadernos via MCP usa as mesmas verificações de execução; essas verificações não colocam em sandbox o shell do Terminal de um intermediário.

Apêndice · Contexto e histórico planejados da pasta de trabalho

Apenas proposta de design: estes recursos não estão implementados nem atribuídos a uma versão. Eles são separados das alterações de aprovação de execução futuras acima e não bloqueiam a versão atual.

  • Buscar um resumo da pasta de trabalho quando necessário. O plano substitui prévias automáticas repetidas do código-fonte por uma ferramenta de diretório apenas de metadados: nomes de células, descrições opcionais, idiomas e tipos, além de uma revisão da pasta de trabalho. A ferramenta proposta é list_cells com view: "metadata"; o Assistente leria o código-fonte selecionado separadamente. Esta é uma visão geral delimitada, não uma explicação de IA gerada automaticamente.
  • Anexar uma vez em vez de a cada envio. Uma caixa de seleção proposta Anexar resumo da pasta de trabalho desta vez poderia iniciar marcada para uma conversa nova e ser desmarcada após esse anexo ser efetivamente enviado. Você poderia desmarcá-la antes de enviar ou marcá-la novamente para uma nova visão geral. Seu padrão inicial ainda precisa de revisão de privacidade e usabilidade. Continuações não adicionariam outro resumo, e alternar de guia não a reativaria silenciosamente. A prévia e as permissões existentes de leitura/privacidade ainda se aplicariam; uma pasta de trabalho grande poderia exigir páginas adicionais.
  • Desmarcado não apaga o histórico. Isso impediria um novo anexo automático, sem remover os resumos já presentes na conversa ou impedir leituras permitidas por ferramentas. Os controles de contexto existentes do Agente em tela cheia, do Prompt de IA e do preenchimento permaneceriam separados.
  • Alterações entre envios são uma opção futura. Atualizações compactas precisariam de uma linha de base conhecida do contexto enviado e de revisões confiáveis. Edições humanas poderiam ser destacadas, mas edições do agente, importações e alterações desconhecidas também são importantes. Uma edição no código-fonte não reescreveria automaticamente a descrição de uma célula; um histórico ausente ou desatualizado exigiria uma visão geral nova em vez de uma atualização presumida.
  • O histórico local opcional e a sincronização com o GitHub são ideias de longo prazo para o Pro. Pontos de controle de envio locais poderiam dar suporte a diffs baseados em Git sem compartilhar nada. A sincronização independente poderia publicar uma pasta de trabalho em um Gist ou em um arquivo escolhido em um repositório, com sua própria prévia de payload e autorização. Ativar o histórico não faria push para o GitHub nem enviaria um diff para a IA. O Git mostra alterações de conteúdo, não provas de que um ser humano as realizou.

Um Gist secreto não é privado. Qualquer pessoa com sua URL pode lê-lo; use um repositório privado quando o acesso precisar ser restrito. Mantenha dados confidenciais fora do código-fonte e das descrições da pasta de trabalho antes de publicar. Documentação de visibilidade de Gists do GitHub.
