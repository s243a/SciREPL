Aprenda na prática

Adicionar imagens, diagramas e equações

Um caderno pode explicar uma ideia tanto com uma imagem quanto com código. Experimente três maneiras de mostrar o mesmo sistema de coordenadas simples: uma imagem estática em Markdown, uma figura desenhada por JavaScript e uma equação formatada com KaTeX. Você não precisa de Python, R, instalação de pacotes ou uma conta de IA.

  • Fluxo de trabalho Free + Pro
  • Exemplos verificados no navegador
  • Cerca de 10 minutos

Os exemplos e capturas de tela foram verificados na versão para navegador do SciREPL Free em 6 de outubro de 2026. As capturas de tela usam uma janela de visualização estreita do navegador; elas não são capturas do Android. Os mesmos controles são usados no Android, mas sua posição pode ser diferente. O Pro e todas as versões lançadas do aplicativo não foram testados para este guia.

Todos os tutoriais

Passo 1

Abra o caderno de exemplo

O arquivo complementar contém os exemplos completos, incluindo um PNG incorporado. Ele mantém tudo em um pequeno caderno para que você não precise digitar uma longa sequência de caracteres de imagem em Base64.

  1. Baixe o caderno de exemplo de gráficos (.srwb). Salve o arquivo real, mantendo sua extensão .srwb. Se o seu navegador exibir texto, use a ação de salvar/baixar dele. Anote a pasta em que você o salvou.
  2. Abra o SciREPL. No cabeçalho na parte superior do aplicativo, localize ☰ Menu, o botão com três linhas horizontais. Toque ou clique nele.
  3. Escolha 📂 Importar arquivo (por exemplo, .srwb, .ipynb, .csv, .py, .zip). Role dentro do menu, se necessário. No seletor de arquivos do seu dispositivo, selecione workbook-graphics.srwb de Downloads ou da pasta que você escolheu.
  4. Feche o menu se ele permanecer aberto e selecione a nova aba Workbook Graphics no seletor de pastas de trabalho. Suas abas existentes são mantidas.
  5. Encontre as quatro células chamadas static_axes, embedded_png, canvas_axes e math_axes. Leia-as antes de executar o código. Os diagramas estáticos e as equações aparecem a partir de sua fonte Markdown; a imagem JavaScript aparece apenas depois que você executa sua célula.

Importar não é executar. Uma importação .srwb não executa seu código, mesmo quando a configuração de execução automática está ativada. Apenas canvas_axes precisa de execução JavaScript nesta lição. Não há etapa de Executar todas as células.

Precisa de mais detalhes sobre o download ou o seletor? Siga o passo a passo de importação manual de pasta de trabalho. Os nomes acima aparecem nas células salvas; o tutorial de caminhos de células nomeadas explica como atribuí-los e usá-los. Você também pode criar esses exemplos em uma pasta de trabalho que já tenha aberta, usando os passos abaixo.

Etapa 2 · Método 1

Mantenha um diagrama estático em Markdown

Pense em uma folha de papel voltada para você. r aponta para a direita ao longo do papel, u aponta para cima ao longo dele e n aponta para fora do papel em sua direção. Um círculo com um ponto representa essa direção para fora, como ver a ponta de uma seta vindo em sua direção.

Editar o diagrama importado

  1. Encontre static_axes. Toque em seu ✎ lápis no cabeçalho da própria célula salva, perto de ✕. Isso abre o código-fonte da célula existente; o painel de nova célula criaria outra célula.
  2. Mantenha o botão de tipo de célula definido como Md. No texto do SVG, altere r: right para r: across.
  3. Toque no botão ▶ Executar dessa célula para salvar e renderizar o Markdown novamente. Para uma célula Md, esse botão renderiza texto; ele não executa JavaScript nem inicia um runtime de linguagem.

Ou crie sua própria célula Markdown

  1. Encontre o painel de nova célula onde você digita a próxima célula. Se ele estiver recolhido, use o botão ⌃ Mostrar painel de nova célula perto do título do aplicativo.
  2. Toque no botão de tipo de célula marcado como código para que ele mude para Md. Markdown é um tipo de célula, não uma entrada no menu suspenso de idiomas.
  3. Copie o SVG completo abaixo para o campo de texto, sem adicionar delimitadores de código Markdown (```). Deixe uma linha em branco entre o texto ao redor e o SVG.
  4. Toque em ▶ Executar para adicionar a célula Markdown renderizada. Você deverá ver o papel e todos os três rótulos de direção.
<svg xmlns="http://www.w3.org/2000/svg"
     viewBox="0 0 360 220" width="100%" height="220"
     role="img" aria-label="Right, up and outward normal on paper">
  <title>A paper coordinate frame</title>
  <rect x="20" y="18" width="320" height="184"
        rx="6" fill="#ffffff" stroke="#526170" stroke-width="2" />
  <path d="M110 145 H280" fill="none" stroke="#075d69" stroke-width="3" />
  <polygon points="280,145 267,138 267,152" fill="#075d69" />
  <path d="M110 145 V48" fill="none" stroke="#064d91" stroke-width="3" />
  <polygon points="110,48 103,61 117,61" fill="#064d91" />
  <circle cx="110" cy="145" r="10" fill="#ffffff" stroke="#14191f" stroke-width="2" />
  <circle cx="110" cy="145" r="3" fill="#14191f" />
  <text x="204" y="168" fill="#14191f" font-size="16">r: right</text>
  <text x="124" y="62" fill="#14191f" font-size="16">u: up</text>
  <text x="42" y="190" fill="#14191f" font-size="16">n: toward you</text>
</svg>

O SciREPL sanitiza o Markdown. Este exemplo usa formas SVG comuns, texto e atributos fill/stroke explícitos. Suas pontas de seta são polígonos: não confie que marker-end="url(...)", um bloco <style>, scripts ou animações sobrevivam ao sanitizador.

Use um PNG incorporado em vez disso

A outra opção estática é um PNG com seus dados Base64 armazenados diretamente no código-fonte Markdown. A sintaxe padrão de imagem do Markdown tem esta aparência:

![Paper axes](data:image/png;base64,PASTE_THE_COMPLETE_BASE64_PNG_HERE)

Esta linha mostra o formato, não uma imagem em funcionamento: substitua o espaço reservado pelo PNG codificado completo ou use a célula embedded_png que já funciona. A parte após base64, são dados de imagem, não um nome de arquivo. Mantenha em uma única linha.

Para uma imagem que se ajuste à célula em uma tela pequena, a célula embedded_png complementar usa o HTML em linha equivalente abaixo, com width="100%". Ela ainda é armazenada dentro do Markdown, não como saída de código:

<img alt="Paper axes" width="100%"
     src="data:image/png;base64,PASTE_THE_COMPLETE_BASE64_PNG_HERE">

Escolha uma rota estática: use um elemento SVG em linha para um pequeno diagrama editável, ou uma imagem data:image/png;base64,... para uma imagem rasterizada. Um URL de dados SVG como data:image/svg+xml,... não é o mesmo que SVG em linha e é bloqueado na compilação verificada. URLs de imagens remotas também são bloqueados lá. Esses dois exemplos autocontidos não precisam de download de imagem quando exibidos.

Ambos os exemplos estáticos ficam no código-fonte Markdown. Eles podem ser exibidos após a importação do caderno de trabalho sem executar código.

Etapa 3 · Método 2

Desenhe uma imagem com JavaScript

Uma imagem estática permanece a mesma até que você edite seu código-fonte. Para uma imagem calculada ou desenhada por um programa, use uma célula código e selecione JS - JavaScript. Este exemplo desenha em um canvas, converte-o para PNG e envia essa imagem para a saída da célula.

  1. No caderno de trabalho importado, toque no ✎ lápis em canvas_axes. Verifique se o tipo de célula é código e se seu idioma é JS - JavaScript (o seletor compacto pode mostrar apenas JS).
  2. Leia o código abaixo, que é o programa completo nessa célula. Ele não precisa de nenhuma outra célula, arquivo, pacote ou solicitação de rede.
  3. Toque, naquela célula, em ▶ Executar. Uma imagem deve aparecer abaixo do código-fonte JavaScript.

Para criar uma nova célula em vez disso, vá para o painel de nova célula, altere Md de volta para código, se necessário, e escolha JS - JavaScript no menu suspenso de idiomas. Cole o código e toque em ▶ Executar. Se JavaScript estiver oculto, localize ☰ Menu → Idiomas e ative-o.

(() => {
  const canvas = document.createElement('canvas');
  canvas.width = 360;
  canvas.height = 220;
  const ctx = canvas.getContext('2d');
  ctx.fillStyle = '#ffffff';
  ctx.fillRect(0, 0, 360, 220);
  ctx.strokeStyle = '#526170';
  ctx.lineWidth = 2;
  ctx.strokeRect(20, 18, 320, 184);

  function arrow(x1, y1, x2, y2, color) {
    const angle = Math.atan2(y2 - y1, x2 - x1);
    ctx.strokeStyle = color;
    ctx.fillStyle = color;
    ctx.lineWidth = 3;
    ctx.beginPath();
    ctx.moveTo(x1, y1);
    ctx.lineTo(x2, y2);
    ctx.stroke();
    ctx.beginPath();
    ctx.moveTo(x2, y2);
    ctx.lineTo(x2 - 14 * Math.cos(angle - 0.5),
               y2 - 14 * Math.sin(angle - 0.5));
    ctx.lineTo(x2 - 14 * Math.cos(angle + 0.5),
               y2 - 14 * Math.sin(angle + 0.5));
    ctx.closePath();
    ctx.fill();
  }
  arrow(110, 145, 280, 145, '#075d69'); // right
  arrow(110, 145, 110, 48, '#064d91');  // up
  ctx.fillStyle = '#ffffff';
  ctx.strokeStyle = '#14191f';
  ctx.lineWidth = 2;
  ctx.beginPath();
  ctx.arc(110, 145, 10, 0, 2 * Math.PI);
  ctx.fill();
  ctx.stroke();
  ctx.fillStyle = '#14191f';
  ctx.beginPath();
  ctx.arc(110, 145, 3, 0, 2 * Math.PI);
  ctx.fill();
  ctx.font = '16px sans-serif';
  ctx.fillText('r: right', 204, 168);
  ctx.fillText('u: up', 124, 62);
  ctx.fillText('n: toward you', 42, 190);
  window.renderImage(canvas.toDataURL('image/png'));
})();

Tente alterar r: right em ctx.fillText(...) e execute a célula novamente. O encapsulador de função (() => { ... })(); mantém as variáveis deste exemplo locais, para que você possa executá-lo novamente sem redeclarar variáveis const de nível superior.

A chamada de exibição é importante. Mantenha window.renderImage(canvas.toDataURL('image/png')) no final. Retornar uma cadeia de caracteres comum, como '<svg>...</svg>', a partir de JavaScript exibe texto; isso não transforma essa cadeia de caracteres em um diagrama em linha. Você não precisa inserir o canvas na página do aplicativo.

Etapa 4 · Método 3

Explique a imagem com equações

Use uma célula Markdown (Md) para matemática no estilo TeX. As direções dos diagramas formam um referencial dextrogiro: direita × cima = normal externa. Na matriz abaixo, a primeira linha é r, a segunda é u e a terceira é n; os subscritos são suas componentes em um sistema de coordenadas x, y, z escolhido.

  1. Toque no ✎ lápis em math_axes ou crie uma nova célula usando código → Md no painel de nova célula.
  2. Use o texto completo abaixo. Os delimitadores $$ pertencem ao código-fonte Markdown; não o envolva em um bloco de código delimitado.
  3. Toque em ▶ Executar para salvar e renderizar o Markdown. Você deve ver uma equação de produto vetorial e uma matriz de três linhas, não comandos brutos de barra invertida. Nenhum kernel de linguagem é executado para esta célula.
Right, up and outward normal form a right-handed frame.

$$\mathbf{r} \times \mathbf{u} = \mathbf{n}$$

Rows of the frame matrix: right, up, then outward normal.

$$
M = \begin{pmatrix}
r_x & r_y & r_z \\
u_x & u_y & u_z \\
n_x & n_y & n_z
\end{pmatrix}
$$

O KaTeX não é um compilador TeX completo. Ele renderiza notação matemática compatível, mas não compila diagramas TikZ nem um documento LaTeX inteiro. Embora o KaTeX liste \includegraphics, isso requer uma opção de confiança que o SciREPL não habilita no renderizador verificado; não é uma forma de inserção de imagens aqui. Use Markdown SVG/PNG ou canvas do JavaScript para imagens.

Para outros símbolos e comandos matemáticos, consulte a tabela de compatibilidade do KaTeX; a documentação pode descrever recursos mais recentes do que a versão incluída no SciREPL. Para um livro de exercícios que usa essas instruções para explicar movimentos do cubo, consulte o passo a passo dos Grupos de Markov.

Etapa 5

Salve uma cópia e saiba o que executar novamente

  1. Abra ☰ Menu → Exportar pastas de trabalho e pacotes.
  2. Escolha Pasta de trabalho (.srwb) e Apenas guia atual para este livro de exercícios e depois toque em Exportar. Salve o arquivo em algum local sob seu controle.
  3. Para reabrir essa cópia, use Menu → Import File. Isso adiciona outra aba de livro de exercícios; não substitui a existente.
  4. Verifique o SVG estático, o PNG incorporado e as equações. Eles vêm do código-fonte salvo em Markdown e não precisam de execução de código. Inspecione canvas_axes e execute essa célula de JavaScript novamente para gerar sua imagem de novo.

A saída gerada não é o mesmo que o código-fonte. Na versão de navegador verificada do Free, a exportação .srwb pode armazenar uma saída de imagem em JavaScript, mas o uso manual de Menu → Import File não restaura essa saída de código. O código-fonte em JavaScript permanece, portanto execute-o novamente. O SVG embutido, o PNG incorporado e as equações são código-fonte em Markdown e são exibidos na importação. Não use uma saída visível anteriormente como prova de que o código acabou de ser executado.

Essas verificações cobrem os exemplos de livro de exercícios acima, não a fidelidade de imagem em todos os formatos de exportação. Não presuma que exportações de documentos em PDF, DOCX, Markdown e outros preservem todas as imagens da mesma forma; inspecione seu documento exportado. Consulte arquivos e exportação (Página de referência em inglês) para ver os formatos disponíveis.

Exportar seu livro de exercícios editado cria uma cópia de segurança de suas alterações; o exemplo original baixado não é atualizado quando você edita uma célula. O armazenamento local do aplicativo não é uma cópia de segurança, e sessões no Android e no navegador não compartilham o trabalho automaticamente.

Se algo parecer errado

Verifique o tipo da célula e o código-fonte

  • Você vê o código SVG em vez de um diagrama: verifique se o tipo de célula é Md, remova quaisquer delimitadores de código ao redor e renderize a célula novamente. Use o exemplo completo de <svg>...</svg> em linha, não uma URL de dados SVG.
  • O PNG está ausente: use a célula embedded_png do material complementar ou verifique se colou a cadeia de caracteres data:image/png;base64,... inteira, sem espaços ou quebras de linha. Um nome de arquivo local não é dado de imagem incorporado.
  • O código do canvas não é executado: defina o tipo de célula como código e sua linguagem como JS - JavaScript, não Python. Mantenha todo o invólucro da função e a chamada final de window.renderImage(...).
  • Uma célula JavaScript importada não possui imagem: a importação deste caderno não o executa nem restaura a saída do seu código. Inspecione e execute novamente canvas_axes.
  • Você vê TeX puro ou um erro matemático: use Md, inclua tanto a abertura quanto o fechamento $$, e confira cada barra invertida e chave com o exemplo. Cada linha da matriz, exceto a última, termina com duas barras invertidas, \\.
  • A edição criou uma célula extra: o painel de nova célula adiciona células. Use o ✎ lápis da célula salva para alterar essa célula existente, e depois o seu próprio botão ▶ Executar. Use Cancelar se tiver aberto o editor por engano.
