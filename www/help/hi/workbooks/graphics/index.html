सभी ट्यूटोरियल

चरण 1

उदाहरण वर्कबुक खोलें

साथी फ़ाइल में एम्बेडेड PNG सहित संपूर्ण उदाहरण शामिल हैं। यह सब कुछ एक छोटी वर्कबुक में रखता है ताकि आपको लंबी Base64 इमेज स्ट्रिंग टाइप न करनी पड़े।

  1. ग्राफ़िक्स उदाहरण वर्कबुक (.srwb) डाउनलोड करें। वास्तविक फ़ाइल को उसके .srwb एक्सटेंशन को बनाए रखते हुए सहेजें। यदि आपका ब्राउज़र टेक्स्ट प्रदर्शित करता है, तो उसकी सेव/डाउनलोड क्रिया का उपयोग करें। उस फ़ोल्डर पर ध्यान दें जिसमें आपने इसे सहेजा है।
  2. SciREPL खोलें। ऐप के शीर्ष पर मौजूद हेडर में, ☰ Menu खोजें, जो तीन क्षैतिज रेखाओं वाला बटन है। उस पर टैप या क्लिक करें।
  3. 📂 फ़ाइल आयात करें (उदा. .srwb, .ipynb, .csv, .py, .zip) चुनें। आवश्यकता पड़ने पर मेनू के अंदर स्क्रॉल करें। अपने डिवाइस के फ़ाइल पिकर में, डाउनलोड्स या अपने चुने हुए फ़ोल्डर से workbook-graphics.srwb का चयन करें।
  4. यदि मेनू खुला रहता है तो उसे बंद करें, और वर्कबुक चयनकर्ता में नए Workbook Graphics टैब का चयन करें। आपके मौजूदा टैब सुरक्षित रहेंगे।
  5. static_axes, embedded_png, canvas_axes, और math_axes नाम वाले चार सेल खोजें। कोड चलाने से पहले उन्हें पढ़ें। स्टैटिक आरेख और समीकरण उनके Markdown स्रोत से दिखाई देते हैं; JavaScript चित्र केवल उसके सेल को चलाने के बाद ही दिखाई देता है।

इंपोर्ट करना रन करना नहीं है। एक .srwb इंपोर्ट इसके कोड को निष्पादित नहीं करता है, भले ही ऑटो-एग्ज़ीक्यूट सेटिंग सक्षम हो। इस पाठ में केवल canvas_axes को JavaScript निष्पादन की आवश्यकता है। कोई सभी सेल चलाएं चरण नहीं है।

डाउनलोड या पिकर के बारे में अधिक विवरण चाहिए? मैन्युअल वर्कबुक इंपोर्ट वॉकथ्रू का पालन करें। ऊपर दिए गए नाम सहेजे गए सेल पर दिखाई देते हैं; नेम्ड-सेल पाथ ट्यूटोरियल बताता है कि उन्हें कैसे असाइन और उपयोग करना है। आप नीचे दिए गए चरणों का उपयोग करके पहले से खुली हुई वर्कबुक में भी ये उदाहरण बना सकते हैं।

चरण 2 · विधि 1

Markdown में एक स्टैटिक आरेख रखें

अपने सामने रखे कागज़ के एक पन्ने की कल्पना करें। r कागज़ पर दाईं ओर इंगित करता है, u उस पर ऊपर की ओर इंगित करता है, और n कागज़ से बाहर आपकी ओर इंगित करता है। एक बिंदु वाला वृत्त उस बाहरी दिशा को दर्शाता है, जैसे आपकी ओर आते तीर की नोक देखना।

इंपोर्ट किए गए आरेख को संपादित करें

  1. static_axes खोजें। उस सहेजे गए सेल के अपने हेडर में इसके ✎ पेंसिल पर टैप करें, जो ✕ के पास है। यह मौजूदा सेल का स्रोत खोलता है; नया-सेल पैनल एक अन्य सेल बना देगा।
  2. सेल-प्रकार बटन को Md पर सेट रखें। SVG टेक्स्ट में, r: right को r: across में बदलें।
  3. उस सेल के ▶ चलाएं बटन पर टैप करके Markdown को फिर से सहेजें और रेंडर करें। किसी Md सेल के लिए, यह बटन टेक्स्ट को रेंडर करता है; यह JavaScript को निष्पादित नहीं करता है और न ही किसी लैंग्वेज रनटाइम को प्रारंभ करता है।

या अपना स्वयं का Markdown सेल बनाएं

  1. नया-सेल पैनल खोजें जहां आप अगला सेल टाइप करते हैं। यदि यह संकुचित है, तो ऐप शीर्षक के पास मौजूद ⌃ Show new-cell panel बटन का उपयोग करें।
  2. कोड चिह्नित सेल-प्रकार बटन पर टैप करें ताकि यह Md में बदल जाए। Markdown एक सेल प्रकार है, भाषा ड्रॉपडाउन में कोई प्रविष्टि नहीं।
  3. नीचे दिए गए संपूर्ण SVG को टेक्स्ट फ़ील्ड में कॉपी करें, Markdown कोड फेंस जोड़े बिना (```)। आस-पास के गद्य और SVG के बीच एक रिक्त पंक्ति छोड़ें।
  4. ▶ चलाएं पर टैप करके रेंडर किया गया Markdown सेल जोड़ें। आपको कागज़ और तीनों दिशा लेबल दिखाई देने चाहिए।

SciREPL Markdown को सैनिटाइज़ करता है। यह उदाहरण सामान्य SVG आकृतियों, टेक्स्ट, और स्पष्ट fill/stroke विशेषताओं का उपयोग करता है। इसके बाणशीर्ष बहुभुज हैं: सैनिटाइज़र से बचने के लिए marker-end="url(...)", किसी <style> ब्लॉक, स्क्रिप्ट या एनीमेशन पर भरोसा न करें।

इसके बजाय एक एम्बेडेड PNG का उपयोग करें

दूसरा स्टैटिक विकल्प एक PNG है जिसका Base64 डेटा सीधे Markdown स्रोत में संग्रहीत होता है। मानक Markdown छवि सिंटैक्स इस प्रकार दिखता है:

![Paper axes](data:image/png;base64,PASTE_THE_COMPLETE_BASE64_PNG_HERE)

यह पंक्ति प्रारूप दिखाती है, कोई काम करता हुआ चित्र नहीं: प्लेसहोल्डर को संपूर्ण एन्कोडेड PNG से बदलें, या पहले से काम कर रहे embedded_png सेल का उपयोग करें। base64, के बाद का भाग छवि डेटा है, कोई फ़ाइल नाम नहीं। इसे एक ही पंक्ति में रखें।

छोटी स्क्रीन पर सेल में फ़िट होने वाले चित्र के लिए, कंपैनियन का embedded_png सेल नीचे दिए गए समतुल्य इनलाइन HTML का उपयोग करता है, जिसमें width="100%" शामिल है। यह अभी भी Markdown के अंदर संग्रहीत है, कोड आउटपुट के रूप में नहीं:

<img alt="Paper axes" width="100%"
     src="data:image/png;base64,PASTE_THE_COMPLETE_BASE64_PNG_HERE">

एक स्टैटिक मार्ग चुनें: एक छोटे संपादन योग्य आरेख के लिए इनलाइन SVG एलिमेंट का उपयोग करें, या रैस्टर चित्र के लिए data:image/png;base64,... छवि का। data:image/svg+xml,... जैसा SVG डेटा URL इनलाइन SVG के समान नहीं है और जांची गई बिल्ड में अवरुद्ध है। रिमोट छवि URL भी वहां अवरुद्ध हैं। प्रदर्शित होने पर इन दो आत्मनिर्भर उदाहरणों को किसी छवि डाउनलोड की आवश्यकता नहीं होती है।

दोनों स्टैटिक उदाहरण Markdown स्रोत में रहते हैं। इन्हें वर्कबुक इंपोर्ट के बाद बिना कोड चलाए प्रदर्शित किया जा सकता है।

चरण 3 · विधि 2

JavaScript से एक चित्र बनाएं

एक स्टैटिक चित्र तब तक वैसा ही रहता है जब तक आप उसके स्रोत को संपादित नहीं करते। किसी प्रोग्राम द्वारा परिकलित या बनाए गए चित्र के लिए, एक कोड सेल का उपयोग करें और JS - JavaScript चुनें। यह उदाहरण एक कैनवस पर चित्र बनाता है, उसे PNG में परिवर्तित करता है, और उस छवि को सेल के आउटपुट पर भेजता है।

  1. इंपोर्ट की गई वर्कबुक में, ✎ पेंसिल पर टैप करें जो canvas_axes पर है। जांचें कि सेल प्रकार कोड है और इसकी भाषा JS - JavaScript है (कॉम्पैक्ट चयनकर्ता केवल JS दिखा सकता है)।
  2. नीचे दिया गया कोड पढ़ें, जो उस सेल का संपूर्ण प्रोग्राम है। इसे किसी अन्य सेल, फ़ाइल, पैकेज या नेटवर्क अनुरोध की आवश्यकता नहीं है।
  3. उस सेल के ▶ चलाएं पर टैप करें। JavaScript स्रोत के नीचे एक चित्र दिखाई देना चाहिए।

इसके बजाय एक नया सेल बनाने के लिए, नए-सेल पैनल पर जाएं, यदि आवश्यक हो तो Md को वापस कोड में बदलें, और भाषा ड्रॉपडाउन से JS - JavaScript चुनें। कोड पेस्ट करें, फिर ▶ चलाएं पर टैप करें। यदि JavaScript छिपा हुआ है, तो ☰ Menu → भाषाएं खोजें और इसे सक्षम करें।

(() => {
  const canvas = document.createElement('canvas');
  canvas.width = 360;
  canvas.height = 220;
  const ctx = canvas.getContext('2d');
  ctx.fillStyle = '#ffffff';
  ctx.fillRect(0, 0, 360, 220);
  ctx.strokeStyle = '#526170';
  ctx.lineWidth = 2;
  ctx.strokeRect(20, 18, 320, 184);

  function arrow(x1, y1, x2, y2, color) {
    const angle = Math.atan2(y2 - y1, x2 - x1);
    ctx.strokeStyle = color;
    ctx.fillStyle = color;
    ctx.lineWidth = 3;
    ctx.beginPath();
    ctx.moveTo(x1, y1);
    ctx.lineTo(x2, y2);
    ctx.stroke();
    ctx.beginPath();
    ctx.moveTo(x2, y2);
    ctx.lineTo(x2 - 14 * Math.cos(angle - 0.5),
               y2 - 14 * Math.sin(angle - 0.5));
    ctx.lineTo(x2 - 14 * Math.cos(angle + 0.5),
               y2 - 14 * Math.sin(angle + 0.5));
    ctx.closePath();
    ctx.fill();
  }
  arrow(110, 145, 280, 145, '#075d69'); // right
  arrow(110, 145, 110, 48, '#064d91');  // up
  ctx.fillStyle = '#ffffff';
  ctx.strokeStyle = '#14191f';
  ctx.lineWidth = 2;
  ctx.beginPath();
  ctx.arc(110, 145, 10, 0, 2 * Math.PI);
  ctx.fill();
  ctx.stroke();
  ctx.fillStyle = '#14191f';
  ctx.beginPath();
  ctx.arc(110, 145, 3, 0, 2 * Math.PI);
  ctx.fill();
  ctx.font = '16px sans-serif';
  ctx.fillText('r: right', 204, 168);
  ctx.fillText('u: up', 124, 62);
  ctx.fillText('n: toward you', 42, 190);
  window.renderImage(canvas.toDataURL('image/png'));
})();

r: right को ctx.fillText(...) में बदलने का प्रयास करें, फिर सेल को फिर से चलाएं। फ़ंक्शन रैपर (() => { ... })(); इस उदाहरण के वेरिएबल्स को लोकल रखता है, ताकि आप टॉप-लेवल const वेरिएबल्स को फिर से डिक्लेयर किए बिना इसे दोबारा चला सकें।

डिस्प्ले कॉल महत्वपूर्ण है। अंत में window.renderImage(canvas.toDataURL('image/png')) रखें। '<svg>...</svg>' जैसी किसी साधारण स्ट्रिंग को JavaScript से लौटाने पर टेक्स्ट प्रदर्शित होता है; यह उस स्ट्रिंग को इनलाइन आरेख में नहीं बदलता है। आपको ऐप के पेज में कैनवस सम्मिलित करने की आवश्यकता नहीं है।

चरण 4 · विधि 3

समीकरणों के साथ चित्र को समझाएं

TeX-शैली के गणित के लिए Markdown (Md) सेल का उपयोग करें। आरेखों की दिशाएं एक दक्षिणहस्त फ्रेम बनाती हैं: right × up = outward normal। नीचे दिए गए मैट्रिक्स में, पहली पंक्ति r है, दूसरी पंक्ति u है, और तीसरी पंक्ति n है; सबस्क्रिप्ट चुनी गई x, y, z निर्देशांक प्रणाली में उनके घटक हैं।

  1. ✎ पेंसिल पर टैप करें जो math_axes पर है, या नए-सेल पैनल में कोड → Md का उपयोग करके एक नया सेल बनाएं।
  2. नीचे दिए गए संपूर्ण टेक्स्ट का उपयोग करें। $$ डिलीमीटर Markdown स्रोत के अंतर्गत आते हैं; इसे कोड फेंस में न लपेटें।
  3. ▶ चलाएं पर टैप करके Markdown को सहेजें और रेंडर करें। आपको क्रॉस-प्रोडक्ट समीकरण और तीन-पंक्तियों वाला मैट्रिक्स दिखाई देना चाहिए, न कि रॉ बैकस्लैश कमांड। इस सेल के लिए कोई लैंग्वेज कर्नेल नहीं चलता है।
Right, up and outward normal form a right-handed frame.

$$\mathbf{r} \times \mathbf{u} = \mathbf{n}$$

Rows of the frame matrix: right, up, then outward normal.

$$
M = \begin{pmatrix}
r_x & r_y & r_z \\
u_x & u_y & u_z \\
n_x & n_y & n_z
\end{pmatrix}
$$

KaTeX कोई पूर्ण TeX कंपाइलर नहीं है। यह समर्थित गणितीय नोटेशन को रेंडर करता है, लेकिन TikZ आरेखों या संपूर्ण LaTeX दस्तावेज़ को कंपाइल नहीं करता है। यद्यपि KaTeX में \includegraphics सूचीबद्ध है, इसके लिए एक ट्रस्ट विकल्प की आवश्यकता होती है जिसे SciREPL जांची गई रेंडरर में सक्षम नहीं करता है; यह यहां छवि-सम्मिलन का मार्ग नहीं है। चित्रों के लिए Markdown SVG/PNG या JavaScript कैनवस का उपयोग करें।

अन्य प्रतीकों और गणित कमांड के लिए, KaTeX समर्थन तालिका देखें; प्रलेखन में SciREPL के बंडल किए गए संस्करण से नए फीचर्स का वर्णन हो सकता है। क्यूब चालों को समझाने के लिए इन दिशाओं का उपयोग करने वाली वर्कबुक के लिए, Markov Groups walkthrough देखें।

चरण 5

एक प्रति सहेजें, फिर जानें कि क्या पुनः चलाना है

  1. ☰ Menu → वर्कबुक और पैकेज निर्यात करें खोलें।
  2. इस वर्कबुक के लिए वर्कबुक (.srwb) और केवल वर्तमान टैब चुनें, फिर निर्यात पर टैप करें। फ़ाइल को किसी ऐसे स्थान पर सहेजें जो आपके नियंत्रण में हो।
  3. उस प्रति को फिर से खोलने के लिए, मेनू → Import File का उपयोग करें। यह एक अन्य वर्कबुक टैब जोड़ता है; यह आपके मौजूदा टैब को प्रतिस्थापित नहीं करता है।
  4. स्टैटिक SVG, एम्बेडेड PNG, और समीकरणों की जांच करें। वे सहेजे गए Markdown स्रोत से आते हैं और उन्हें कोड निष्पादन की आवश्यकता नहीं होती है। canvas_axes का निरीक्षण करें और उस JavaScript सेल को उसके चित्र को फिर से जनरेट करने के लिए दोबारा चलाएं।

जनरेट किया गया आउटपुट स्रोत के समान नहीं है। जांची गई Free ब्राउज़र बिल्ड में, .srwb निर्यात एक JavaScript छवि आउटपुट संग्रहीत कर सकता है, लेकिन मैन्युअल मेनू → Import File उस कोड आउटपुट को पुनर्स्थापित नहीं करता है। JavaScript स्रोत बना रहता है, इसलिए इसे दोबारा चलाएं। इनलाइन SVG, एम्बेडेड PNG, और समीकरण Markdown स्रोत हैं और इंपोर्ट पर प्रदर्शित होते हैं। पहले से दिखाई दे रहे आउटपुट को इस बात का प्रमाण न मानें कि कोड अभी-अभी चला है।

ये जांच ऊपर दिए गए वर्कबुक उदाहरणों को कवर करती हैं, प्रत्येक निर्यात प्रारूप में छवि निष्ठा को नहीं। यह न मानें कि PDF, DOCX, Markdown, और अन्य दस्तावेज़ निर्यात प्रत्येक छवि को उसी तरह संरक्षित करते हैं; अपने निर्यात किए गए दस्तावेज़ का निरीक्षण करें। उपलब्ध प्रारूपों के लिए files and export (अंग्रेज़ी संदर्भ पृष्ठ) देखें।

आपकी संपादित वर्कबुक को निर्यात करने से आपके परिवर्तनों का एक बैकअप बन जाता है; जब आप किसी सेल को संपादित करते हैं तो मूल डाउनलोड किया गया उदाहरण अपडेट नहीं होता है। स्थानीय ऐप संग्रहण कोई बैकअप नहीं है, और एंड्रॉइड और ब्राउज़र सत्र स्वचालित रूप से काम साझा नहीं करते हैं।

यदि कुछ गलत दिखता है

सेल का प्रकार और स्रोत जांचें

  • आपको आरेख के बजाय SVG कोड दिखाई देता है: जांचें कि सेल प्रकार Md है, किसी भी आस-पास के कोड फेंस को हटाएं, और सेल को फिर से रेंडर करें। संपूर्ण इनलाइन <svg>...</svg> उदाहरण का उपयोग करें, SVG डेटा URL का नहीं।
  • PNG गायब है: साथी के embedded_png सेल का उपयोग करें, या जांचें कि आपने बिना किसी स्पेस या लाइन ब्रेक के संपूर्ण data:image/png;base64,... स्ट्रिंग पेस्ट की है। एक स्थानीय फ़ाइल नाम एम्बेडेड छवि डेटा नहीं होता है।
  • कैनवस कोड नहीं चलता है: इसके सेल प्रकार को कोड पर और इसकी भाषा को JS - JavaScript पर सेट करें, न कि Python पर। संपूर्ण फ़ंक्शन रैपर और अंतिम window.renderImage(...) कॉल को बनाए रखें।
  • इंपोर्ट किए गए JavaScript सेल में कोई चित्र नहीं है: इस वर्कबुक को इंपोर्ट करने से यह रन नहीं होती है और न ही इसका कोड आउटपुट पुनर्स्थापित होता है। canvas_axes का निरीक्षण करें और उसे दोबारा चलाएं।
  • आपको रॉ TeX या कोई गणितीय त्रुटि दिखाई देती है: Md का उपयोग करें, प्रारंभिक और समापन दोनों $$ शामिल करें, और उदाहरण के विरुद्ध प्रत्येक बैकस्लैश और ब्रेस की जांच करें। अंतिम पंक्ति को छोड़कर प्रत्येक मैट्रिक्स पंक्ति दो बैकस्लैश, \\ के साथ समाप्त होती है।
  • संपादन से एक अतिरिक्त सेल बन गया: नया-सेल पैनल सेल जोड़ता है। उस मौजूदा सेल को बदलने के लिए सहेजे गए सेल के ✎ पेंसिल का उपयोग करें, फिर उसके अपने ▶ चलाएं बटन का। यदि आपने गलती से इसका संपादक खोल दिया है तो रद्द करें का उपयोग करें।

सहेजे गए सेल, पेंसिल, और नए-सेल पैनल के सचित्र विवरण के लिए, फ़र्स्ट-वर्कबुक इंटरफ़ेस वॉकथ्रू देखें। सेल प्रकारों के संक्षिप्त स्मरण के लिए वर्कबुक्स संदर्भ (अंग्रेज़ी संदर्भ पृष्ठ) पर लौटें।
