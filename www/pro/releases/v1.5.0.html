Android Pro · v1.5.0 · Candidate preparation

SciREPL Pro v1.5.0

This candidate makes Help examples easier to reuse, connects the app to language-aware online guides, and adds offline Bash and Prolog completion. These are the changes since v1.4.0.

Not released These notes are prepared locally, not a publication or rollout announcement. Exact-candidate native CI, signed CLOSED-testing upgrades on both test phones, and the required validation and publication gates must finish before release.

Copy or insert Help examples

  • Help examples have Copy and Insert buttons.
  • Insert adds an example as a new cell at the end of the current notebook. It does not run the example.

Online guides in your display language

  • Help and walkthroughs link to the shared online tutorials, workbook-import guide and AI and completion guide.
  • The app chooses guide links using the selected display language. The guides are online, not bundled offline help, and their public routes must be available before the app ships.
  • Opening a guide does not grant permissions, run notebook code or send an AI-provider request.
  • Translated tutorial fields have completed their acceptance process; that is not native-speaker approval. App language catalogues retain their draft status, and 22 Russian tutorial fields retain optional manual-review flags.

Offline Bash and Prolog completion

  • Built-in completion adds Bash commands and Prolog predicates.
  • These suggestions use local tables without a model request or sending code off the device.
  • The optional local code model and online AI suggestions introduced in v1.4.0 are unchanged by these additions.

Execution consent and interface fixes

  • Open mode still requires execution consent, and run ownership and permissions are revalidated before cells execute.
  • Custom-theme icon contrast, scrolling dialogs and walkthrough placement have been improved.
  • Android debug builds use a separate package and marked launcher icon so they can install beside Play Pro. A debug build does not replace signed release-upgrade testing.

The existing local-model delivery limits remain: Google Play delivers the model; sideloaded APKs cannot download it, and the local engine needs an arm64 device with at least 4 GB of memory. See the privacy policy for current data flows. Browser checks, native-language review, public-site publication and signed Android validation are separate release gates.
