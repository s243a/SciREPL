# Earlier development ideas

The previous README mixed completed features and possible future work in one roadmap. The unfinished ideas are preserved here so the README can describe the current app without silently discarding them. This is an archive of ideas, **not** a prioritized or verified release plan; check the current code and issues before starting one.

- Screenshots or short videos showing R plots, cross-language data flow, and the mobile UI.
- Collapsible long cell outputs.
- Execution counters such as `In [N]` and `Out [N]`.
- Local keyword and variable completion in the cell editor.
- A variable inspector across supported kernels.
- Undo for deleted cells.
- Consider porting Pro's touch double-tap-to-edit shortcut for saved code cells to Free, while preserving normal text selection on desktop.
- Sharing small notebooks through a URL or gist.
- Revisit Capacitor WebView pointer and hover media-query behavior.
- Byte-level download progress for large runtimes and packages.
- Background package and workbook installation without switching the active notebook.

The earlier README also listed a dark/light theme toggle, which is already implemented in Menu → Appearance and is therefore not carried forward as an open idea.

## Workbook images and saved outputs: decide the retention policy

Ordinary **Menu → Import File** import of a `.srwb` workbook currently discards saved **code outputs**. A picture generated by JavaScript or another kernel therefore needs its cell rerun. Images embedded in **Markdown source** do not: they are workbook content and render again without executing code. This is not the same as saying exports contain no outputs: the current `.srwb` exporter and local workbook persistence already retain `lastOutputHtml`, and other import paths can restore it.

Proposed direction, not current behaviour:

- **Export:** an optional “Include generated outputs” choice, off by default. Show the resulting size and allow useful small pictures to travel with the workbook without silently embedding large ones.
- **Local persistence:** a separate opt-in “Keep generated outputs between launches” setting, off by default for new installations. Apply a storage budget and per-output limits; explain what is omitted when an output is too large or storage is full. Do not silently delete outputs already saved by existing installations when introducing the setting.
- **Markdown illustrations:** retain embedded images as source under either choice. Make their contribution to workbook size visible too; a large base64 image is still large even though it is not a generated output.

The immediate concern is generated images and other large rich outputs. Decide separately whether ordinary text results share the same setting. Outputs may still be shown for the current session when retention is off; workbook source and settings must not depend on retaining a picture.

Decide whether ordinary import should restore retained outputs automatically, offer a choice, or intentionally discard them. Restored output must be sanitized, inert and clearly identified as a saved result, not evidence that the kernel has run or contains the original variables. Never rerun cells automatically just to restore pictures. Set explicit byte limits and a predictable response to quota failures, and agree on the same policy for Free and Pro. An export choice should also warn that outputs may contain sensitive data, not just pictures.

Before implementation, test static Markdown SVG/PNG versus generated pictures through export/import, rerunning, relaunch and storage-limit failures. Cover hostile HTML, scripts and external image references, and distinguish ordinary `.srwb` import from `.ipynb` import and other workbook-loading paths. The [workbook graphics tutorial](../www/help/workbooks/graphics/index.html) explains today's distinction; revisit its wording when this policy changes.

## Files & Storage: decode byte-backed text before preview and editing

The named-cell tutorial's browser checks exposed an existing Free issue: Bash can write valid UTF-8 JSON into SharedVFS as `Uint8Array`, but the file preview and text editor call `readFile(path)` without decoding. They show comma-separated byte values instead of JSON. An unchanged Save could consequently replace the original file with those numbers. The same file stored as a JavaScript string displays correctly; the tutorial uses that text-writing route, without changing the app.

In a separate fix, choose explicitly which files are text, decode byte-backed text for preview and editing, and keep binary files out of a plain text Save path. Preserve the original bytes until a successful, intentional edit. Add regressions for the same JSON written by Bash and by JavaScript, correct preview, unchanged Save, non-ASCII UTF-8 and binary data. Audit Pro's file-editor implementation separately rather than assuming it has the same bug.
