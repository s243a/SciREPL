# Proposal: Configurable build profiles + resilient kernel sources

Status: draft / design
Scope: SciREPL (free + Pro). Two related pieces:
1. A **build-time configuration** that selects which languages are enabled and
   which kernel runtimes are **bundled** into the app — so we can ship `mini`,
   `light`, and `full` variants from one codebase.
2. A **resilient kernel-load path** that tries multiple sources (CDN mirrors,
   then a local bundle if present) with a per-attempt **timeout** and a
   per-kernel **source override** — so a slow/dead CDN no longer hangs the load.

Note: actual bundling of swipl/pyodide is **deferred**. We build the
*mechanism* now but keep those two external by default, so the external-load +
fallback path is exercised in real use first.

## 1. Single source of truth: a kernel config

A generated config object the runtime reads (and the build writes):

```js
// www/js/kernel_config.js  (generated by the build from a profile)
window.KERNEL_CONFIG = {
  profile: 'light',                 // mini | light | full | custom
  languages: {
    javascript: { enabled: true, runtime: 'native' },
    bash:  { enabled: true, sources: [{ type: 'local', url: 'vendor/brush/brush_wasm.js' }] },
    typr:  { enabled: true, sources: [{ type: 'local', url: 'vendor/typr/typr_wasm.js' }] },
    lua:   { enabled: true, timeoutMs: 15000, sources: [
              { type: 'cdn', url: 'https://cdn.jsdelivr.net/npm/fengari-web@latest/dist/fengari-web.js' },
              { type: 'cdn', url: 'https://unpkg.com/fengari-web@latest/dist/fengari-web.js' } ] },
    prolog:{ enabled: true, timeoutMs: 20000, sources: [
              { type: 'cdn', url: 'https://SWI-Prolog.github.io/npm-swipl-wasm/3/latest/dynamic-import.js' },
              { type: 'cdn', url: 'https://cdn.jsdelivr.net/npm/swipl-wasm@latest/dist/dynamic-import.js' },
              { type: 'cdn', url: 'https://unpkg.com/swipl-wasm@latest/dist/dynamic-import.js' }
              /* , { type: 'local', url: 'vendor/swipl/dynamic-import.js' }  // when bundled */ ] },
    python:{ enabled: true, timeoutMs: 30000, sources: [
              { type: 'cdn', url: 'https://cdn.jsdelivr.net/pyodide/v0.26.2/full/pyodide.mjs' },
              { type: 'cdn', url: 'https://unpkg.com/pyodide@0.26.2/pyodide.mjs' } ] },
    r:     { enabled: true, timeoutMs: 60000, sources: [
              { type: 'cdn', url: 'https://webr.r-wasm.org/latest/webr.mjs' } ] },
  }
};
```

- **`enabled`** → whether the language appears in `LANGUAGE_META` / the
  selector and is registered. The hardcoded lists in `index.html` /
  `file_io.js` are driven from this (kills the existing drift problem too).
- **`sources`** → ordered candidate list (point 1). `local` entries point at
  bundled vendor assets; `cdn` entries are mirrors (point 3).
- **`timeoutMs`** → per-attempt cap (point 2).

## 2. Build profiles (the configurable build)

A profile declares which languages are enabled and which are bundled
(i.e. which get a `{type:'local'}` source + their vendor assets copied in):

| Profile | Enabled | Bundled runtimes |
|---------|---------|------------------|
| **mini** | js, bash, typr (+ lua) | brush, typr (already local) — **no swipl/pyodide** |
| **light** | mini + prolog + python | + swipl, pyodide *(bundling deferred — CDN for now)* |
| **full**  | light + r (+ more) | + webR where feasible, etc. |

Build mechanism (extends `build-package.sh` / the npm `build` flow):
- `BUILD_PROFILE=light npm run build` (default `light`).
- A `scripts/configure-build.{sh,mjs}` reads `build-profiles.json`, then for the
  chosen profile: (a) writes `www/js/kernel_config.js`, (b) for each *bundled*
  runtime, copies its vendor assets into `www/vendor/...` and adds the `local`
  source + the asset to the service-worker `APP_SHELL`, (c) leaves non-bundled
  runtimes as CDN-only.
- Profiles are data (`build-profiles.json`), so adding/retuning a variant is a
  config edit, not a code change.

Deferred: `light`/`full` will *eventually* bundle swipl/pyodide; for now those
stay CDN even in `light`, so we validate the fallback path against real CDNs.

## 3. Resilient kernel load (runtime — points 1,2,3,5)

A shared helper used by every CDN kernel's `init()`:

```
loadKernelSource(lang):
  candidates = [ override(lang)?, ...KERNEL_CONFIG.languages[lang].sources ]
  for src in candidates:
    try: return await withTimeout(import(src.url) or fetch+instantiate, timeoutMs)
    catch (timeout | network | error): record, continue
  throw "all sources failed for <lang>: <details>"
```

- **Point 1** — ordered candidate list per kernel.
- **Point 2** — `withTimeout` wraps each attempt; a stalled CDN fails fast and
  moves to the next source instead of hanging forever (today's bug).
- **Point 3** — jsdelivr/unpkg mirrors for the npm-based kernels (swipl, lua,
  pyodide); webR has only its own host for now.
- **Point 4** — a `{type:'local'}` candidate (only present when the profile
  bundled it) is the last, always-succeeding fallback. Mechanism built now;
  swipl/pyodide local entries stay commented/off until we bundle them.
- **Point 5** — per-kernel override: `localStorage['scirepl_<lang>_source']`
  (a URL or `local`) is tried first. Surfaced in the Languages modal next to
  the existing version override (`KERNEL_VERSION_META`).

Note the per-attempt timeout is the highest-value piece — even alone it
converts "CDN stalled → app hangs → WebView killed" into a recoverable error.

## 4. How it composes with existing work

- **Service worker opaque-caching fix** (separate branch) reduces *re-downloads*;
  this proposal handles *failed/stalled* downloads. Together: robust both ways.
- **`KERNEL_VERSION_META`** (existing per-kernel version override) generalizes
  into the `sources`/override model here.
- Driving `LANGUAGE_META` / the selector from `KERNEL_CONFIG.enabled` also
  removes the long-standing hardcoded-list drift between `index.html` and
  `file_io.js`.

## 5. Staged implementation plan

1. **kernel_config.js + runtime loader** (points 1,2,3,5): introduce the config
   object (hand-written initially with current CDNs + mirrors), and a shared
   `loadKernelSource` with per-attempt timeout; convert the prolog kernel first
   (the one that actually stalls), then python/r/lua. Everything stays external.
2. **Build profiles** (the configurable build): `build-profiles.json` +
   `configure-build` that generates `kernel_config.js`, sets enabled languages,
   and wires bundled assets + SW precache; `BUILD_PROFILE` selects mini/light/full.
3. **Drive `LANGUAGE_META`/selector from the config** (removes hardcoded drift).
4. **Local bundling of swipl/pyodide** (point 4, deferred): add their vendor
   assets + `local` sources under the `light`/`full` profiles once the external
   path is proven.
